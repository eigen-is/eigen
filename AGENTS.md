# AGENTS.md: Eigen Project Context

Eigen is a self-hosted Google Workspace alternative: a monorepo of apps sharing one API server, one UI library and one business-logic layer (`package.json` and `ls apps packages` give the layout). In dev the API listens on `localhost:8000` and each app runs its own vite server ([CONTRIBUTING.md](docs/CONTRIBUTING.md)). `packages/sheet` is our fork of fortune-sheet/luckysheet ([SHEETS.md](docs/SHEETS.md)).

## Critical Rules

- **No AI co-author trailers in commits**, even when your tooling adds one. Title `type(area): what changed`, at most 60 characters; a plain-English body says what was wrong and what changed ([CONTRIBUTING.md § Commit messages](docs/CONTRIBUTING.md#commit-messages)).
- **A new API route, database migration or package needs the owner's explicit yes**, asked as its own question right before you build it. A migration is a new schema version in a `db-config.ts` or a column `ensureAuthSchemaColumns` adds to `users3.db`; a package is an npm package in any `package.json` (devDependencies included), a `bun patch`, or a system package or binary in a Dockerfile or CI image. Name it (for a package, its size and what it pulls in), why nothing existing or a few lines of our own serve, and the simpler alternative. An approved plan or ruling that implies one is not that yes; a subagent stops and reports instead.
- **No simple, clean fix? Ask first**, the options in two sentences, before you build a new seam, a layer crossing, a second mechanism or a choice between two non-obvious designs. In an incident, ship the minimal fix, then name the robust option and its size.
- **A second patch means fix the source**: when a fix needs another fix, or a mechanism keeps getting a guard, flag, cache, retry or second path, stop patching and change the design at the cause, or drop the feature or accept the edge case. The third fix on one mechanism in a week is a stop ([REVIEW-STANDARD.md](docs/REVIEW-STANDARD.md)).
- **Read before you write**: [CODE-STANDARDS.md](docs/CODE-STANDARDS.md), 2–3 sibling files and the domain doc ([docs/README.md](docs/README.md); [ARCHITECTURE.md](docs/ARCHITECTURE.md) maps every concept). New code looks like it was always there. No `as any` or `as Type`; trust our own types, validate only what a person or another program wrote, and no test-only code in production ([§ Code Philosophy](docs/CODE-STANDARDS.md#code-philosophy)).
- **Search [SHARED-PRIMITIVES.md](docs/SHARED-PRIMITIVES.md) first**; a primitive is shared only once its barrel exports it (`bun run primitives` regenerates the index).
- **Right layer**: hooks in `packages/lib/src/core/[domain]/hooks/`, shared types in `packages/lib/src/types/`, shared UI in `packages/ui/`, app-only code in `apps/`; two apps need it: `packages/`; a third copy of a scaffold: one wrapper in `packages/ui`. App components hold no `useQuery`, `useMutation`, toasts or `try/catch` + `toast.error()`; hooks use `onMutationError` ([NOTIFICATIONS.md](docs/NOTIFICATIONS.md)).
- **Package direction is one-way**: `sheet → lib`, `ui → lib`, `math` and `formula` leaves; the backend imports lib only through React-free subpaths. One fact lives in one module ([§ Package boundaries](docs/ARCHITECTURE.md#package-boundaries)).
- **Drive is Route → SharedDrive → Drive → Mount**: a feature changes all four, and every route-callable `Drive` method gets a `SharedDrive` wrapper with its permission check. **Never `getHome()` another user's data**: use `home-relay.ts`. **Pages are `ColumnLayout` + `Column`** with the `toolbar` prop. Gated: `DRIVE_MIME_*` constants, `:ownerId` second in every authenticated route (`OWNER_ID_EXEMPT`), `pointer-coarse:` on hover reveals. All: [§ Pitfalls](docs/ARCHITECTURE.md#pitfalls).

## Working with the owner

- A question ("what is happening?") gets findings, not edits.
- Every question to the owner opens with a short summary in super simple English: what is asked, why it comes up now (the context, no jargon), what happens with each answer, and your recommendation. The owner should understand it without having read the session.
- Before multi-file work ask "branch, or the current branch?" and keep the answer; a trivial fix goes on the current branch. Never push or tag without an explicit go. Work lands on `develop`; `main` moves only on the owner's word, as a fast-forward ([TESTING.md](docs/TESTING.md#work-lands-on-develop-and-main-moves-only-for-a-release)).
- Another session may share the tree: stage by path, never `git commit -a`, `git add -A` or `git stash`; unstage files you didn't change (`git reset -- <path>`) and re-stage them after your commit. While files you never touched are dirty, run no global check.
- Start dev servers (vite, the API) only when the owner asks or a check needs them, and stop every one you started once it is done: a vite left running hangs as other agents change the files it watches, and an idle stack keeps the machine loaded. Before starting one, kill eigen vites and APIs no live session owns ([verify-in-browser skill](.claude/skills/verify-in-browser/SKILL.md)).
- No AI attribution in PRs, issues or upstream posts. Draft for the owner's review, post with `--body-file` (`gh` posts as eigen-is), then grep the posted body for `claude|co-author|generated`.
- Owner away and the recommended answer clearly logical: proceed after 15 minutes, log the ruling with its cost if wrong and its undo, and name it in your summary. Product, UX, stored-format, irreversible and outward-facing choices still wait, as does every Critical Rules yes.

## Done means

- **`bun run check` passes** ([TESTING.md § CI](docs/TESTING.md#ci)); docs, copy and string-only edits skip it, and with agents in parallel only the main agent runs it. Tests live only in `<workspace>/src/test/` (gated). One API test file: `cd apps/api && bun test --preload ./src/test/preload.ts ./src/test/<domain>/<file>.test.ts`.
- **Every changed file meets CODE-STANDARDS.md**, header comment and self-review checklist included. Fix the broken windows you pass; removing lines is welcome. Fix a bug you find, even outside the task, in its own commit (a subagent reports it instead, and its orchestrator dispatches the fix); a rare edge case that can't crash or block the server, lose data or leak access is accepted ([REVIEW-STANDARD.md](docs/REVIEW-STANDARD.md)). A bug needing a Critical Rules yes, a product or UX choice, or more than a small unit of work gets a [ROADMAP.md](docs/ROADMAP.md) row instead, in the same commit, named in your summary.
- **Docs in the same cycle**: gotchas into `docs/<DOMAIN>.md` (domain-doc skill), a new concept into ARCHITECTURE.md, a user-visible change into the help center (support-article skill) and `CHANGELOG.md` (changelog skill). A standing rule goes into the doc or skill it governs, never memory alone; a one-off for the current run into its `STATE.md`.
- **Markdown**: one line per paragraph, no hard wraps, no line numbers (name the file and symbol).
- Multi-step work and subagents: the [orchestrate skill](.claude/skills/orchestrate/SKILL.md). Reviewers: [REVIEW-STANDARD.md](docs/REVIEW-STANDARD.md).
