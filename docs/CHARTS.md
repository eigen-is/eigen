# Charts

> **TLDR:** A chart is one stored description, a `ChartSpec`: its type, titles, legend, axes, colors and data. One pure layout turns it into ordinary canvas elements plus lines of text, and one painter draws those as plain SVG, so a chart looks the same live, in a preview and in every export. The spec, its reader and the layout are `packages/lib/src/charts/` with the types in `packages/lib/src/types/chart.ts`; the canvas kind and its painter are `packages/lib/src/vector/kinds/chart.ts` and `chart-render.ts`; the shared editor and the Edit data dialog are `packages/ui/src/components/charts/`.

A chart is a column, bar, line or pie chart, in Google's and Excel's names: a column chart has vertical bars, a bar chart horizontal ones. Its `ChartSpec` holds the presentation (title, legend position, axis titles, value-axis min and max, gridlines, stacking, colors, font) and the data: categories along one axis and one or more series of values. The spec is stored as a JSON string wherever a chart lives: the `chart` field of a canvas element of kind `chart`, in Vector and Slides ([CANVAS.md](CANVAS.md)), the `spec` attribute of a docs `chart` node ([§ A doc's chart](#a-docs-chart-draws-its-look-at-its-own-size)), and a sheet's `charts` map in Sheets ([§ A sheet chart reads its ranges](#a-sheet-chart-reads-its-ranges-and-its-editor-adds-googles-setup)). On a canvas and in a doc, Insert → Chart places one with sample data, the properties panel edits its presentation, and Edit data its numbers ([§ One chart editor edits a spec](#one-chart-editor-edits-a-spec-and-the-host-writes-it)).

The data is inline or a range. Inline data is the numbers themselves, inside the spec. Range data names cells of a sheet (a `CellRangeRef`: sheet id, first and last row, first and last column), which only a sheet can resolve. A canvas has no sheet, so it draws only inline data.

A chart's look is the rest of how it draws: its background and the hatch of its bars and slices, the stroke of its axes, its sketch and its label color. It is a set of fields beside the spec, in a canvas chart element's own field names, so a doc's chart and a canvas chart store it the same way ([§ One look, a canvas chart's own fields](#one-look-a-canvas-charts-own-fields-paints-a-chart-in-every-app)).

The layout, `layoutChart`, takes the spec, the resolved data, a box and a paint (the look as the painter reads it), and returns shapes and labels in the box's own coordinates. The shapes are real canvas elements: rectangles for bars and legend swatches, lines for gridlines, baselines and line series, ellipses for markers and the pie kind for slices. The labels are lines of text with a position, font, size, weight, color and turn. The painter, `renderChartSvg`, draws the shapes through their own kinds and the labels as SVG `<text>`.

The sections cover the spec and its reader, its limits, how a canvas stores a chart, the layout, the painter, the look, converting a chart to shapes, the chart editor and Edit data, the text widths, a sheet's charts and how a chart goes to Office. Four things in them surprise people:

- A canvas keeps a chart's spec exactly as stored, even one that doesn't parse ([§ A canvas keeps the spec as stored](#a-canvas-keeps-the-spec-as-stored-and-draws-a-placeholder-for-one-it-cant-draw)).
- A chart's labels are SVG text, never rich text, because WeasyPrint ignores `foreignObject` ([§ The painter draws each shape with its own kind](#the-painter-draws-each-shape-with-its-own-kind-and-the-labels-as-svg-text)).
- Label widths come from a committed table, not from a browser ([§ Text widths come from a committed table](#text-widths-come-from-a-committed-table-generated-from-the-bundled-fonts)).
- Past 200 points a chart's data draws flat whatever its sketch ([§ Past 200 points the data draws flat](#past-200-points-the-data-draws-flat-and-the-rest-keeps-the-sketch)).

## parseChartSpec is the one reader of a stored chart

Everything that reads what a stored chart says goes through `parseChartSpec` (`packages/lib/src/charts/spec.ts`), because a stored chart is written by any collaborator or a paste. It takes the stored string, so the byte limit is measured on what peers store. Broken structure (no type, no data, a series that is not a list, a range outside Excel's grid) or a hard limit returns `null`. A broken or missing presentation field reads its default instead, so a field added to the type later never turns a chart stored before it into a placeholder. Text is cut to 200 characters and loses what XML can't hold, because every label ends up in SVG.

The font is a presentation field like the others: one of the bundled Eigen fonts, read through the canvas's own font reader, and Inter (`DEFAULT_CHART_FONT`) when it is missing or anything else. Only a bundled font has a width table and an `@font-face` an export can embed. It lives in the spec rather than on a canvas element because a document or a sheet has no element, so a chart keeps its font wherever it goes.

A series or slice color of `null` is automatic: it draws in `chartColor(i)`, the palette color at its index, which the layout resolves on every draw. A missing color, or one that isn't a color token, reads as `null`. Charts made in Eigen store `null` (the sample, a new series or row in Edit data, a Sheets insert), so a palette change reaches them; a picked color stores its hex. As with Google's Auto, deleting a series shifts the automatic colors of the series after it, since their indexes change. `chartColor` is the shared accent palette in the order calendars and labels hand it out (`EIGEN_ACCENT_COLORS_SHUFFLED`, `constants/colors.ts`). It has seventeen colors, so the grid's twelve series never repeat one. Only eight are 3:1 or more against white, and they are mostly blues and purples a deuteranope can't tell apart, so the order trades contrast for distinctness: three of them lead (indigo, red, fuchsia), every neighbor stays apart under deuteranopia, yellow and lime (about 1.9:1) sit past the eighth, and pink, the background a new deck's title slide opens on, comes last. `colors.test.ts` pins those properties. The same module owns the sample chart, `sampleChartSpec`, which Insert → Chart starts from: where a star's light goes, the share of the Sun's, a bulb's (2700 K) and a hot star's light per equal 100 nm bin from 300 to 1000 nm, from Planck's law and normalized to that window so the bars compare, one dataset for every type because the Type switch keeps the data, and a pie draws the Sun. It carries axis titles, with the unit in the value axis's title since only a sheet chart reads `valueAxis.format`. A Sheets insert starts from `defaultChartPresentation` instead, so a chart of a selection never inherits the sample's titles.

`stacking` is Excel's grouping, for column and bar charts: `'none'`, `'stacked'` or `'percent'`. Any other value reads `'none'`. Under `'percent'` the value axis's min and max are shares, 1 for 100%.

Each axis has `visible`, and the category axis has `reversed`, both read as Google's look when missing. A hidden axis draws no labels and no line, as Excel's `c:delete`; its title and the gridlines are fields of their own and stay. With gridlines on, the line at zero stays as a gridline, as Office keeps its 0 line; with them off a hidden category axis draws nothing there. An imported axis reads as hidden under `c:delete` and under `c:tickLblPos none` alike, though Office keeps the axis line for `none`: `visible` is one bit, so a `none` axis loses its line. A reversed category axis runs the other way from Google's: a bar chart's from the bottom up, which is Excel's default, and a column or line chart's from the right. The whole axis turns, bands included, so inside each category the first series sits where the axis starts, as Excel draws it. Reversing the data would turn the categories but not the series inside each band, and an xlsx chart's ranges can't be read backwards anyway. The writer mirrors the reader: `c:orientation` is `maxMin` when `(type === 'bar') !== reversed` and `minMax` otherwise, with the value axis crossing at that end so it stays where Eigen draws it, and a hidden axis is `c:delete`, so a `c:tickLblPos none` axis comes back deleted ([§ A chart goes to Office as a c:chartSpace](#a-chart-goes-to-office-as-a-cchartspace-that-reads-back-as-the-same-spec)).

## Hard limits bound what every peer lays out

Every peer lays out and paints whatever is stored, so the limits bound one chart's cost. They are constants in `charts/spec.ts`.

| Limit | Value | Over it |
|---|---|---|
| Serialized spec | 64 KiB | the spec reads as `null` |
| Series | 32 | `null` |
| Points (all inline values, or categories) | 2,000 | `null` |
| One label | 200 characters | cut |
| Inline data the Edit data grid edits | 12 series, 200 categories and 2,000 cells | `exceedsInlineGridLimits` answers true, and the grid opens read-only |

## A canvas keeps the spec as stored, and draws a placeholder for one it can't draw

The chart kind's `read` keeps the `chart` string as it came, never re-serialized from the parsed spec. Only a string over 64 KiB reads as `''`. The reader's repairs live only in the scene anyway ([CANVAS.md § The reader is the trust boundary](CANVAS.md#the-reader-is-the-trust-boundary)), but a parse-and-rewrite would turn a spec this build can't read, such as one with a field from a newer build, into its defaults the next time anyone writes the field. Kept as stored, it stays recoverable.

A spec that doesn't parse, and a spec with range data, draws a placeholder: a dashed box in the gray a picture with no file draws, and one centered line, "This chart can't be shown", ellipsized to the box or left out when the box is too small. `layoutChartMessage` lays that line out the way the layout's own messages are laid out.

## A chart is laid out as canvas elements plus labels

`layoutChart` (`charts/layout.ts`) is pure and synchronous, so the server and the live canvas run the same code. Its shapes are the canvas's own element types rather than a chart-only drawing, so a bar paints exactly as a rectangle with the same fields, with the host's roughness and hatch. Each shape's id is `${chartId}:${key}` (`c1:bar:0:2`, `c1:gridline:3`), which keeps the ids and every id derived from them unique on a page, and its seed is derived from the chart's seed and the key, so the jitter is the same on every redraw and differs per shape.

Shapes come in paint order: background, gridlines, bars or slices, lines, markers, baseline, legend swatches. Every shape has opacity 100 except the gridlines, which are faint. The chart's own opacity is its layer's, as for every element.

A label's `y` is the top of its line, not its baseline, so a renderer adds its font's baseline offset and a text box could take it as its top. A turned label turns about `(x, y)`.

The look is Google's defaults: text scaled to the box, title on top in bold, legend on top for column, bar and line and none for a pie, light gridlines, no tick marks, zero-based bars. Stacked bars sum positives and negatives apart. A 100% stack (`'percent'`) plots each value as its share of its category's absolute sum, as Excel and Observable Plot do, so a category's positives and negatives together span 100%, and its ticks read as percents whatever the axis's or the source cells' number format. A category that sums to zero draws no bar. A line's value axis fits its data with nice ends, as Excel's and Google's do, and takes in zero only when the line is flat. All zeros draw an axis from 0 to 1, and so does a span too small for a tick step (under 1e-300). Value ticks come from a port of d3-array's tick algorithm (`charts/ticks.ts`), spaced by pixels and never more than 20 (`MAX_TICK_COUNT`), however long the axis, because a peer sets the box. d3 takes the count as a hint and can return half as many again, so an axis over 20 asks again for fewer, which steps up to the next nice step. A bar chart's value axis then asks for as many as its widest pair of labels has room for until they stop touching. A tick label carries as many decimals as the step, and reads in scientific notation (`5E-21`, `1.0E100`) past six decimals or from a step of 1e15, so tiny ticks stay distinct and a huge value leaves the plot its room. A pinned min or max too close to its partner to tick gives way to the data's domain. Category labels turn -45° when upright ones would touch, then ellipsize. A bar chart's category names are centered on their bands, so where the bands are thinner than a line they start half a line in from the plot's ends, which keeps the end names off the title or legend above and the value labels below. A hidden axis gives its labels' room to the plot, and a hidden category axis draws no baseline, since the baseline is that axis's line. A column or line chart's end tick labels overhang the plot by half a line, so the plot keeps that half line at the top, and at the bottom when no category names sit there, off the axis title and a bottom legend. A legend past its room, 30% of the height on top or bottom and the height below the title on a side, drops the entries that don't fit and ends with "+N" counting them. A pie labels each slice of 5% or more with its name and share, beside the slice and without leader lines. No data, a pie with a negative value or a box too small for a plot draws one centered message instead. No data means no series, no categories or every value blank, whatever the blanks setting, and for a pie also nothing positive. `packages/lib/src/test/charts/layout.test.ts` pins each of these.

## The painter draws each shape with its own kind and the labels as SVG text

`renderChartSvg` (`vector/kinds/chart-render.ts`) wraps each shape in its own translate group and calls that kind's `render`, so a chart's bar and a drawn rectangle with the same fields are the same SVG by construction. It imports the four shape kinds one by one: the registry imports the chart kind, so reaching the shapes through `ELEMENT_KINDS` would be an import cycle.

The labels go through `svgTextLine` (`vector/kinds/render-utils.ts`), the one helper that turns a line of text into SVG `<text>`; an arrow's label draws through it too. Plain SVG text is what lets a chart print: WeasyPrint ignores `foreignObject`, so rich text would vanish from a PDF. A bold label is drawn at weight 600, the weight of Inter's and JetBrains Mono's bundled bold faces.

A document or a sheet has no element, so it draws through `renderChartSpecSvg` (`@workspace/lib/vector`, safe on the server): the same painter in the look the chart stores, and in `FLAT_CHART_LOOK` (`charts/look.ts`) when it is given none. That is Google's flat look: near-black text in the spec's font, a mid gray for the baseline and the faint gridlines, line width 2 (Google's series width), roughness 0, solid marks and no background, so the chart sits on the page. It takes the parsed spec, `null` drawing the placeholder, and for a sheet the resolved range data or why there is none: `'ref'` draws `#REF!` and `'too-many-points'` draws "Too much data for a chart", one centered line without the dashed box. Inline data needs nothing passed; range data with nothing passed draws the placeholder. It returns a complete `<svg>` the size of the box, which a document's HTML inlines and a sheet overlays.

The placeholder draws its line in Inter, since a spec that doesn't parse names no font.

So previews and exports need nothing for charts. The editor's downloaded SVG, the PDF page, a deck's HTML and the preview all draw the chart through the kind, and the export sanitizer keeps every shape and label; `apps/api/src/test/export/chart-export.test.ts` proves it. The downloaded SVG embeds the faces `canvasImageFaces` collects, and each kind answers for its own elements (`fontFamilies`), so the chart kind gives the font its labels draw in without the writer asking for charts by type. A placeholder adds none, so its line falls back to the viewer's fonts unless another element embeds Inter. The live canvas loads nothing extra: the app's `@font-face` rules load a face the first time SVG text uses it.

## A doc's chart draws its look at its own size

A docs `chart` node stores the spec beside a width, a height and its look, and draws it through `renderChartSpecSvg` everywhere: the node view at its size, and the server's HTML, PDF and preview as inline SVG in the figure's box ([DOCS.md](DOCS.md#a-chart-is-a-node-of-its-own-in-the-figures-frame)). Its labels draw in the spec's font, Inter for a chart Insert → Chart places, and the Chart panel's Font row changes it: the node view's inline SVG takes the face from the app's `@font-face` rules and the export's from the HTML's embedded fonts. A doc has no sheet, so its charts hold inline data, and anything else draws the placeholder. Search reads the node through `chartSearchText` (`charts/spec.ts`), the text the canvas kind indexes too. The docx writes a chart as a picture of that SVG beside a PNG of it, not as a Word chart ([EXPORT.md](EXPORT.md#an-office-image-is-a-png-or-jpeg-made-from-its-source)); its media key holds the look, so two charts of one spec in different looks are two pictures.

Insert → Chart places a flat chart, as Google's is, with a random `seed`. The sketch is a pure function of the seed, so a sketch picked later jitters the same in the editor, the export, the docx picture and a copy.

Every drawing of a doc's chart (`chartSvg`) takes a fresh id. A gradient background writes a `<linearGradient>` whose id derives from the chart's id, and a page holds many charts, so a fixed id would let one chart paint with another's gradient.

## One look, a canvas chart's own fields, paints a chart in every app

A chart's look is `ChartLook` (`types/chart.ts`): the canvas chart element's `fill`, `color`, `strokeColor`, `strokeWidth`, `strokeStyle`, `roughness` and `seed`, listed once in `CHART_LOOK_FIELDS`. A canvas chart is its element, so it follows its host's style table like any shape: rough and hatched in Vector, flat and solid in Slides. A doc's chart stores the same fields as attributes of its node, one each, so a peer's stroke edit and another's sketch edit merge instead of one overwriting the other. `readChartLook` (`charts/look.ts`) reads a doc's or a clipboard item's look through the canvas reader's own validators, and a missing field reads flat, so a doc written before the look existed draws as it did. `chartPaintOf` turns any look into the painter's `ChartPaint`, the one map in all four apps. Opacity is a canvas layer's, not the look's. The font is not part of the look but the spec's, so Insert → Chart writes the host table's font into the new spec: Excalifont in Vector, Inter in Slides.

| Look field | What it paints |
|---|---|
| `fill` | The background, always solid; its hatch style is the fill style of the bars, slices and legend swatches |
| `strokeColor`, `strokeStyle` | The axes and gridlines, not a border |
| `strokeWidth` | The axes and gridlines, series lines and markers, and the outline of a hatched bar or swatch. A bar narrows by its outline across its band, so bars side by side meet outline to outline instead of overlapping, and a bar thinner than two outlines draws a thinner one |
| `color` | Every label |
| `roughness`, `seed` | Every shape |

A bar, a slice or a legend swatch with a solid fill draws no outline, as Google's do. A hatched one (hachure, cross-hatch or zigzag) is outlined in its own series or slice color, since a hatch is strokes inside an outline and reads as unfinished without it. The painter derives this from the fill style at draw time, so switching the style writes nothing else. A hatched slice's edge is 1px wide. Its hatch draws inside a clip of its own outline, as every canvas shape's does (`drawableToSvg`): roughjs strokes a hatch past the edge, a zigzag by about 3px at any size, which shows on a legend swatch. Series and slice colors are in the spec, automatic or picked ([§ parseChartSpec](#parsechartspec-is-the-one-reader-of-a-stored-chart)).

`PaintSections` (`packages/ui/src/components/properties-panel/`) is the one panel section that edits a look: the Labels color, the Fill with its hatch Style, the Stroke and the Sketch. The canvas panel shows it for every selection, merging each row across it, and adds the Labels row for charts alone; the Docs Chart panel shows it for the selected chart. A shape's hatch row shows only while it has a fill, since a hatch fills its body, but a chart's shows without a background, since its hatch is its bars'.

## Past 200 points the data draws flat, and the rest keeps the sketch

A rough or hatched mark costs about 20 times a flat one. Every viewer draws what a peer stores, a doc's chart is drawn again for its export, its docx picture and every copy's `<img>`, and the box can be 2112 px a side. At 2000 × 1200, cross-hatched, 200 points take 35 to 55 ms and 1.5 to 3.8 MB of SVG on the server, and 400 points 70 to 110 ms and 3 to 7.5 MB, which the browser then parses and paints. So past `MAX_SKETCH_POINTS` (200, `charts/layout.ts`) the data marks (bars, slices, lines and markers) draw with roughness 0 and solid, and so without outlines, while the background, gridlines, axes and legend keep the sketch. A chart counts its points as the values it plots (`chartPointCount`): a pie its first series, any other type every series. It is the painter's rule, so every app draws the same, and the panel's Sketch section says so when it applies (`isSketchCapped`).

## Convert to shapes unpacks the painter's own layout

Convert to shapes, a row in the canvas object menu and a button in the chart's panel section for a selection of one chart that draws, replaces the chart with what it draws. `chartToElements` (`vector/kinds/chart-convert.ts`) reads the same layout the painter draws (`chartLayout` in `chart-render.ts`), so each converted shape is the element that drew it: same kind, fields and seed, so no jitter or hatch rerolls. Each shape's center turns about the chart's center, the chart's angle is added to its own, and its opacity is multiplied by the chart's. Each label becomes a rich-text box in the label's font, sized by `measureLabel` plus half an em of slack, since its kerning-free width can run short and a wrapped label would take two lines, one line high at the font's own line height so the baseline lands where the SVG text put it, and aligned by its anchor. A turned label turns about its anchor but an element turns about its center, so the box's center is turned instead. A chart that draws its placeholder converts to nothing, and the row is hidden. The kind answers through `toShapes`, read by `convertToShapes`, so the menu never asks for a chart by type.

`replaceElementInDoc` (`packages/ui/src/components/vector/hooks/element-writes.ts`) deletes the chart and writes the shapes in one transaction, at keys between the chart's index and the next one above it, so they keep the chart's place in the stacking order. Both run it through `convertElementToShapes` as one sealed undo step, so one ⌘Z brings the chart back, and selects the shapes, since the canvas has no groups to put them in. An arrow bound to the chart keeps its endpoints and loses its binding, as on a delete. The action is one way and has no ⌘K entry, because the palette has no canvas element actions.

The converted labels are rich text, each its own layer. The live canvas, a preview and the PDF mount a rich-text layer as HTML, and the downloaded SVG writes it as SVG text the browser measured ([EXPORT.md](EXPORT.md#a-drawing-downloads-its-own-svg-and-prints-as-layers)), so all of them draw the labels.

## One chart editor edits a spec, and the host writes it

`ChartEditor` (`packages/ui/src/components/charts/`) is Google's Customise rows over one `ChartSpec`: type, stacking (Google's None, Standard and 100%), titles, legend, font, each axis's Show axis box, the category axis's Reverse axis order box, the value axis's min, max and gridlines, and a color per series or per pie slice. A color row says Automatic while its color is `null`, with the palette color in its swatch and no swatch marked in its picker, so a click on that palette color is a visible pick; a picked color's popover has an Automatic row (the shared `ColorRow`'s `automatic` prop) that writes `null` back in one change. The Font row is the canvas text box's `FontRow`, so a chart offers the same fonts as a text box. It takes a spec and hands back the next one, and knows nothing of where the chart lives, so any surface that stores a spec can mount it. On a canvas the chart kind's panel section is this editor, shown for exactly one selected chart, because a spec doesn't merge across charts the way a color does. Each change is one write of the element's `chart` field, the whole spec serialized.

A typed title writes on every keystroke inside the host's gesture (`PropertyGestureContext`), so the title is one undo step and peers see it as it is typed. A range chart's categories and series names are only known to the sheet that resolves them, so its host passes them in (`categories`, `seriesNames`, one per series in the spec) to name the pie slices and the series rows; without them the slices and series go by number. A range series whose values ref is null draws nothing, so it has no row. A bar chart lies on its side, so its Horizontal axis rows edit the value axis and its Vertical axis rows the category axis, Reverse axis order among them. A box writes on its click, one undo step. Show axis is one box where Google has Show labels and Show axis line, because `visible` hides both. Each box is a `PropertyCheckbox`, Google's words beside it, and its accessible name leads with its section ("Horizontal axis: Show axis"), since both sections have one. A min at or past the max is not written, because the reader would drop both and the field would snap back. Under a 100% stack the min and max are shares of the whole, as Excel's `c:min` and `c:max` are (1 is 100%), so the editor shows and takes them as percents: a typed 100 stores 1, and a typed 33.3 stores 0.333 (rounded to 15 digits, past the division's float noise). Switching Stacking to or from 100% sets min and max back to automatic in the same change, since a raw max of 100 would read as 10,000% and a share of 1 as a raw 1. Switching Type between bar and any other type sets the category axis back to Google's direction in the same change: an Excel bar chart reads as reversed, which would turn it as a column chart right to left. Markers and smooth lines are in the spec and the layout but not in the editor, as on Google's insert surface.

## Edit data is a grid over inline data, and Save is one write

`ChartDataDialog` shows inline data as a small sheet: categories down column A, series across row 1, and the empty top-left cell. It edits a draft, so Save is one write of the spec and one undo step, and Cancel leaves the chart as it was. A cell keeps what was typed, so a value that isn't a number stays on screen, flagged, and Save waits for it. A new series or row is automatic, and each row carries its pie slice's color, so removing a row takes that color with it.

The grid stops at 12 series, 200 categories and 2,000 cells in total, since a full 12 × 200 grid would be past the 2,000-point limit that makes a spec unreadable (`fitsInlineGrid`). A chart past those limits, written outside the grid, opens read-only as a plain table rather than as thousands of cells. On a canvas and in a doc the dialog opens from the panel's Edit data button and from a double-click on the chart ([CANVAS.md § A kind is one registry entry](CANVAS.md#a-kind-is-one-registry-entry)). `ChartEditor` shows that button for inline data and owns its dialog, except in Docs, which passes `onEditData` because `editor.tsx` opens the one dialog for both. A double-click mounts `InlineChartDataDialog`, open at once, which closes itself when the chart's data is no longer inline, as after a peer deletes the chart.

## Edit data looks and types like Eigen Sheets

The grid is drawn to look like a sheet, so a user who knows Sheets knows it. Its sizes come from `@workspace/lib/sheets` (`SHEET_DEFAULT_COL_WIDTH`, `SHEET_ROW_HEADER_WIDTH` and their siblings) and its colors from the `--sheet-*` variables in ui's `globals.css`, the ones Sheets' canvas reads, on a light-pinned `.eigen-paper` as the workbook is. It is its own component rather than an embedded Workbook; what embedding would take is a [ROADMAP](ROADMAP.md) row (Edit data: embed the Sheets grid).

Like a sheet, it fills the dialog with empty cells and opens on A1: every column a series can go in, B to M, and rows two views past the scroll position, more as it scrolls, up to the 200th category. Typing in an empty cell adds a category or a series, those between as gaps, and an empty commit adds nothing. A value past the 2,000-value total is left out, and the grid says so. A row or column header selects the whole row or column, and Delete removes it; Delete on cells clears them to gaps.

The keys are Sheets' keys: arrows move and Shift extends, typing replaces the cell, Enter and Tab commit and move down or right, F2, Enter and a double-click edit in place, and Escape cancels the edit. One `<input>` sits on the active cell and keeps the focus, invisible until a cell opens, as Sheets' own cell input does. That is what makes a canvas host stand down: its clipboard listeners bail on a focused input (`isTypingTarget`). Radix hears Escape on the document before the input does, so the dialog's `onEscapeKeyDown` lets an open cell editor (`[data-cell-editor][data-editing]`) take it, and only a second Escape closes the dialog.

⌘C writes the selection as TSV and an HTML table (`@workspace/lib/clipboard`'s `table.ts`, the helpers Sheets' copy uses too). ⌘V fills from the active cell and grows the grid to fit, up to the limits, and says how many rows and columns it pasted when some fell outside. A paste reads TSV when the plain text has a tab, and otherwise an HTML table if there is one, then the plain text's lines: a Docs table's `text/plain` is its cells on lines of their own, which would land down one column. A1 is the category axis title, the header of the categories column as in Google, typed, pasted and cleared like any cell; Save writes the title only when A1 changed, so a peer's title change made while the dialog was open stands. A `<br>` in an HTML table cell is a line break in it, as Google's HTML marks one. A paste past the limits is cut to one row and column more than the grid holds before it fills, so a million rows cost no more than 202. Numbers read as Sheets shows them in the `en` convention: grouped (`1,234`), after a currency symbol (`$1,234.00`) or a percent (`12%` is 0.12, rounded as the editor's percents are), over a plain decimal with an optional exponent; anything else, `0x10` among it, is flagged. While a cell is open, a single value pastes into it as typed text.

## Text widths come from a committed table generated from the bundled fonts

The layout needs a label's width to reserve room for the value-axis labels, the legend and turned or ellipsized category labels, and it runs where there is no DOM. `measureLabel` (`vector/text-width.ts`) sums advance widths in the spec's font from `vector/text-width-data.ts`: one table per Eigen font, regular and bold, for Basic Latin and Latin-1, with an em fallback for every other character. It ignores kerning, so it runs slightly off a browser's measurement, which is why widths only reserve room and placement goes through `text-anchor`.

The table is generated from the static TTFs a docx embeds: `bun apps/api/src/scripts/chart-text-widths.ts`, rerun after a font changes. Inter's and JetBrains Mono's bold TTFs are weight 600, the weight a bold label draws at. Source Serif's is 700, so its bold widths run slightly wide of the 600 the app's variable face draws, which only reserves extra room. Excalifont has only a regular face, so its bold width is its regular width and the browser fakes the bold. The demo seeder sizes its labels with the same function.

## A sheet chart reads its ranges, and its editor adds Google's Setup

A sheet keeps its charts beside its cells as `SheetChart` records, and a chart there usually holds range data, which the sheet resolves from its cells when it draws. The editor's overlay and the export draw it through `renderSheetChartSvg`, `renderChartSpecSvg` with the sheet's resolved data and its number formats. A sheet chart stores no look yet, so it draws flat; storing one is a [ROADMAP](ROADMAP.md) row. Insert → Chart charts the selected cells, and the sheet's Chart editor puts Google's Setup (the data range, Switch rows/columns, headers and labels) above this editor's rows, or Edit data for an inline chart. How the sheet stores, shifts, draws and exports charts: [SHEETS.md § A chart is a floating record](SHEETS.md#a-chart-is-a-floating-record-whose-refs-name-sheets-by-id) and the sections after it.

## A chart goes to Office as a c:chartSpace that reads back as the same spec

`writeChart` (`apps/api/src/lib/core/ooxml-chart-writer.ts`) writes a spec as a DrawingML chart part, the `c:chartSpace` a docx, an xlsx and a pptx share, and `readChart` (`core/ooxml-chart.ts`) is its inverse: `ooxml-chart-writer.test.ts` writes every kind and option and reads back the same spec. Excel sees a chart it can edit, not a picture. Range data is written as refs by the names the workbook writes its sheets under, each with a cache of what the cells show, so Excel draws before it recalculates; inline data is written as literals. The xlsx export places each sheet chart as a two-cell anchor over the cells its box covers (`sheetTrackAt`, the inverse of the import's walk), so a re-import lands it on the same pixels.

An automatic color is written as the palette color at its place, so Excel and Google show Eigen's colors rather than their theme's. The reader reads a series or slice color equal to `chartColor(i)` back as automatic, so the round trip keeps `null`, and a file from elsewhere that happens to use that color draws the same either way. Hidden rows are plotted (`c:plotVisOnly` 0), since the sheet reads hidden cells like any other. A pie has no axes in Office, so its axis fields, which only a Type switch shows, come back as a new pie's. Excel can't turn a chart frame, so a rotated chart is written upright.

## A chart copies between apps with its numbers inline

⌘C on a chart in Sheets, Docs, Slides or Vector puts one chart item on the shared clipboard: the spec as stored, and the chart's box. Every host pastes it as a live chart it can edit, not a picture ([CLIPBOARD.md](CLIPBOARD.md#a-chart-travels-as-its-spec-with-the-numbers-inline)). The data must be inline, since only the sheet a chart came from can read its ranges and anywhere else a range chart draws the placeholder. So a sheet chart is read into inline data as it is copied, and only a paste back into the same workbook keeps its ranges ([SHEETS.md](SHEETS.md#a-selected-chart-copies-itself-not-the-cells-behind-it)). The font travels in the spec and the look beside it, so a Vector chart pasted into Docs keeps Excalifont and its sketch, and a canvas writes a pasted chart's look onto the element's own fields. Value ticks in Docs and on a canvas ignore `valueAxis.format` and draw as plain numbers, so a percent column copied from Sheets ticks as 0.25 rather than 25%; that gap is a [ROADMAP](ROADMAP.md) row.
