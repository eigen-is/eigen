# Canvas Engine

> **TLDR**: One engine for free-canvas documents. `packages/lib/src/vector/` is the React-free half — the element model, the kind registry, the outline math, the layer contract, the reader, the SVG serializer — and `packages/ui/src/components/vector/` is the host: `CanvasEditor` plus its hooks, tools and panel. The vector app (`apps/vector`) mounts it. Every kind is one registry entry, every consumer dispatches through the registry, and every element renders as one absolutely positioned layer. The slides app still runs its own canvas over the shared conventions below (keymap, layered Escape, ObjectTransform, snap, arrange, clipboard); docs is a partial canvas (figures adopt ObjectTransform only) and sheets floating images adopt the object system but keep the grid model.

## The element model

`packages/lib/src/vector/types.ts`. Every stored field is a scalar or a string — arrays and objects ride JSON scalars (`points`, `pressures`, `commentCardIds`, `fill`, the bindings, `fixedSegments`) — so a Yjs element map is a flat set of primitive reads and the write/read whitelist (`ELEMENT_FIELDS`) stays a list of key names.

Base fields on every element: `id`, `type`, `x`, `y`, `width`, `height`, `angle` (degrees, clockwise, y-down — SVG's `rotate()`), `index` (a fractional-index z-order string), `frameId`, `commentCardIds`, `opacity` (0..100), `locked`, `strokeColor`, `strokeWidth`, `strokeStyle`. The kinds are `rectangle`, `diamond`, `ellipse`, `image`, `richtext`, `freedraw`, `line`, `arrow`.

| Field | On | Shape |
|---|---|---|
| `fill` | rectangle, diamond, ellipse, freedraw, line, richtext | The serialized `Fill`: paint **and** hatch style in one JSON scalar (below) |
| `roughness`, `seed` | everything roughjs draws — shapes, freedraw, line, arrow | Image and rich text are DOM boxes and carry neither |
| `corners` | rectangle, diamond, image, richtext | `'straight' \| 'curved' \| 'round'`. An ellipse has no corners to treat, so it has no field; lines and arrows keep `roundness` (sharp vs curved shaft), a different question |
| `mediaName`, `objectFit` | image | The filename in the container's `media/` folder (never a dataURL) and `'fill' \| 'contain' \| 'cover'` → `preserveAspectRatio` |
| `html` + typography | richtext | TipTap HTML plus `fontFamily`, `fontSize`, `fontWeight`, `fontStyle`, `textDecoration`, `textAlign`, `verticalAlign`, `color`, `letterSpacing`, `lineHeight`, `padding` (px inset; the box keeps its stored size). `strokeColor`/`strokeWidth`/`strokeStyle` are its border, `fill` its box background. There is no highlight colour — a marker highlight is a mark inside `html` |
| `points`, `pressures`, `simulatePressure`, `roundness` | freedraw, line, arrow | `points` is a JSON `[[x,y],…]` in scene units relative to `(x,y)`, min corner always `(0,0)` |
| `elbow`, `fixedSegments`, `startArrowhead`/`endArrowhead`, `startBinding`/`endBinding`, `text`, `fontSize`, `fontFamily`, `labelWidth` | arrow | The label is the one client-measured plain-text path left on the canvas; everything else typed is rich text |

**`fill` is paint plus style.** `packages/lib/src/vector/fill.ts` is the codec: a paint (`{type:'solid',color}` or `{type:'gradient',from,to,angle}`, sRGB, colours restricted to hex or the `transparent` sentinel so no `url(...)` paint server can be smuggled into an export) with the hatch style (`hachure`, `cross-hatch`, `solid`, `zigzag`) stored beside it. One field, so a kind that fills carries one key; the panel edits the two halves separately, each write preserving the other on each element (re-painting a mixed-hatch selection must not collapse it to one hatch). `''` or anything malformed reads back as `TRANSPARENT_FILL`, so a corrupt peer write can never throw on a render path. `parseBackgroundFill` is the same codec widened with the image variant, which is what a frame background and the scene's `meta.background` speak; the shared types live in `packages/lib/src/types/background.ts` (`BackgroundFill`, `Fill = Exclude<BackgroundFill, ImageBackgroundFill>` plus the style) and the CSS comes from `getBackgroundStyle` (`@workspace/lib/background`).

**Frames.** The `frames` root holds `{ id, index, name, width, height, background }`; `width`/`height` are the `FRAME_WIDTH`/`FRAME_HEIGHT` constants (1920×1080, 16:9) and are never stored, so `FRAME_FIELDS` is `id`, `index`, `name`, `background`. An element's `frameId` is `''` on the infinite canvas; when set, its `x`/`y` are **relative to the frame origin** and `elementsInFrame` selects the frame's own elements. Elements may overhang — the frame clips them.

**Comments** ride `commentCardIds`, a JSON id list, not an array field: `parseIdList` / `serializeIdList` own the encoding.

**The reader** is `readVectorFromDoc` (`read-vector.ts`) → `VectorScene { elements, frames, meta }`, Worker-safe (yjs only). Scene-level passes live there — invalid fractional indices are re-synced, a dangling `frameId` re-homes to the lowest-index frame, a binding whose target is gone or is no longer bindable drops to unbound — while per-kind field validation (enums, numeric clamps, string caps, colour tokens) is the registry's `fields` + `read`. The reader is the trust boundary: a hostile peer write and a forged clipboard record meet the same validator.

## The registry

One kind = one entry, and everything the engine needs to treat it generically. Outside `kinds/`, only the `Fill` codec and the two family predicates (`isLinearElement`, `isBindable`) test `.type`; a `case 'rectangle'` anywhere else is a review finding.

- **`packages/lib/src/vector/kinds/<kind>.ts`** — the pure entry, built with `defineKind`: `type`, `is` (the narrowing guard), `fields` (the stored keys beyond the base set), `capabilities`, `defaults(style)` (what a new element gets, typed as that kind's own fields), optional `baseDefaults` (per-kind overrides of the shared base props), optional `capabilitiesOf(el)`, `read(src, base)`, optional `bounds`, `hitTest`, `outline(el, inflate)`, optional `anchorPoints` / `aimLines` (the box defaults cover every kind today), `render(el, ctx)` → `{ svg } | { html, style }`, and optional `searchText`. `defineKind` widens the narrow spec into the union-typed `ElementKind`, re-narrowing through the guard in every method, so no call site casts and a mis-dispatch degrades quietly instead of throwing mid-render.
- **`packages/ui/src/components/vector/kinds/<kind>.tsx`** — the React entry, only where a kind needs one: `icon`, `label`, `shortcut` (letter + digit), `InPlaceEditor`, `PanelSection`. `ELEMENT_KIND_UI` answers how a kind is *presented*; `ELEMENT_KINDS` answers what it *is*.

`kinds/index.ts` assembles the rest from those entries, so nothing is hand-listed twice: `ELEMENT_FIELDS` (base fields plus every kind's, de-duplicated), `isVectorElementType` (a stored `type` is validated against the registry itself), `CREATION_TOOL_TYPES` (the kinds a tool can create, which is what `VECTOR_TOOLS` maps into toolbar entries), `baseDefaultsFor(type)` (so a panel row's **reset restores exactly what create would have given** — an image's border resets to none, a rectangle's to the shared ink colour), and `VECTOR_STYLE_DEFAULTS`, the vector app's `StyleDefaults` table (roughness 1, hachure, Excalifont, curved corners). A host's style table is the only per-app fork: it decides how a *new* element looks, never which kinds exist.

**`capabilitiesOf(el)` is THE capability accessor.** The static table answers `fill`, `fillStyle`, `roughness`, `corners`, `stroke`, `strokeOptional`, `bindable`, `silhouette` (`box` / `diamond` / `ellipse`, the family the elbow router's heading heuristics follow) and `creation` (`box` / `polyline` / `freedraw` / `none` — `none` keeps a kind off the toolbar, which is how an image arrives by upload). Some answers depend on the *element*, not the kind: an open stroke has nothing to fill, so the freedraw and line kinds' `capabilitiesOf` closes `fill` unless the path closes (`isClosedLinear`, the same predicate their renderer paints from). Nothing holding an element reads `ELEMENT_KINDS[type].capabilities` directly — the panel, the tools and the binding code all call `capabilitiesOf(el)`.

**Adding a kind (say `graph`)**: add `'graph'` to `VectorElementType`, write its own file in `packages/lib/src/vector/kinds/` and add one line to `ELEMENT_KINDS`, then add one `ELEMENT_KIND_UI` entry. TypeScript forces both halves — a `Record<VectorElementType, …>` cannot be half-filled — and the tool list, the field whitelist, the reader, the renderer, the panel rows, the search collector, the clipboard and the arrange math all pick it up because they dispatch through the registry.

## Corners and the outline

`outline.ts` is the one definition of a shape's edge: the renderer draws it and the docking math intersects it, so a bound arrow lands on the curve the user can see. A rounded convex shape is modelled as the Minkowski sum `core ⊕ disc(radius)`, where `core` is the shape inset by `radius`; inflating for docking keeps the core and grows the disc to `radius + gap`. One routine serves rectangle and diamond — only the core polygon differs (a rectangle's is the box pulled in on four sides, a diamond's a similar diamond scaled by `1 − radius / inradius`).

The radius comes from `corners`: `straight` → 0, `curved` → the adaptive radius (`min(w, h) × 0.25`, capped at 32), `round` → the shape's **inradius**, the largest radius that keeps the silhouette — `min(w, h) / 2` for a rectangle (a pill, or a circle when square) and `w·h / (2·√(w² + h²))` for a diamond (its inscribed circle). `radius === 0` dispatches to the sharp offset, so `straight` is bit-for-bit what it always was; the Minkowski model would round those corners by `gap·(√2−1)` instead, and that discontinuity is deliberate. Consumers: the kind's `render` draws the same path, `geometry.ts` docks a straight or curved arrow on it, `elbow-heading.ts` measures distance to it, and `tools/binding.ts` tests the padded outline for a bind candidate.

## Rendering: layers

`elementLayer(el, { resolveMedia, route })` (`scene-layers.ts`) is the one definition of *where an element goes and what it draws*: a `Layer` of `{ id, box: { x, y, width, height, angle }, opacity, content }`, where `content` is the kind's `render` output — `{ svg }` for everything drawn, `{ html, style }` for rich text. It returns null when the element draws nothing (unresolvable media). `sceneLayers(scene, { frameId, resolveMedia })` is the same function over a whole scene: elements in fractional-index order, scoped to one frame when asked, with every elbow arrow's route derived against the full scene so an arrow inside a frame still routes around its bound shapes. `layerInnerHtml(content)` is the body as one HTML string, which is what a host that mounts layers as DOM needs.

**Rich text is sanitized at the mount seam, not at the reader.** `html` is a stored scalar, so it arrives verbatim from any peer with write access — and, on the paste path, from a wire any web page can forge. The reader (`read-fields.ts`) only byte-caps it: the allowlist needs a DOM, and that module also runs inside the API transform Worker. So `ElementLayer` runs `sanitizeToLightEditorHtml` (`@workspace/lib/html-dom`, the same allowlist the in-place editor's own paste uses) before it mounts the body, and `tools/paste-elements.ts` runs it before a pasted record reaches the document. One function, two seams; legitimate LightEditor markup passes through unchanged.

The live canvas renders one memoized `ElementLayer` per element (`element-layer.tsx`). Each is an absolutely positioned div carrying the box as **`transform: translate(x,y) rotate(a)`, not `left`/`top`** — the browser pixel-snaps a fractional box origin before painting, which would put every element up to half a pixel off its float coordinates; transforms are not snapped, and `transform-origin` defaults to the box centre, so the composed transform is exactly the single-`<svg>` renderer's `translate(x y) rotate(a w/2 h/2)`. Opacity rides the layer. An SVG fragment sits in an `overflow-visible` `<svg>` with a 1px minimum extent (roughjs overshoots its box, an elbow route spills past it, and a zero-extent viewport disables rendering entirely); rich text *is* the layer's own styled div. The memo compares every `ELEMENT_FIELDS` scalar plus the derived elbow route, so pan, zoom and drag re-render without re-running any kind's rough path generation.

**Gradients are per-element defs.** A kind's `render` emits `<defs><linearGradient id="…-<elementId>">` inside its own SVG and points `fill=` (solid style) or `stroke=` (the hachure / cross-hatch / zigzag sketch paths) at it; ids are element-scoped so layers never collide, and `gradientVector(angle)` maps the CSS angle convention onto objectBoundingBox coordinates. Rich text paints its background as CSS `linear-gradient(<angle>deg, from, to)` through `getBackgroundStyle`, the same string a frame or scene background uses.

**`sceneToSvg`** stays the standalone-document renderer — vector's SVG export, the server preview and the clipboard's SVG flavour — placing each element itself and wrapping an `{html}` layer in a `<foreignObject overflow="visible">` with a class-scoped `<p{margin:0}` reset, because a downloaded SVG carries none of the app's CSS. It is DOM-free (roughjs's generator yields path ops as plain data, and text trusts the client-measured label width), so the API transform Worker runs it verbatim.

## The host: `CanvasEditor`

`canvas-editor.tsx` is the live surface: viewport, tool-driven drag-create, selection, move, and the shared `ObjectTransform` chrome. Every drag/resize/rotate preview is local state; exactly one Yjs transact fires per completed gesture, with `stopCapturing()` at each gesture start so one gesture is one undo step.

Props: `doc` (the whole `CanvasDoc` from `useCanvasDoc`, taken whole rather than threaded prop by prop), `viewport: 'infinite' | 'frame'` + `frameId`, `tool`/`setTool` + `toolLocked`/`setToolLocked`, `canEdit`, `ownerId`/`mountId` (for cross-mount image paste), the lifted selection (`selectedIds`/`setSelectedIds`/`toggle`), `aspectLocked`, `publishCursor`, an optional `imageInsertRef` (the imperative image-insert surface the toolbar's Insert entries call, because placement needs the live viewport), the optional comment callbacks `onOpenCard`/`onAddComment`, and the ⌘F paint props `searchMatchedIds`/`searchActiveId`.

**Viewport modes.** `useViewport({ mode, frame, resetKey })` keeps scene ↔ screen as `(scene + scroll) * zoom`. The infinite canvas opens with the scene origin at the container centre and scrolls forever. Frame mode is the bounded page: `fitFrameViewport` letterboxes it with `FRAME_FIT_PADDING` (24 screen px), `clampFrameViewport` keeps the visible window inside the page on every pan, the pan resets when the active frame changes, and the frame's edges and centre lines are seeded into `computeSnapTargets`' `extraV`/`extraH` so an object aligns to the page the way it aligns to its neighbours. The pure math lives in `packages/lib/src/vector/viewport.ts`, so any host resolves the same numbers as the live hook.

**The live viewport is a ref, not React state.** A pan/zoom event writes `viewportRef` and schedules ONE rAF that writes the transform of the three nodes that *are* the viewport — the scene layer (`sceneRef`), the overlay group (`overlayRef`) and the screen-space chrome layer (`chromeRef`) — so a gesture costs zero renders (it used to cost one full `CanvasEditor` render per pointermove/wheel event: ~150 ms of JS each, a 15 fps pan). React state holds the last COMMITTED viewport, published on a trailing timer once the input stops; it is what layout reads — `boxToStyle`, the zoom pill, `TextOverlay`. The scene layer and overlay group take the live viewport whole (`sceneTransform` / `groupTransform`); the chrome layer is laid out by `boxToStyle` at the committed one and rides `chromeTransform(rendered, live)`, the correction onto the live viewport: exact for positions and scene-sized boxes, while screen-sized details (a 1px ring border, a grip) scale with it until the gesture commits. Anything that must be exact MID-gesture — `clientToScene`, `screenDeltaToScene`, a hit-test threshold, an image placement — reads the ref, which is why those functions are identity-stable and why the canvas — and `use-drawing-tools.ts`, whose eraser step, freehand sample spacing, line confirm/drag radii and bind candidate all divide a screen-px constant by zoom — read `viewportRef.current.zoom` in their event handlers rather than the rendered `zoom`. The rendered `zoom` stays the right value for the chrome those hooks LAY OUT (the point handles, the binding outline, the snap dots), since that is the viewport `chromeTransform` corrects from.

**Scoping.** `visibleElements` is the active frame's elements in frame mode and the whole scene otherwise; render, hit-test, marquee, snap, select-all and the keyboard all read the scoped list, and the frame paints its own background and clips what overhangs it. Comments and ⌘F deliberately do **not** — both must reach an element on another frame — so they read the host's full element list. Every insert path (drag-create, image drop/paste/picker, clipboard) goes through the canvas' own `addElement` / `addElements` wrappers, which stamp the active `frameId` after the caller's own fields — so a pasted element lands in the frame being pasted *into*, not the one it was copied from. In frame mode the viewport's scene space *is* the frame's space, so no coordinate translation is needed.

**Frame ops** live on the doc hook (`hooks/frame-writes.ts`, plain functions over the Y.Doc): `addFrame(afterId?)`, `deleteFrame(id)` (its elements go in the same transact), `duplicateFrame(id)` (through the element duplicate pass, so bindings remap), `moveFrame(id, afterId)`, `updateFrame`/`updateFrames`. The undo scope is `elements` + `frames` + `meta`.

**The properties panel** (`canvas-properties-panel.tsx`) is the engine's, mounted whenever the user can edit; with nothing selected it edits the canvas itself. Every row gates on a **capability**, never a type list — `fill` opens the Fill block, `stroke` the Stroke section (with a None swatch where `strokeOptional`), `roughness` the Sketch section, `corners` the Shape section — and what a capability cannot express comes from the kind's own `PanelSection`. Each control change is one `updateElements` transact across the selection, sealed on both sides, and mixed selections use the shared `—` conventions.

## Rich text in place

Double-clicking a box (or clicking with the text tool) mounts the kind's `InPlaceEditor` inside that element's own layer, and the layer stops drawing its own body: the editor *is* what the user sees, painted with the same `richTextCssText` string the renderer emits, applied through `setAttribute` so there is no second source of truth for typography and paint. It is `LightEditor` with `toolbar="floating"` and `proseStyle={false}`, focused at the end on ready.

Writes stream: every `onChange` writes `html` straight through, unsealed, so the session coalesces into one undo step and peers see the text live. Exit is Escape (claimed inside the editor, which stops propagation so the canvas' own listener never sees it) or a click away. On exit an empty box is deleted — a rich-text box with no text is invisible chrome — and the delete is **sealed first**, otherwise it would land inside `Y.UndoManager`'s 500 ms capture window and merge into the last keystroke, making "is this its own undo step" depend on how fast the user clicked away.

While any text session is open (a rich-text box or an arrow label) the canvas gates itself: `useCanvasKeyboard` runs with `enabled: canEdit && !textEditing` so tool letters, `Q`, Delete/Backspace, the nudges and the Mod combos can't steal keystrokes out of a contenteditable (`ignoreInputs` does not cover ProseMirror), the viewport freezes so a pan can't desync the editor from its element, and the context menu is suppressed.

**Limitation**: `html` is one scalar field on the element map, so two people editing the same box at once resolve last-writer-wins for the whole box — there is no character-level merge like the eigendoc editor's `Y.XmlFragment`. Different boxes merge normally.

## Comments

`packages/lib/src/vector/comments.ts` owns the anchoring questions and `useCanvasComments` the panel shape. An element's `commentCardIds` is a JSON id list (`parseIdList` / `serializeIdList`); the host adds and removes an id inline, idempotently, so a double submit can't list a card twice. `commentAnchorTexts(elements, labelOf)` gives each card its panel row from the anchoring element's own `searchText` — first anchor wins, so pass the elements in z-order — falling back to the kind's UI label so a row is never blank, and `elementForCommentCard` answers which element a card reveals.

**Every card in the document's `comments` map is active.** A card whose anchor element was deleted degrades to a document-level comment rather than vanishing from the panel. A commented element flags its top-right corner; clicking the flag opens the first card, and opening a card from the panel selects its anchor. A comment raised from the canvas object menu anchors to that element; one raised from the pane's "New comment" button stays document-level. Deleting a card removes the map entry *and* strips the id from its anchor, so no element keeps a flag for a card that is gone. The comments map is deliberately outside the canvas `UndoManager` scope — tracking it would let ⌘Z resurrect cards mid-edit. See [COMMENTS.md](COMMENTS.md).

## Search

`useCanvasDocSearch` is the canvas' `DocSearchController`: `searchScene` (`search-scene.ts`) walks every kind's `searchText` in reading order — frame by frame, then z-order inside a frame, both from the fractional indices — so ⌘F and the server-side search index agree about what a drawing says. Match ids **are element ids**. It is search-only; replace stays unset, so the bar hides its replace row. The collector spans the whole scene, other frames included, so `reveal` hands the host the element and the host decides what revealing means (the vector app selects it). Matched elements ring on the canvas and the stepped-to one rings brighter and flashes. See [IN_DOCUMENT_SEARCH.md](IN_DOCUMENT_SEARCH.md).

## Presence

`useCanvasPresence` publishes the shared cursor-layer fields plus the frame the peer is on. `frameId` is engine-private — it never enters the shared `CursorPeerState` — and `peerOnFrame` is the filter: a peer that publishes no frame reads as `''`, the same value the infinite canvas publishes, so it stays visible there and hidden on any real frame. The vector app publishes `''`.

## Clipboard

A canvas selection rides as one typed `elements` clipboard item: `buildElementsClipboardItem` copies the whole stored record of each element (so a canvas→canvas paste restores exactly what was copied, including fields a future kind adds) and `readElementsClipboardItem` runs each record back through the document reader, so a forged wire is exactly as safe as a hostile peer write. `reanchorElements` shifts a pasted set to its target anchor — the viewport centre in infinite mode, the frame's space in frame mode, where the canvas' `addElements` wrapper re-homes the elements after the source frame's id rides in on the record. Rich text's `html` is forgeable by any web page, so the paste planner runs it through the same sanitizer the mount seam does before it reaches the document. The producer is `tools/clipboard.ts`, the paste decisions (partials in z-order, the arrow-binding remap map, the cross-mount image manifest) are `tools/paste-elements.ts`, and `hooks/use-canvas-clipboard.ts` owns the events, transacts and placement. Full flavour policy, the SVG carrier and cross-mount re-upload: [CLIPBOARD.md](CLIPBOARD.md).

## Keymap

Every canvas command runs through `@tanstack/react-hotkeys` (`useHotkey` with `enabled` gating + `ignoreInputs` for Mod-combos), so shortcuts keep working while focus sits off-canvas and auto-ignore text inputs. The whole map is gated off while a text session is open. The step/offset constants are one source in `packages/lib/src/vector/geometry.ts` (`NUDGE_STEP`, `NUDGE_STEP_LARGE`, `DUPLICATE_OFFSET`) so hosts never drift.

**"Sealed" means one discrete op is one undo step.** `Y.UndoManager` merges everything inside a 500 ms capture window, so every discrete op — duplicate, delete, z-order, a panel row, add/delete/duplicate/move frame — runs through `sealed(undoManager, op)` (`hooks/use-canvas-doc.ts`), which `stopCapturing()`s on **both** sides. Anything that should deliberately coalesce (a nudge, a keystroke inside a text session) simply doesn't call it.

## Layered Escape

Escape is priority-ordered, not a single handler. On the canvas: **rich-text editing → mid-gesture cancel → deselect → return to the select tool**. The in-place editor claims it first and stops propagation, so the canvas' document listener never sees it while a session is open; `ObjectTransform` claims a mid-resize/rotate Escape in the capture phase, so the canvas' handler never fires during a grip drag; the canvas' own bubble-phase listener then cancels an in-progress create / marquee / move (a cancelled marquee restores the gesture's base selection, which is the prior set for an additive marquee and empty for a plain one), else clears the selection, else returns to `select`. Slides' capture-phase listener is the same discipline over its own layers — **present → text-edit → find-bar → deselect** — each layer claiming Escape only when it is active, so the innermost active mode wins. This ordering is load-bearing (the find bar's own bubble-phase Escape would otherwise close it before a canvas handler could tell it had been open). **This is a documented convention, not a refactor target** — do not try to extract a shared Escape router; the capture-phase ordering per host is intentional.

## Touch / stylus policy

Ported from Excalidraw and kept in `packages/ui/src/components/vector/tools/touch-gestures.ts` (the canvas only dispatches — `canvas-editor.tsx` must not grow). The surface is `touch-action: none` (`touch-none` on the canvas container), so single-finger events reach the pointer handlers directly. Five behaviors: (1) **penMode latch** — the first `pointerType === 'pen'` pointerdown flips a session-scoped penMode; while it's on a `pointerType === 'touch'` pointerdown can no longer start a draw/create gesture (allowlist: `select` + `richtext`), so a resting palm can't draw. A mouse is never affected. (2) **Two-finger pan + pinch-zoom** — a second touch aborts the live one-finger gesture (a freehand stroke under `SPIKE_MAX_POINTS` = 10 points is a palm spike and is discarded, else finalized — `drawing.abortForSecondTouch`), then both pointers drive pan + pinch through `useViewport`'s imperative `pinch(scale, px, py, panDx, panDy)`, which stays the single owner of the clamp/anchor math (the gesture module never duplicates it). (3) **Coarse hit-slop** — the screen-px grab threshold is fattened by `COARSE_HIT_SLOP_MULTIPLIER` (1.75, our addition; upstream keeps it constant) through the single `hitThresholdScreen(coarse)` seam in `geometry.ts`, gated on `matchMedia('(pointer: coarse)')` (`useIsCoarsePointer`). (4) **Double-tap → text** — two quick stationary taps open the same in-place rich-text session a mouse double-click does; a touch that DRAGS is never a tap, so a drag can never enter editing. (5) **Small screens are view-only** — the vector editor derives `canEdit = canWrite && !isMobile` (the 768px `useLayout().isMobile` breakpoint; tablets keep the editor) the way slides splits `canEdit` from `canWrite`: the canvas, tools and properties panel follow `canEdit`, while the file menu, share cluster and comments keep the real `canWrite`. A non-editable canvas pans on any primary drag, so one finger scrolls the drawing. Real palm rejection, pressure feel, and iOS/Android gesture conflicts need a physical device — headless can only assert the pure decision/pinch math.

## Shared primitives

The generated inventory is [SHARED-PRIMITIVES.md](SHARED-PRIMITIVES.md); the canvas-specific seams and where they live:

- **ObjectTransform + `snapBox`** (`packages/ui/src/components/transform/object-transform.tsx`) — the resize/rotate chrome (ring, grips, cursors, W×H + angle pills). Consumers pass `resizeMode`, `minSize`, and an optional `snapBox?: (b: Box) => Box` applied on the RESIZE path only (never rotate, never the pointerdown echo), before the latch, minSize re-clamped after. A host that doesn't snap omits it (a full no-op). Chrome renders from one CSS source (`.eigen-selection-ring` / `.eigen-selection-handle`), so a selected object looks identical in vector, slides and docs.
- **Panel sections** (`packages/ui/src/components/properties-panel/`) — `TransformSection` (numeric X/Y/W/H/° + aspect-ratio checkbox), `AlignSection` (align/distribute/match-size, presentational — the host owns the write), `ZOrderButtons` (+ `useZOrderHotkeys`), `BackgroundFillBlock` (none / solid / gradient / image). All speak canonical geometry (`x, y, width, height, angle`).
- **Marquee** (`packages/lib/src/vector/geometry.ts`) — `marqueeMode(startX, currentX)` resolves direction (rightward = contain, leftward = intersect) and `marqueeHits(bounds, marquee, mode)` is the pure hit test. Slides shows the dashed border for intersect. Shared math; hosts keep their own drag/render loops.
- **Snap** (`packages/lib/src/vector/snap.ts`) — `computeSnapTargets(boxes, excludeIds, extraV?, extraH?)` builds edge/centre targets (rotated objects contribute centre only; a frame seeds its own edges and centre lines, slides seeds canvas-edge guides, the infinite canvas passes none), and `snapBoxToTargets(box, targets, mode, threshold, centerOnly?)` returns the snapped box plus the matched guide lines. **Threshold contract**: it is in the box's coordinate units, so a zoom-aware host passes `SNAP_SCREEN_THRESHOLD / zoom` to keep the snap radius a constant SCREEN distance at any zoom; a zoom-less host (slides) passes a plain constant. **Rotated rule (`centerOnly`)**: a rotated box's axis-aligned edges lie about its visual box, so it snaps by CENTRE only as a mover and contributes centre only as a target. Move snaps in the gesture loop; resize feeds ObjectTransform's `snapBox`.
- **Align / arrange math** (`packages/lib/src/vector/arrange.ts`) — `computeArrange(items, op)` over the minimal `{id, x, y, width, height}` shape returns position/size patches; the host applies them in one sealed transact.
- **Collab lifecycle** (`packages/lib/src/core/collab/hooks/use-collab-doc.ts`) — `useCollabDoc` owns the Y.Doc + WebsocketProvider + UndoManager lifecycle. It exposes `synced` (live sync state — drives presence and seed-on-sync), `offline` (socket down after first load and not a storage outage, from the provider's `status` event) and a LATCHED `loaded` (true after the first sync, reset only on teardown / pathId swap). **Gate the loading screen on `loaded`, never `synced`** — a mid-session WS blip must not unmount the editor (which would destroy y-prosemirror undo history / transient selection); the mounted doc converges on reconnect. Sheets is the exception: it gates on `!initialData`. While the socket is down the editor keeps working: edits land in the local Y.Doc and y-websocket pushes them on the next sync handshake. Every collab toolbar surfaces that by passing the hook's `offline` and `storageUnavailable` to `DocumentShareCluster`, which draws one red wifi-off icon for both — its popover reads "Offline, will sync when back online", or "Storage is temporarily unavailable, retrying. Edits will sync when it is back." when the outage flag is set, which wins because it is the more specific answer. `offline` only flips 1.5 s after the `disconnected` event and the timer is cancelled by a reconnect, so neither a blip nor the storage retry cycle's one connected tick per 5 s flashes the icon. It also exposes `storageUnavailable`, set when the socket closes with `COLLAB_STORAGE_UNAVAILABLE_CLOSE` (1013, `packages/lib/src/constants/collab.ts`) and reason `storage-unavailable`, which the collab WS route sends when the document's storage answers 503; every other failed open keeps 1008. On that close the hook disconnects the provider and reconnects itself after `STORAGE_RETRY_MS` (5 s), because y-websocket only grows its backoff for sockets that never opened, and ours did open (the route closes from inside `open()`), so its own retry timer would re-pay the failing storage load every 100 ms. The flag clears on the next `sync`. Because nothing persists locally, a reload or a closed tab loses whatever the server has not acknowledged: the hook exposes `unsyncedEdits` for that, armed by an update applied while the socket is down and by the `disconnected` event whenever this tab pushed updates since the last completed handshake — which is how a silently dead socket (`wsconnected` stays true until y-websocket's 30 s silence check fires) is caught, one event late instead of never. Updates y-websocket applied itself (provider origin: the server, or a sibling tab over BroadcastChannel) don't count towards that, so a passive reader is never warned about someone else's edits. It clears on the next `sync`, and every editor renders `<UnsyncedEditsGuard active={unsyncedEdits} />` (`packages/ui/src/components/layout/app/unsynced-edits-guard.tsx`) once: it passes `enableBeforeUnload` to TanStack's `useBlocker`, so the browser confirms a reload or close, and blocks in-app navigation with the shared `ConfirmDialog` ("Leave without syncing?", Leave / Stay).
- **Loading and failure surfaces** (`packages/ui/src/components/layout/app/collab-loading-state.tsx`) — the five editors render the shared `CollabLoadingState` instead of a bare spinner. It renders `LoadingState` with its `message` prop: nothing for the first 10 s (a cold open is legitimately slow), then "Storage is responding slowly, still connecting…", and "Storage is temporarily unavailable, retrying automatically" whenever `storageUnavailable` is set. The pre-editor screen for the doc-info query is `EigenDocRouteStatus` (`packages/ui/src/components/layout/app/eigen-doc-route-status.tsx`), which every route renders while `useEigenDocEditorRoute` (`packages/ui/src/hooks/use-eigen-doc-editor-route.ts`) has no `docInfo`: data first, so a spinner while the query has no answer and `ErrorState` when it failed. `useCollabDocumentInfo` maps only 401 and 403 to `canRead: false` and rethrows everything else, so an infrastructure error retries and shows the error state rather than offering to request access to a document the user may already own.
- **Parent→child ref repair** (`packages/lib/src/core/collab/normalize-refs.ts`) — `normalizeParentChildRefs(doc, parentMap, childMap, childRefField, orderArrayName)` repairs the two corruptions a concurrent merge can leave in a parent-holds-child-ids structure: a child referenced by MORE THAN ONE parent (keep the last parent's copy, delete the earlier ones) and a child referenced by NO parent (append it to the first parent). **Both ends rank parents by the host's order array** (slides `slideOrder`, stickies `columnOrder`), never by `Y.Map` key order — key order is that peer's local integration order, so peers that created parents concurrently disagree about which is "first"/"last" and can delete each other's survivor, leaving the child in no parent at all. Parents absent from the order array ("strays", themselves a corruption) rank BEFORE every ordered parent, so a stray only wins the dedupe when it is the sole holder and is never a re-home target — neither end may park a child on a parent the UI never renders. Idempotent, one `NORMALIZE_ORIGIN` transaction, safe to run on every remote merge. Hosts: `normalizeDeck` (`apps/slides`) and `normalizeBoard` (`apps/stickies`). The canvas engine needs none of it — an element names its own `frameId` and a frame holds no id list.
- **Typed Yjs root + id-array reads** (`packages/lib/src/core/collab/yjs-utils.ts`) — slides and stickies read their roots and nested id lists through three accessors instead of `as Y.Map<…>` / `as Y.Array<…>` / `as string[]` casts: `getItemMapRoot(doc, name)` for a root map of per-item Y.Maps (`slides`/`objects`/`columns`/`tasks`), `getIdArrayRoot(doc, name)` for a root id list (`slideOrder`/`columnOrder`), and `getIdArray(map, field)` for a nested one (`objectIds`/`taskIds`). Roots need no runtime guard — `doc.get` upgrades an `AbstractType` root (the state `Y.applyUpdate` leaves server-side) in place, and throws only on a genuine type mismatch — while `getIdArray` narrows with `instanceof Y.Array`, which is sound because nested types integrate with their real constructors and never decode as `AbstractType`. Both ends read through them: the FE hooks (`use-deck.ts`, `use-board.ts` and their dnd/dialog siblings) and the BE readers (`apps/api/src/lib/document/slides.ts`, Worker-pure, + `stickies.ts`, main-thread — it takes a `Mount`), which import the React-free `@workspace/lib/collab/yjs-utils` subpath. Per-key scalar reads on a heterogeneous item map (`slideMap.get('title') as string`) still cast — one value generic can't type mixed keys.
- **Sealing discipline** — discrete ops (delete, duplicate, arrange, z-order, drag-end commit, an in-place text session's close) bracket their Yjs write with `undoManager.stopCapturing()` on BOTH sides so they don't merge into the previous step within Y.UndoManager's 500ms `captureTimeout`; nudges and text typing stay unsealed so they coalesce. Technical fixups that must never be undoable (the pending→real image mediaName swap, the ref repair) run under a non-null origin sentinel that escapes the UndoManager's default `{null}` trackedOrigins — `UNTRACKED_ORIGIN` (the canvas' `updateElementUntracked`/`deleteElementsUntracked`, `hooks/use-canvas-doc.ts`) and `NORMALIZE_ORIGIN` (`collab/normalize-refs.ts`); the write still broadcasts to peers.
- **Arrow bindings** (`packages/lib/src/vector/geometry.ts` + `tools/binding.ts`) — an arrow endpoint binds to a shape by storing a `fixedPoint` anchor (a proportion of the target's local w/h), so the endpoint follows the shape's move/resize/rotate by construction. Bindings are **forward-only**: the shape→arrows reverse index is derived in memory (`arrowsBoundTo`), never stored, so there is no second write to keep consistent, and a binding whose target is gone or no longer bindable is dropped to unbound **on read** (the Y.Doc untouched). After any element patch the hook re-runs `followBindings` and writes the re-glued geometry **inside the same transact** — one undo step, one broadcast — so every caller (nudge, drag-commit, align, paste-move) glues for free; a shape+arrow moved rigidly no-ops via `followBindings`' null return. Docking intersects the kind's `outline`, so a bound arrow meets a rounded rectangle or diamond exactly on the drawn curve. A **curved** (round, ≥3-point) bound arrow docks where its rendered Catmull-Rom shaft crosses that outline (`curveOutlineDock` / `arrowCurveBeziers`), not the straight chord. The curve is golden-locked by test to roughjs's control points at roughness 0, and the dock is endpoint-independent (it replaces the bound end with the resolved anchor and reads only the interior vertices + anchor + shape), so it's a strict fixed point and `followBindings`' exact no-op still holds for a settled arrow. A bound arrow dragged ALONE detaches only past `ARROW_UNBIND_SCREEN` (10px screen-space); dragged together with its shape it rides along bound. Labels ride the arrow: `labelWidth` is client-measured (the sole width source, height derives from the line count), centred on the polyline's index-midpoint, and the shaft is clipped by an even-odd hole under the label so nothing shows through the text.
- **Arrow type + elbow routing** (`packages/lib/src/vector/elbow-route.ts` + `tools/point-handles.tsx`) — an arrow is `sharp`/`curved`/`elbow`, a 3-way vocabulary DERIVED from its two stored owners (`roundness` + the `elbow` flag) by `arrowShapeOf`/`arrowShapeFields`, so the panel's Type row and the model never drift. An elbow arrow persists ONLY the `elbow` flag, its two endpoints, and the bindings — its orthogonal "snake" route is derived on every read/render by `elbowRoute` (grid + A\* over the two bound shapes' padded AABBs, a plain L/Z route when unbound; never throws), so the server renderer draws exactly what the canvas draws. One gate — `arrowRoute` in `elbow-route.ts` — decides when an arrow gets a derived route (elbow + scene context, else its stored points); every path (live canvas, previews, export, hit-test, bounds, label) reads it, so none can silently degrade an elbow arrow to a straight line. An elbow arrow pins angle 0 (its route lives in the unrotated local frame), so the panel disables the Angle input for a pure-elbow selection. **Point handles**: a single selected line/arrow shows round `.eigen-vertex-handle` dots (drag to reshape, Delete to remove a vertex) with translucent `.eigen-midpoint-handle` dots between them (drag to insert a vertex, the insert + drag landing in one sealed write) — instead of an ObjectTransform box for the 2-point case. Elbow arrows show vertex dots only (their bends are derived, not stored). An elbow arrow's **first and last segments are pinnable** too (`elbow-pins.ts`, the upstream jog model): dragging an end segment inserts an L-jog that turns the pinned segment interior while the endpoint itself never moves (a bound end is re-inserted verbatim, interior pins reindexed), so "first/last segments are never fixed" holds as an output property. The `startIsSpecial`/`endIsSpecial` flags mark such inserted jogs and are cleared on the reverse move.
- **Freedraw pressure** (`packages/lib/src/vector/types.ts`) — a freedraw stroke can carry per-point pen pressure in a `pressures` field (a JSON array aligned by index with `points`, in its own field so the 2-tuple points re-serialization can't strip it) plus a `simulatePressure` flag; `simulatePressure: false` + a matching pressures array feeds perfect-freehand the real per-point widths (Excalidraw's model), while an absent field (or `simulatePressure: true`) reproduces the velocity-simulated stroke. One shared render path reads both, so the server SVG renderer draws exactly what the canvas draws.
- **Typed clipboard** (`packages/lib/src/types/clipboard.ts` + `core/clipboard/`) — items carry geometry (`width`/`height`/`angle`) and text `typography` as FIRST-CLASS typed fields (never sniffed from `meta`); build/read via `buildImageClipboardItem` / `buildTextClipboardItem` / `readClipboardBox`. **Both dims are mandatory** — the producer measures its own rendered box (docs measures the figure's `<img>`), so a consumer places straight from the wire and never probes the image for a ratio. Rich-HTML arbitration uses `hasRichHtmlBeyondMarker(clipboardData)` to tell an eigen-only payload from one that also carries meaningful external HTML. Flavor policy: a pure-image object copy writes the eigen JSON with NO `text/plain`; a text copy writes `text/plain` (no png); a mixed copy that writes `text/plain` writes no png — so a paste into chat/mail never double-pastes. Cross-mount images re-upload into the target `media/` via `needsReUpload` / `reUploadImage`, skip-on-failure. See [CLIPBOARD.md](CLIPBOARD.md).
