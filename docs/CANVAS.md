# Canvas Conventions

> **TLDR**: Shared conventions for the free-canvas editors — vector (`packages/ui/src/components/vector/`) and slides (`apps/slides/`). One keymap, one layered-Escape priority stack, and a set of shared primitives (ObjectTransform, snap, marquee, align/arrange, clipboard, collab lifecycle) so selecting, moving, resizing and arranging objects feels identical everywhere. Docs is a partial canvas (figures adopt ObjectTransform only); sheets floating images adopt the object system but keep the grid model.

## Keymap

Every canvas command runs through `@tanstack/react-hotkeys` (`useHotkey` with `enabled` gating + `ignoreInputs` for Mod-combos), so shortcuts keep working while focus sits off-canvas and auto-ignore text inputs. The step/offset constants are one source in `packages/lib/src/vector/geometry.ts` (`NUDGE_STEP`, `NUDGE_STEP_LARGE`, `DUPLICATE_OFFSET`) so vector and slides never drift.

| Shortcut | Action | Notes |
|----------|--------|-------|
| Letter / digit | Select the matching tool | `V/1` select, `R/2` rect, `D/3` diamond, `O/4` ellipse, `A/5` arrow, `L/6` line, `P/7` draw, `T/8` text, `E/0` eraser (Excalidraw letters; vector only) |
| `Q` | Toggle the tool lock (padlock) | Locked, a shape/line/arrow/text tool stays active after a placement instead of reverting to select (freedraw/eraser always do); session-only, vector only |
| `Arrow` | Nudge selection by `NUDGE_STEP` (1) | Unsealed — rapid taps coalesce into one undo step |
| `Shift+Arrow` | Nudge by `NUDGE_STEP_LARGE` (5) | Unsealed |
| `Mod+A` | Select all (slides: active slide's objects) | `ignoreInputs` so it never hijacks input select-all |
| `Mod+D` | Duplicate selection at `+DUPLICATE_OFFSET` (10,10) | One sealed undo step; reselects the copies |
| `Delete` / `Backspace` | Delete selection | One sealed undo step, then clears selection |
| `Mod+[` / `Mod+]` | Send backward / bring forward | `useZOrderHotkeys` owns the manual `event.code` listener (⌘⇧[ arrives as `'{'`) |
| `Mod+Shift+[` / `Mod+Shift+]` | Send to back / bring to front | Same hook |
| `Alt`-drag | Duplicate — clones materialize at gesture END in one transact | Local preview ghosts during the drag; the drag never writes, so it stays one undo step. Alt is read off the terminal pointerup (vector) / mouseup (slides); dnd-kit hosts (stickies) track Alt via a keydown/keyup ref because the drop event carries no modifier state |

Reference implementations: vector `packages/ui/src/components/vector/hooks/use-vector-keyboard.ts` (the canonical keymap hook) and vector-canvas's gesture loop for Alt-drag; slides wires the same keys in `apps/slides/src/components/slides/editor.tsx` and Alt-drag in `hooks/use-object-drag.ts` (the UX reference).

## Layered Escape

Escape is priority-ordered, not a single handler. Slides' capture-phase document listener is the documented reference: **present → text-edit → find-bar → deselect** — each layer claims Escape and stops propagation only if its layer is active, so the innermost active mode wins. Vector layers similarly (mid-gesture cancel via ObjectTransform's capture-phase claim → deselect → return to select tool), and its gesture-cancel restores the gesture's base selection (additive marquees keep the prior set). This ordering is load-bearing (the find bar's own bubble-phase Escape would otherwise close it before a canvas handler could tell it had been open). **This is a documented convention, not a refactor target** — do not try to extract a shared Escape router; the capture-phase ordering per host is intentional.

## Touch / stylus policy (vector)

Ported from Excalidraw and kept in `packages/ui/src/components/vector/tools/touch-gestures.ts` (the canvas only dispatches — `vector-canvas.tsx` must not grow). The surface is `touch-action: none` (`touch-none` on the canvas container), so single-finger events reach the pointer handlers directly. Four behaviors: (1) **penMode latch** — the first `pointerType === 'pen'` pointerdown flips a session-scoped penMode; while it's on a `pointerType === 'touch'` pointerdown can no longer start a draw/create gesture (allowlist: `select` + `text`), so a resting palm can't draw. A mouse is never affected. (2) **Two-finger pan + pinch-zoom** — a second touch aborts the live one-finger gesture (a freehand stroke under `SPIKE_MAX_POINTS` = 10 points is a palm spike and is discarded, else finalized — `drawing.abortForSecondTouch`), then both pointers drive pan + pinch through `useViewport`'s imperative `pinch(scale, px, py, panDx, panDy)`, which stays the single owner of the clamp/anchor math (the gesture module never duplicates it). (3) **Coarse hit-slop** — the screen-px grab threshold is fattened by `COARSE_HIT_SLOP_MULTIPLIER` (1.75, our addition; upstream keeps it constant) through the single `hitThresholdScreen(coarse)` seam in `geometry.ts`, gated on `matchMedia('(pointer: coarse)')` (`useIsCoarsePointer`). (4) **Double-tap → text** — two quick stationary taps synthesize the same text-edit entry a mouse double-click uses; a touch that DRAGS is never a tap, so a drag can never enter editing. Real palm rejection, pressure feel, and iOS/Android gesture conflicts need a physical device — headless can only assert the pure decision/pinch math.

## Shared Primitives

The generated inventory is [SHARED-PRIMITIVES.md](SHARED-PRIMITIVES.md); the canvas-specific seams and where they live:

- **ObjectTransform + `snapBox`** (`packages/ui/src/components/transform/object-transform.tsx`) — the resize/rotate chrome (ring, grips, cursors, W×H + angle pills). Consumers pass `resizeMode`, `minSize`, and an optional `snapBox?: (b: Box) => Box` applied on the RESIZE path only (never rotate, never the pointerdown echo), before the latch, minSize re-clamped after. A host that doesn't snap omits it (a full no-op). Chrome renders from one CSS source (`.eigen-selection-ring` / `.eigen-selection-handle`), so a selected object looks identical in vector, slides and docs.
- **Panel sections** (`packages/ui/src/components/properties-panel/`) — `TransformSection` (numeric X/Y/W/H/° + aspect-ratio checkbox), `AlignSection` (align/distribute/match-size, presentational — the host owns the write), `ZOrderButtons` (+ `useZOrderHotkeys`). All speak canonical geometry (`x, y, width, height, angle`).
- **Marquee** (`packages/lib/src/vector/geometry.ts`) — `marqueeMode(startX, currentX)` resolves direction (rightward = contain, leftward = intersect) and `marqueeHits(bounds, marquee, mode)` is the pure hit test. Slides shows the dashed border for intersect. Shared math; hosts keep their own drag/render loops.
- **Snap** (`packages/lib/src/vector/snap.ts`) — `computeSnapTargets(boxes, excludeIds, extraV?, extraH?)` builds edge/centre targets (rotated objects contribute centre only; slides seeds canvas-edge guides via `extraV`/`extraH`, vector's infinite canvas passes none), and `snapBoxToTargets(box, targets, mode, threshold, centerOnly?)` returns the snapped box plus the matched guide lines. **Threshold contract**: it is in the box's coordinate units, so a zoom-aware host (vector) passes `SNAP_SCREEN_THRESHOLD / zoom` to keep the snap radius a constant SCREEN distance at any zoom; a zoom-less host (slides) passes a plain constant. **Rotated rule (`centerOnly`)**: a rotated box's axis-aligned edges lie about its visual box, so it snaps by CENTRE only as a mover and contributes centre only as a target. Move snaps in the gesture loop; resize feeds ObjectTransform's `snapBox`.
- **Align / arrange math** (`packages/lib/src/vector/arrange.ts`) — `computeArrange(items, op)` over the minimal `{id, x, y, width, height}` shape returns position/size patches; the host applies them in one sealed transact.
- **Collab lifecycle** (`packages/lib/src/core/collab/hooks/use-collab-doc.ts`) — `useCollabDoc` owns the Y.Doc + WebsocketProvider + UndoManager lifecycle. It exposes `synced` (live sync state — drives presence and seed-on-sync), `connected` (live socket state from the provider's `status` event) and a LATCHED `loaded` (true after the first sync, reset only on teardown / pathId swap). **Gate the loading screen on `loaded`, never `synced`** — a mid-session WS blip must not unmount the editor (which would destroy y-prosemirror undo history / transient selection); the mounted doc converges on reconnect. Sheets is the exception: it gates on `!initialData`. While the socket is down the editor keeps working: edits land in the local Y.Doc and y-websocket pushes them on the next sync handshake. Every collab toolbar surfaces that through the `DocumentShareCluster` `offline` prop (`loaded && !connected`, an "Offline, will sync when back online" pill), and the hook blocks `beforeunload` while offline edits are waiting, because there is no local persistence — a reload or closed tab loses them.
- **Parent→child ref repair** (`packages/lib/src/core/collab/normalize-refs.ts`) — `normalizeParentChildRefs(doc, parentMap, childMap, childRefField, orderArrayName)` repairs the two corruptions a concurrent merge can leave in a parent-holds-child-ids structure: a child referenced by MORE THAN ONE parent (keep the last parent's copy, delete the earlier ones) and a child referenced by NO parent (append it to the first parent). **Both ends rank parents by the host's order array** (slides `slideOrder`, stickies `columnOrder`), never by `Y.Map` key order — key order is that peer's local integration order, so peers that created parents concurrently disagree about which is "first"/"last" and can delete each other's survivor, leaving the child in no parent at all. Parents absent from the order array ("strays", themselves a corruption) rank BEFORE every ordered parent, so a stray only wins the dedupe when it is the sole holder and is never a re-home target — neither end may park a child on a parent the UI never renders. Idempotent, one `NORMALIZE_ORIGIN` transaction, safe to run on every remote merge. Hosts: `normalizeDeck` (`apps/slides`) and `normalizeBoard` (`apps/stickies`).
- **Typed Yjs root + id-array reads** (`packages/lib/src/core/collab/yjs-utils.ts`) — slides and stickies read their roots and nested id lists through three accessors instead of `as Y.Map<…>` / `as Y.Array<…>` / `as string[]` casts: `getItemMapRoot(doc, name)` for a root map of per-item Y.Maps (`slides`/`objects`/`columns`/`tasks`), `getIdArrayRoot(doc, name)` for a root id list (`slideOrder`/`columnOrder`), and `getIdArray(map, field)` for a nested one (`objectIds`/`taskIds`). Roots need no runtime guard — `doc.get` upgrades an `AbstractType` root (the state `Y.applyUpdate` leaves server-side) in place, and throws only on a genuine type mismatch — while `getIdArray` narrows with `instanceof Y.Array`, which is sound because nested types integrate with their real constructors and never decode as `AbstractType`. Both ends read through them: the FE hooks (`use-deck.ts`, `use-board.ts` and their dnd/dialog siblings) and the BE readers (`apps/api/src/lib/document/slides.ts`, Worker-pure, + `stickies.ts`, main-thread — it takes a `Mount`), which import the React-free `@workspace/lib/collab/yjs-utils` subpath. Per-key scalar reads on a heterogeneous item map (`slideMap.get('title') as string`) still cast — one value generic can't type mixed keys.
- **Back-references are derived, never authoritative** — the parent's ref array is the truth. Slides objects also carry `slideId`, which the shared repair does not touch, so `normalize-deck.ts` reconciles every object's `slideId` to the slide whose `objectIds` actually holds it (same transaction, write only on change). A stale `slideId` misroutes real paths: duplicate / z-order WRITE into `slidesMap.get(src.slideId)` (which can recreate the very duplicate-reference corruption), and comment-open + in-document search NAVIGATE by it. Stickies needs no such pass — its cards carry no column id.
- **Sealing discipline** — discrete ops (delete, duplicate, arrange, z-order, drag-end commit) bracket their Yjs write with `undoManager.stopCapturing()` on BOTH sides so they don't merge into the previous step within Y.UndoManager's 500ms `captureTimeout`; nudges and text typing stay unsealed so they coalesce. Technical fixups that must never be undoable (the pending→real image mediaName swap, the U6d ref repair) run under a non-null origin sentinel that escapes the UndoManager's default `{null}` trackedOrigins — `UNTRACKED_ORIGIN` (vector's `updateElementUntracked`/`deleteElementsUntracked`, `use-vector-doc.ts`) and `NORMALIZE_ORIGIN` (`collab/normalize-refs.ts`); the write still broadcasts to peers.
- **Arrow bindings** (`packages/lib/src/vector/geometry.ts` + `tools/binding.ts`) — an arrow endpoint binds to a shape by storing a `fixedPoint` anchor (a proportion of the target's local w/h), so the endpoint follows the shape's move/resize/rotate by construction (R3.2). Bindings are **forward-only**: the shape→arrows reverse index is derived in memory (`arrowsBoundTo`), never stored, so there is no second write to keep consistent, and a binding whose target is gone or no longer bindable is dropped to unbound **on read** (`clearDanglingBindings`, the Y.Doc untouched). After any element patch the hook re-runs `followBindings` and writes the re-glued geometry **inside the same transact** (R3.9) — one undo step, one broadcast — so every caller (nudge, drag-commit, align, paste-move) glues for free; a shape+arrow moved rigidly no-ops via `followBindings`' null return. A **curved** (round, ≥3-point) bound arrow docks on where its rendered Catmull-Rom shaft crosses the shape outline (`curveOutlineDock` / `arrowCurveBeziers` in `geometry.ts`), not the straight chord — so the drawn curve meets the outline exactly at the head. The curve is golden-locked by test to roughjs's control points at roughness 0, and the dock is endpoint-independent (it replaces the bound end with the resolved anchor and reads only the interior vertices + anchor + shape), so it's a strict fixed point and `followBindings`' exact no-op still holds for a settled arrow. A bound arrow dragged ALONE detaches only past `ARROW_UNBIND_SCREEN` (10px screen-space); dragged together with its shape it rides along bound. Labels ride the arrow: `labelWidth` is client-measured (the sole width source, height derives from the line count), centred on the polyline's index-midpoint, and the shaft is clipped by an even-odd hole under the label so nothing shows through the text (R3.6/R3.12).
- **Arrow type + elbow routing** (`packages/lib/src/vector/elbow-route.ts` + `tools/point-handles.tsx`) — an arrow is `sharp`/`curved`/`elbow`, a 3-way vocabulary DERIVED from its two stored owners (`roundness` + the `elbow` flag) by `arrowShapeOf`/`arrowShapeFields`, so the panel's Type row and the model never drift. An elbow arrow persists ONLY the `elbow` flag, its two endpoints, and the bindings — its orthogonal "snake" route is derived on every read/render by `elbowRoute` (grid + A\* over the two bound shapes' padded AABBs, a plain L/Z route when unbound; never throws), so the server renderer (`scene-to-svg`) draws exactly what the canvas draws. One gate — `arrowRoute` in `elbow-route.ts` — decides when an arrow gets a derived route (elbow + scene context, else its stored points); every path (live canvas, previews, export, hit-test, bounds, label) reads it, so none can silently degrade an elbow arrow to a straight line. An elbow arrow pins angle 0 (its route lives in the unrotated local frame), so the panel disables the Angle input for a pure-elbow selection. **Point handles**: a single selected line/arrow shows round `.eigen-vertex-handle` dots (drag to reshape, Delete to remove a vertex) with translucent `.eigen-midpoint-handle` dots between them (drag to insert a vertex, the insert + drag landing in one sealed write) — instead of an ObjectTransform box for the 2-point case. Elbow arrows show vertex dots only (their bends are derived, not stored). An elbow arrow's **first and last segments are now pinnable** too (`elbow-pins.ts`, the upstream jog model): dragging an end segment inserts an L-jog that turns the pinned segment interior while the endpoint itself never moves (a bound end is re-inserted verbatim, interior pins reindexed), so "first/last segments are never fixed" holds as an output property. The `startIsSpecial`/`endIsSpecial` flags that mark such inserted jogs are now actively set (and cleared on the reverse move) rather than left dormant.
- **Freedraw pressure** (`packages/lib/src/vector/types.ts`) — a freedraw stroke can carry per-point pen pressure in a `pressures` field (a JSON array aligned by index with `points`, in its own field so the 2-tuple points re-serialization can't strip it) plus a `simulatePressure` flag; `simulatePressure: false` + a matching pressures array feeds perfect-freehand the real per-point widths (Excalidraw's model), while an absent field (or `simulatePressure: true`) reproduces the velocity-simulated stroke, so legacy strokes render pixel-identically. One shared render path reads both, so the server SVG renderer draws exactly what the canvas draws.
- **Typed clipboard** (`packages/lib/src/types/clipboard.ts` + `core/clipboard/`) — items carry geometry (`width`/`height`/`angle`) and text `typography` as FIRST-CLASS typed fields (never sniffed from `meta`); build/read via `buildImageClipboardItem` / `buildTextClipboardItem` / `readClipboardBox`. **Both dims are mandatory** — the producer measures its own rendered box (docs measures the figure's `<img>`), so a consumer places straight from the wire and never probes the image for a ratio. Rich-HTML arbitration uses `hasRichHtmlBeyondMarker(clipboardData)` to tell an eigen-only payload from one that also carries meaningful external HTML. Flavor policy (D6): a pure-image object copy writes the eigen JSON with NO `text/plain`; a text copy writes `text/plain` (no png); a mixed copy that writes `text/plain` writes no png — so a paste into chat/mail never double-pastes. Cross-mount images re-upload into the target `media/` via `needsReUpload` / `reUploadImage`, skip-on-failure. See [CLIPBOARD.md](CLIPBOARD.md).
