# Roadmap — after 1.0

Work that waits until after 1.0, or until a trigger appears. The road-to-1.0 backlog is in [ROADMAP.md](ROADMAP.md). Eigen does not implement backward compatibility for persisted formats before 1.0 — a format-breaking change is done outright now (existing data is dropped, or converted with a one-off) — so from 1.0 every change to a persisted format needs the migration machinery in the first row below.

**Legend** — Effort: S / M / L / XL (rough T-shirt size). Frozen-format: from 1.0 a change to a persisted format (Yjs roots, DB schema, drive MIME values) needs a versioned migration; the machinery in the first row is what makes that possible.

---

## Format-change work

The migration machinery, and the persisted-format changes that wait on it. From 1.0 every one of these needs a versioned migration; the first row is that machinery.

| Item | Status in code | Effort | Frozen-format | Notes |
|---|---|---|---|---|
| **CRDT format migration** ([proposal](proposals/PROPOSAL_CRDT_MIGRATION.md)) | Primitive **already exists** — `restoreYjsDoc` (`packages/lib/src/core/collab/yjs-utils.ts`) does single-transaction live-state replacement, with snapshot-before-restore in `apps/api/src/lib/versioning/`. The system on top is net-new and unbuilt; none of its motivating format changes exists yet. | L+ | **Yes** — touches the document container format; design migration + snapshot rollback up front | Machinery whose only scheduled consumer was the rich-text fragment change (the row below), which is deferred too, so this waits with it. Net-new: version stamps per container (`doc_format` row in the container's `data.db`), a per-type migration registry, lazy-migrate-on-open + dormant-doc sweep, and a `?fmt=` sync handshake so stale clients can't write old-format data. Mandatory from 1.0. |
| **Rich text boxes merge last-writer-wins** ([CANVAS.md](CANVAS.md)) | In-place rich text exists and is live-collaborative — every keystroke writes the `html` scalar through (`packages/ui/src/components/vector/kinds/richtext.tsx`), and different boxes merge normally. The one gap: `html` is a single scalar field on the element map, so two people typing in the SAME box at the same moment resolve last-writer-wins for the whole box, with no character-level merge like the eigendoc editor's `Y.XmlFragment`. | M | **Yes** — a per-box `Y.XmlFragment` replaces the scalar `html` field | Only bites when two people are inside the same text box, which is rare on a drawing or slide. The fix stores each box as a Yjs fragment, mounts TipTap's collaboration binding on it (which also scopes undo per box), converts existing `html` strings, and fences stale clients — a container-format change, so it lands with the migration machinery above. The limitation stays documented in [CANVAS.md](CANVAS.md) § Rich text in place. |
| **Sheets stable row/column-id Yjs build** ([proposal](proposals/PROPOSAL_SHEETS_YJS_WORKBOOK.md)) | Sheets keeps one JSON snapshot string plus an op log in Yjs (roots `state.snapshot` + `ops`, `eigensheets/2` snapshot string). Cells have no stable identity, so a `"r_c"`-keyed `Y.Map` is a trap (row inserts re-key the whole sheet, concurrent inserts corrupt it). A real Yjs workbook needs stable row/column ids and id-based formula references. Unbuilt. | L–XL | **Yes** — a full format break of `.eigensheets`: new roots replace `state.snapshot` + `ops` | An engine-level change (~200 MB server RAM per open 340k-cell workbook, ~10 B permanent dead weight per map write). `Y.UndoManager` is in-memory and per-tab like the engine's stack, so undo alone does not justify it. Deferred until the engine needs stable ids for another reason; the four in-place op-log fixes (format-neutral) ship first, in [ROADMAP.md](ROADMAP.md). |

## Deferred — large net-new builds or low value-per-effort today

| Item | Status | Effort | Why defer |
|---|---|---|---|
| **Home Recents** ([proposal](proposals/PROPOSAL_HOME_RECENTS.md)) | 0% | M | Polish for autosuggest/palette; nothing is blocked on it. Its old blocker (File-History actor threading) is gone; needs a new `recents.db` migration. |
| **Copy-Paste ECP v2** ([proposal](proposals/PROPOSAL_COPY_PASTE.md)) | 0% | L | Cross-app converters + BroadcastChannel bus + cut coordination. Current text/image cases already work; Phase 0 (the async-path MIME fix) is in [ROADMAP.md](ROADMAP.md). |
| **Graphs / charts** ([proposal](proposals/PROPOSAL_GRAPHS_CANVAS.md)) | 0%. One native canvas `chart` kind drawn by the existing roughjs painter, arrows bind to marks by row/column id through the existing docking math, docs/sheets embed the same renderer as a figure. | XL | Table-stakes eventually, but net-new across four apps. Snapshot data first; live sheet ranges need a key column for row identity. Remove the dead fortune-sheet chart scaffolding first. |
| **Scripting platform** ([proposal](proposals/PROPOSAL_SCRIPTING_PLATFORM.md)) | 0% | L | Foundations exist (document layer, ACLs, SSE, CodeMirror), but "Deno isn't a true sandbox" caveat. |
| **AI integration** ([proposal](proposals/PROPOSAL_AI.md)) | 0% | XL | Needs a GPU sidecar the host lacks; its flagship semantic search is superseded by the FTS5 plan. Keep as grant narrative, not a build. |
| **Stalwart mail backend** ([proposal](proposals/PROPOSAL_STALWART_MAIL.md)) | 0% | XL | The proposal's own decision section says **don't build it** until a user asks for JMAP. The `MailStore` seam it would plug into exists. |
| **Async `MailStore.search`** | Interface landed; `size()` is already async, only `search()` is sync | S | Only needed once a second (remote) mail backend exists — widen the type together with that backend. |
| **Transform queue → preparation closures** | Accepted drift, recorded in [DOCUMENT-TRANSFORMS.md](DOCUMENT-TRANSFORMS.md) | M | Queued transform jobs retain their full payloads (captured Yjs blobs, upload copies, export media) instead of the original proposal's "small job descriptors or preparation closures". Bounded in practice (~5 foreground exports + 8 background admit; payloads capped by upload quota / doc size), and admission is checked before capture and media prep. Refactor to closures (capture/prep when the job starts) only if queued-payload memory shows up in production — it reworks the reviewed runner seam (prepare-error propagation, abort-during-prepare, the whole runner suite). |
| **Vector: freehand simplification, imperative drag, SVG import as shapes** | Not started. A freehand stroke stores its raw points (`packages/lib/src/vector/kinds/freedraw.ts`, no Douglas-Peucker pass before the commit), a drag re-renders the moved layer every frame and re-runs its roughjs path (only the viewport is imperative), and an SVG pastes as an image, never as elements. | S–M each | Three edges of the drawing app. The stroke payload only matters once several people sketch in one document; the imperative drag is unmeasured and has two traps (a cancelled gesture must reset the transform, a remote edit mid-drag replaces the fragment); SVG-as-shapes is a parser for a small subset. None blocks a workflow today. |
| **Slide animations / transitions** | 0% — no transition or animation model in `apps/slides` (the only `transition` hits are dnd-kit's sortable and a CSS class) | M | Every slide renders as a static canvas frame. Animation is a second, timeline-shaped concept layered on the element model, with its own export story (PDF and HTML have nowhere to put it). Present mode works without it. |
| **PPTX import / export** | 0% — no `pptx` anywhere; `apps/api/src/lib/export/` covers canvas/doc/sheets/vector and `import/` covers doc/sheets | L | The interchange format for decks, and the same class of build as the xlsx/docx work: a full OOXML package mapped onto the canvas element model, in both directions. Wait for someone who has to hand a deck to PowerPoint — PDF export covers reading today. |
| **Dangling card-chat cleanup + same-name card retry** | 0% | S | The two leftovers of the create work ([STORAGE.md § Creating a container](STORAGE.md#creating-a-container)), both scoped out because atomic create plus create reconcile stop the inflow. (1) A one-off `scripts/` pass that loads each board container's `data.db`, collects the `chatName` values from its `tasks`/`comments` maps, lists the `chat/` subfolder and reports chat containers nothing references, older than a 24 h grace so it can never race a create in flight; report-only by default, trashing only on an explicit flag. (2) A retried card create still mints a fresh `fileName` per click, so two clicks that both reach the server leave one chat behind; reusing the name across clicks would need the card's name to be picked once per intent, not per attempt. Worth building only if litter reappears. |
