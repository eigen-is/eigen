# Roadmap after 1.0

Work that waits until after 1.0, or until a trigger appears. The road-to-1.0 backlog is in [ROADMAP.md](ROADMAP.md). Before 1.0 a format-breaking change is done outright ([ROADMAP.md](ROADMAP.md) states the policy). From 1.0 every change to a persisted format needs the migration machinery in the first row.

**Legend**: Effort: S / M / L / XL (rough T-shirt size). Frozen-format: from 1.0 a change to a persisted format (Yjs roots, DB schema, drive MIME values) needs a versioned migration; the machinery in the first row is what makes that possible.

---

## Format-change work

The migration machinery, and the persisted-format changes that wait on it. From 1.0 every one of these needs a versioned migration; the first row is that machinery.

| Item | Status in code | Effort | Frozen-format | Notes |
|---|---|---|---|---|
| **CRDT format migration** ([proposal](proposals/PROPOSAL_CRDT_MIGRATION.md)) | Primitive **already exists**: `restoreYjsDoc` (`packages/lib/src/core/collab/yjs-utils.ts`) does single-transaction live-state replacement, with snapshot-before-restore in `apps/api/src/lib/versioning/`. The system on top is net-new and unbuilt; none of its motivating format changes exists yet. | L+ | **Yes**: touches the document container format; design migration + snapshot rollback up front | Machinery whose only scheduled consumer is the rich-text fragment change (the row below), which is deferred too, so this waits with it. Net-new: version stamps per container (`doc_format` row in the container's `data.db`), a per-type migration registry, lazy-migrate-on-open + dormant-doc sweep, and a `?fmt=` sync handshake so stale clients can't write old-format data. Mandatory from 1.0. |
| **Rich text boxes merge last-writer-wins** ([CANVAS.md](CANVAS.md)) | In-place rich text exists and is live-collaborative: every keystroke writes the `html` scalar through (`packages/ui/src/components/vector/kinds/richtext.tsx`), and different boxes merge normally. The one gap: `html` is a single scalar field on the element map, so two people typing in the SAME box at the same moment resolve last-writer-wins for the whole box, with no character-level merge like the eigendoc editor's `Y.XmlFragment`. | M | **Yes**: a per-box `Y.XmlFragment` replaces the scalar `html` field | Only bites when two people are inside the same text box, which is rare on a drawing or slide. The fix stores each box as a Yjs fragment, mounts TipTap's collaboration binding on it (which also scopes undo per box), converts existing `html` strings, and fences stale clients. It is a container-format change, so it lands with the migration machinery above. The limitation stays documented in [CANVAS.md § Every stored field is a scalar](CANVAS.md#every-stored-field-is-a-scalar). |
| **Sheets stable row/column-id Yjs build** ([proposal](proposals/PROPOSAL_SHEETS_YJS_WORKBOOK.md)) | Sheets keeps one JSON snapshot string plus an op log in Yjs (roots `state.snapshot` + `ops`, `eigensheets/2` snapshot string). Cells have no stable identity, so a `"r_c"`-keyed `Y.Map` is a trap (row inserts re-key the whole sheet, concurrent inserts corrupt it). A real Yjs workbook needs stable row/column ids and id-based formula references. Unbuilt. | L–XL | **Yes**: a full format break of `.eigensheets`: new roots replace `state.snapshot` + `ops` | An engine-level change (~200 MB server RAM per open 340k-cell workbook, ~10 B permanent dead weight per map write). `Y.UndoManager` is in-memory and per-tab like the engine's stack, so undo alone does not justify it. Deferred until the engine needs stable ids for another reason; the three in-place op-log fixes (same roots and snapshot string) ship first, in [ROADMAP.md](ROADMAP.md). |

## Deferred: large net-new builds or low value-per-effort today

| Item | Status | Effort | Why defer |

| **shadcn: move from the `new-york` style to a current one** | 0% | M | `components.json` names shadcn's old `new-york` style, and the registry keeps its newest components, such as Code Block and Trace, only in the new styles (`radix-nova` and its siblings). So `shadcn add` 404s for them, and `code-block.tsx` and `kbd.tsx` in `packages/ui` were copied in by hand, with our `cn` and no Shiki. Moving means re-pulling the 30-odd shadcn files in `packages/ui/src/components` (`shadcn add --diff`), keeping our changes to them (Button's sizes, Dialog's `size`, the menubar's `pressClosesMenu`), and checking every app's look, since every control restyles. The new registry items also depend on shadcn's `cn` npm package and Code Block's highlighter on Shiki, two new packages to approve or swap out. Nothing is blocked: a new component copies in by hand in minutes, so it waits until a release has room for a visual pass. |
| **Docs: Edit › Paste and Paste without formatting** | 0% | S | Edit holds Cut and Copy, which fire `execCommand` for the editor's own handlers ([DOCS.md](DOCS.md#a-docs-copy-with-an-image-writes-its-items-in-order-and-a-docs-paste-reads-its-html)), but no Paste, because reading the clipboard asks the browser's clipboard-read permission. | **Charts: more types, mark-bound arrows and linked data** ([CHARTS.md](CHARTS.md)) | A chart is a column, bar, line or pie chart (`CHART_TYPES`, `packages/lib/src/types/chart.ts`). Not built: doughnut, area, scatter and time axes, combination charts (more than one chart group in a file's `c:plotArea`, which an import refuses as "Combination chart not imported": 48 of the pptx corpus's 433 charts and 57 of the xlsx corpus's 399) and secondary axes, log-scale axes, and a file's manual layout (`c:layout`, the plot area, legend and title placed by the file, in 232 pptx and 174 xlsx corpus charts). The layout places those itself, so an imported chart whose frame overlaps a slide title draws its plot under the title, where PowerPoint draws it lower. Excel draws the value axis at the top or right when the category axis runs `maxMin` (`c:orientation`) or the value axis crosses at the category axis's max (`c:crosses max`); Eigen always draws it at the bottom or left, so such an imported chart shows it on the other side. An arrow binds to a whole chart, never to one bar, slice or point; Convert to shapes is the way to annotate a mark. A chart outside Sheets holds inline data only, so none follows another document's sheet range. | S–M each; linked data L | Each is its own decision, taken when users ask. A type or a label widens `ChartSpec`, `parseChartSpec`, the layout and the editor together. An arrow bound to a mark needs the binding to name the mark by its series and category, kept when the mark goes, never retargeted. Linked data needs a permission-checked refresh through the Drive ACL wrapper and the Home relay ([SCALABILITY.md](SCALABILITY.md)). A chart's own sheet inside its document, the step before it: [PROPOSAL_CHART_SHEETS.md](proposals/PROPOSAL_CHART_SHEETS.md). |

LaTeX export can reuse `@workspace/math`'s LaTeX writer for equations; LaTeX import is the harder half (macros, packages) and starts with a documented subset. |

| **Single-machine multi-process cluster** ([proposal](proposals/PROPOSAL_SINGLE_MACHINE_CLUSTER.md)) | 0%. The seams it builds on exist: every authenticated route carries `:ownerId`, every cross-home call funnels through `apps/api/src/lib/home/home-relay.ts` (still a direct `getHome()` on every push and pull), `routes/internal.ts` already holds `requireLocalhost`-guarded endpoints that the `Caddyfile` 404s from outside, and the API port is already `EIGEN_API_PORT`. Nothing cluster-specific does: no `cluster.ts`, no `docker-compose.cluster.yml`, one `eigen-api:8000` upstream with no `map`/`lb_policy header` block, no `/internal/relay/:ownerId` or `/internal/pull/:ownerId/*` endpoints, no `dispatchToLocalHome()` split in the relay. | M | Capacity work, and the road to 1.0 is data trust, and one process still serves the whole box. Build it when one API process saturates a multi-CPU host; file descriptors, not memory, set the per-process Home ceiling ([proposal](proposals/PROPOSAL_FD_BUDGET.md)), and the `ulimits: nofile` pin sits on the single `eigen-api` service, so each cluster service needs its own. Depends on the durable home-relay outbox ([ROADMAP.md](ROADMAP.md)) (in a multi-process deployment the outbox is the message transport), and the "Home lifecycle + relay" audit names itself a prerequisite for any multi-server work. |
| **Transform queue → preparation closures** | Accepted drift, recorded in [DOCUMENT-TRANSFORMS.md](DOCUMENT-TRANSFORMS.md) | M | Queued transform jobs retain their full payloads (captured Yjs blobs, upload copies) instead of the proposal's "small job descriptors or preparation closures". Bounded in practice (~5 foreground exports + 8 background admit; payloads capped by upload quota / doc size), and admission is checked before capture; an export's media is prepared inside its job, not queued. Refactor to closures (capture/prep when the job starts) only if queued-payload memory shows up in production. It reworks the reviewed runner seam (prepare-error propagation, abort-during-prepare, the whole runner suite). |

| **Dangling card-chat cleanup + same-name card retry** | 0% | S | The two leftovers of the create work ([STORAGE.md § Creating a container is all or nothing](STORAGE.md#creating-a-container-is-all-or-nothing)), both scoped out because atomic create plus create reconcile stop the inflow. (1) A one-off `scripts/` pass that loads each board container's `data.db`, collects the `chatName` values from its `tasks`/`comments` maps, lists the `chat/` subfolder and reports chat containers nothing references, older than a 24 h grace so it can never race a create in flight; report-only by default, trashing only on an explicit flag. | **CJK fonts** ([TYPOGRAPHY.md](TYPOGRAPHY.md)) | 0%: no Noto face is bundled, so Chinese, Japanese and Korean text renders in whatever font the browser has. | M | A full CJK face is about 16 MB, so it can't ship in every app like the four bundled fonts. | **A folder named like a standard mailbox in another case is invisible** | `canonicalMailbox` (`packages/lib/src/constants/mailboxes.ts`) case-folds the six standard names at every domain entry, so on a case-sensitive file system an `.archive` an IMAP client made beside `.Archive` is skipped by the enumeration (`isStandardMailbox` claims the name) and unaddressable (every spelling of it resolves to `Archive`): its messages are reachable over IMAP only. What it takes: fold only `INBOX`, which IMAP itself defines as case-insensitive, and give such a folder a URL segment that `mailboxRouteSegment` does not lowercase onto the standard one. | S | macOS is case-insensitive by default, so this bites on Linux hosts only. The URL form belongs with the inbox naming ([MAIL.md § The inbox is INBOX, and only URLs lowercase it](MAIL.md#the-inbox-is-inbox-and-only-urls-lowercase-it)). |
| **An avatar upload gets no edit grace at a full budget** | `POST /contacts/:ownerId/avatar` (`apps/api/src/routes/contacts.ts`) only stages a photo and answers its URL, so `enforceAvatarUpload` (`apps/api/src/lib/config/enforcement.ts`) knows no contact and no avatar it replaces: it checks `used + fileSize > max` with nothing to credit, and charges the raw upload rather than the smaller stored webp copies. A user at their budget cannot swap a contact's 2 MB photo for a 1 MB one, where the card save itself (`writeCard`) gets the rewrite credit and the 1 KiB grace ([QUOTA.md](QUOTA.md)). | S–M | The fix needs the route to learn which contact the photo is for (a frontend change in the contact form too), then one call through `enforceHomeDataQuota(userId, storedSize, currentAvatarSize)`. A quick fix credited the old photo twice, so a full budget never held. |
| **An `.ics` cannot be imported into a calendar another user shared with you** | `resolveTransferCalendar` (`apps/api/src/routes/calendar.ts`) resolves a team home by `checkCalendarAccess`, so a team calendar the caller may write in is a valid import target, but any other foreign `ownerId` meets `requireSelf` and answers 403, including a calendar a user shared with `write`, because the write would run in that Home and only the relay crosses Homes. The same resolver refuses an export from such a calendar. The picker offers own and team calendars only. | S | It needs an `importEventsAt` in `apps/api/src/lib/home/home-relay.ts` beside `createEventAt`, and the route then resolving every target through `checkCalendarAccess`. A quick fix also let anyone with read access export the whole calendar, reminders and guest lists included, and credited the import to the owner. |
| **A redelivered or reordered REPLY reverts the attendee's status** | Every REPLY is applied as it comes: `processInboundImip` (`apps/api/src/lib/calendar/imip.ts`) verifies it and calls `calendar.receiveAttendeeStatus` or `receiveRsvpForOccurrence` (`apps/api/src/lib/calendar/invitations.ts`), and the RFC 5546 ordering guard `isNewerRevision` (`apps/api/src/lib/ical/ical-component.ts`) orders the organizer's own messages only, since a REPLY carries no revision of its own. So an accept that arrives behind the decline that replaced it (a greylisted mail, a forwarded copy) marks the attendee accepted again, silently. The relay path (`propagateRsvp` in `apps/api/src/lib/calendar/invite-propagation.ts`, the `calendar:rsvp` case in `apps/api/src/lib/home/home-relay.ts`) is fire-and-forget, so two answers in quick succession can land in either order too. | S | iCalendar has no per-attendee revision property, so ordering replies needs a stamp Eigen writes on the `ATTENDEE` line itself and compares the way it already compares the organizer's: a new stored format for a rare case, and a later edit of that occurrence lost the line in the quick fix. |
| **Verify of an older server archive from the admin pane** | Designed, not built: `apps/api/src/routes/server-backup.ts` has no verify route and `BackupJob.kind` has no server verify. A server archive copied back from the bucket or another machine lists with no verdict, cannot be uploaded (`startArchiveUpload` answers 409: it has no readable record), and is only checked when `./eigen restore` stages it. Fix: a verify job that streams one member at a time out of the outer tar into `extractArtifact`, runs `verifyFolder` and wipes it, after a room check for the largest member, and a **Verify** action on the archive's row. Retention skips an archive without a readable record (`pruneLocalArchives` in `apps/api/src/lib/backup/server-archives.ts`), and the verify writes one, so it also marks the record and retention leaves a marked archive alone. | S–M | A new route, and nobody has asked. If an operator does, `./eigen verify` first. |
| **The invite read path re-parses every `.ics` attachment on every open** | `messageGet` re-parses every `text/calendar` attachment with ical.js each time a message opens: sender-controlled N×size amplification, linear, no recurrence expansion, malformed input contained. Open: both run per home, not per mount; the home is offline meanwhile; room for a second copy; the admin UI and its ACL. Owner idea. | M | Owner idea, M, no user-facing breakage. |
