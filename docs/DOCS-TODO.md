# Docs: TODO

The backlog for the Docs app: the editor, its docx and PDF round trip, and the parity gaps against Word and Google Docs. [DOCS.md](DOCS.md) describes how Docs works today. Data-loss and security bugs, and work shared across apps, are in [ROADMAP.md](ROADMAP.md).

**Legend**: Effort: S / M / L / XL (rough T-shirt size).

## Features

- **A stacking order for images in front of and behind the text** (M): An image or chart in front of or behind the text draws in document order ([DOCS.md](DOCS.md#a-figure-in-front-of-or-behind-the-text-sits-at-an-offset-from-its-paragraph)): no stored order, no Bring to front or Send to back, and the docx reader ignores Word's `relativeHeight`. Deferred by the owner. An `index` on the frame, the canvas's Arrange rows in the figure's context menu (`OrderMenuSub` in its `arrange` slot), ⌘[ and ⌘] (Docs binds them to indent, and the canvas z-order hotkeys bail in a contentEditable), and `relativeHeight` both ways.

- **Reach an image in front of or behind the text by keyboard** (S–M): A positioned image is selected by pointer or touch only; the caret skips it ([DOCS.md](DOCS.md#the-caret-never-rests-before-a-positioned-figure)), so a keyboard-only user can't select, move or delete one. Deferred by the owner with the stacking order. A key that cycles the anchor paragraph's positioned images, arrows that nudge 10 px (1 px with Shift, resize moving to Alt), Escape back to the caret.

- **What page-less mode still lacks** (S each): Page-less mode ([DOCS.md](DOCS.md#a-page-less-doc-draws-a-column-at-the-readers-text-width)) lacks Google's Set as default for new docs and a Column width field in the table panel, so a wide table is resized by mouse only. A table's first stored widths follow the reader's text width. The sideways scrollbar shows always, not on hover. Quick look and the Drive preview cut a wide table at the page edge where the PDF fits it ([EXPORT.md](EXPORT.md#a-table-wider-than-the-text-column-prints-fitted-to-it)), paged docs too. The print fallback (`printDocument`) prints a page-less doc without bands and cuts wide tables. Set as default: one optional space-settings field read on doc create. Column width writes `colwidth`, capped at the paper. Previews and print fallback fit tables by `columnFit` like the PDF. Reader-independent first widths: scale drawn widths by the page map's column over the drawn one, pointer included.

- **A letterhead behind the text in a header or footer** (M): A band holds no positioned image: the docx import drops a header's `behindDoc` picture (`band-content-dropped`), such as a full-page letterhead, and the editor draws a band's positioned image in line ([DOCS.md](DOCS.md#a-positioned-figure-lives-in-the-body-only)). Word draws it behind every page's text. Anchor a band's positioned image on the page, drawn on every page in the editor, the PDF's running elements and the docx band.

- **Docx import: a picture's color effects** (M): `readDrawing` (`apps/api/src/lib/import/doc/drawings.ts`) reads a picture's blip and none of its effects, so transparency (`a:alphaModFix`), washout or brightness (`a:lum`), grayscale, duotone and black-and-white (`a:biLevel`) come in at full color. An opacity attribute and a CSS filter drawn by the editor, HTML and PDF and written back to docx; or re-encode the picture with the effect at import.

- **Docx: comments in export and import** (S–M): `writeDocx` (`apps/api/src/lib/export/doc/docx/`) writes no comments, and the reader (`apps/api/src/lib/import/doc/`) drops a comment and keeps its text ([EXPORT.md](EXPORT.md#a-docs-docx-is-written-from-its-json-with-the-editors-css-values)). Open: whether comments export at all (owner's question), and Word comments as threads on import. Design: each open thread a Word comment with author, initials and date, replies through `commentsExtended.xml` (`w15:paraIdParent`); `readCards` (`packages/lib/src/core/comments/hooks/use-comment-cards.ts`) moves to a React-free subpath; open or resolved from `CommentEntry.status` via `withCommentIndex`, no row meaning open. About 2 to 2.5 days. Deferred by the owner: original image bytes, scaling past 4096 px, EXIF, re-encode caching, the PDF taking images through the docx path.

- **What Word and Google Docs show that a doc can't hold** (L, each gap S–M): The docx reader keeps the text and drops looks the schema can't hold. Rows of their own: header and footer variants, footnotes, suggesting mode, positioned images. The rest, with counts from the 154-file docx corpus (`apps/api/src/scripts/docx-audit.ts`): text boxes in a header, footer, group or canvas; multi-level labels like 1.1 (24); right-to-left paragraphs (22); tab stops and leaders (21); a table of contents (12) and heading ids for internal links (18); columns (9); charts Eigen can't draw ([CHARTS-TODO.md](CHARTS-TODO.md)) and SmartArt, which import as text; heading levels 7 to 9 (imported as H6); per-section page size or margins; WMF and EMF pictures, which show broken. Eigen's own gaps: cell border diagonals and `w:tblPrEx` borders unread, no border width, style or color in the table UI ([DOCS.md](DOCS.md#a-cells-border-is-four-sides-on-the-cell-and-an-unset-side-draws-eigens-grey)); an empty line about twice Word's height; the PDF starts a list below a wrapped figure ([EXPORT.md](EXPORT.md#the-pdf-starts-a-list-below-a-wrapped-figure)); the Word download writes em-based spacing at 11 pt whatever the Normal size; a nested task list leaves a gap in the PDF; Convert shows no summary; the editor draws one long page. Owner: the goal is parity with Word and Google Docs, and eigendoc needs no backward compatibility. Background color comes free with `@tiptap/extension-text-style`. Pick gaps by count; each needs the reader, writer, PDF and a help-center line.

- **Headers and footers** (M): Built ([DOCS.md](DOCS.md#a-header-and-a-footer-are-fragments-of-their-own-beside-the-body)), with PDF, HTML and docx support ([EXPORT.md](EXPORT.md#the-pdf-prints-the-bands-as-running-elements-placed-before-the-body)). Left: quick look and the browser print fallback draw no band; the import drops even-page bands, reads only the final section's bands, drops a band's behind-text picture or VML watermark, and keeps fields other than `PAGE` and `NUMPAGES` as cached text (`DOCPROPERTY` in 22 corpus files); comments and find don't reach a band. Next: a date field, different even and odd pages, and per-section bands.

- **A styled page number** (S): A page number takes only its paragraph's look: `AtomMarks` strips marks off a `pageNumber` as off any atom ([DOCS.md](DOCS.md#an-equation-is-an-inline-node-that-stores-its-mathml)), and the docx writer writes its run without marks. Google and Word style it like surrounding text. An attribute on `pageNumber` holding its marks, set by the toolbar, drawn by the chip and the PDF, written as the field's run properties.

- **Charts in headers and footers** (S–M): A band's schema excludes `chart` (`BAND_EXCLUDED_NODES`, `packages/lib/src/docs/eigendoc/bands.ts`), so a band has no Insert › Chart and deletes a chart a peer writes; the Chart panel and **Edit data** follow the body's editor only ([DOCS.md](DOCS.md#a-chart-is-a-node-of-its-own-in-the-figures-frame)). Word allows a chart in a header. Drop `chart` from `BAND_EXCLUDED_NODES` once the chart panel follows the band's editor, and read a band's chart on docx import (today it keeps the title).

- **What a footnote doesn't hold** (S–M each): Footnotes work across editor, PDF, HTML and docx ([DOCS.md](DOCS.md#a-footnote-is-an-inline-node-that-holds-its-notes-paragraphs), [EXPORT.md](EXPORT.md#a-note-is-a-footnote-in-words-notes-part)). Not held: endnotes, which import as footnotes (11 corpus files); number format, per-section restart and position; a custom mark (`w:customMarkFollows`); lists, tables or headings in a note (imported as paragraphs); comments in a note. Editor: an open note closes when a peer splits its paragraph; an image in a note isn't sized to the note's column; Docs binds no ⌘K for a link. Pick by corpus count; a number format needs the editor, the PDF's `::footnote-call` and the docx's `w:footnotePr`.

- **What equations still lack** ([DOCS.md](DOCS.md#an-equation-is-edited-as-latex-in-its-panel-and-a-draft-stays-in-the-tab-until-it-is-written), [MATH.md](MATH.md)) ((1) M, (2) S–M, (3) M, (4) S, (5) S, (6) S): (1) Paste from Word desktop: its HTML holds OMML in `<!--[if gte msEquation 12]>` comments, which `readOmml` doesn't take; no sample exists yet. (2) Find never matches an equation ([DOCS.md](DOCS.md#an-equations-text-is-its-linear-form-and-the-find-bar-skips-it)). (3) No equation editing on a phone. (4) `eigen-prose.css` keys Chrome-only rules on `@supports (display: block math)`, which WebKit or Firefox may match later. (5) Whether `\middle\|` stretches in Chromium is unchecked ([MATH.md](MATH.md#mathml-is-written-with-marks-its-reader-finds-again)). (6) Optional: accept MathML typed or pasted into the LaTeX field via `readMathml`. (1) needs a real Word desktop clipboard sample first. (2) needs find to match the linear text and select the atom. Each user-visible fix needs a help-center line in `docs/equations`.

- **A math font per doc** ([proposal](proposals/PROPOSAL_FALLBACK_FONTS.md#math), its phase 5) (M): Every equation draws in New Computer Modern Math, in the editor, the HTML download and the PDF ([DOCS.md](DOCS.md#every-equation-draws-in-new-computer-modern-math-with-css-for-what-chrome-leaves-out)), and a doc can't choose another. The proposed `EIGEN_MATH_FONTS` (New Computer Modern Math, STIX Two Math, Fira Math) become the fallback registry's math entries, a `mathFont` key in the doc's style map, one `--math-font` variable for every surface and the PDF per font. Stored format, a MathJax font package per extra face and the picker's place wait for the owner, who ruled that it waits until a user asks. Slides and Vector store the same field on their equation element when they get one.

- **What the table of contents panel still lacks** (S each): The panel sets the layout, the depth and each level's look ([DOCS.md](DOCS.md#a-table-of-contents-stores-its-depth-and-its-look-and-draws-the-outline)). Left against Word: its dashes and line leaders, which the import reads as dots and `leader` has room for as more values; a first level, as the node stores no lower bound and a Word `\o "2-4"` lists levels 1 to 4 here; a look per table of contents in the docx, where a second one comes back with the first's ([EXPORT.md](EXPORT.md#a-table-of-contents-is-words-toc-field-its-entries-derived-both-ways), accepted by the owner).

- **A phone path to the table of contents options** (S): A phone shows no properties panel and its right-click menu has no **Table of contents options**, so a phone can't change a table of contents' layout, levels or look. Owner's answer: Format › Table of contents, as Format › Table and Format › Image hold their panels' actions on a phone ([DOCS.md](DOCS.md#the-properties-panels-follow-the-selection-on-desktop-only)), with the panel's rows as menu choices.

- **Typing in a text box on a phone, and peer carets in a box** (M): On a phone a box can be selected and set up in Format › Text box, but its text is read-only, as a note's is. A box's editor has no collaboration of its own, so no peer's caret draws inside it. Both need the story edited in an editor of its own; a phone's must mount where the keyboard reaches it.

- **A View menu** (S): Docs has no View menu, so Show outline sits in Tools (`apps/docs/src/components/docs/tools-menu.tsx`). As Google ([LAYOUT.md](LAYOUT.md#the-bars-menus-come-in-googles-order)), View holds Show outline. The shared Help menu with keyboard shortcuts is a [ROADMAP.md](ROADMAP.md) row.

## Bugs and small fixes

Verified, bounded, cheap to fix on the next touch.

- **y-tiptap gives a deleted atom's Yjs element to the atom next to it** (S): Found by a two-client probe on 2026-11-01. In a paragraph `a`, equation, equation, `b`, a tab that deletes the first equation keeps the first's `Y.XmlElement`, writes the second's attributes onto it, and deletes the second's element, the two equations alike or not. `updateYFragment` in `@tiptap/y-tiptap` 3.0.9 first looks for children it has mapped, but `findMappedChildAnchors` looks a text child up by a fresh array from `normalizePNodeContent`, so text never anchors, and one equation is too few anchors. Its compare loop then asks `computeChildEqualityFactor`, which scores two childless atoms 0 against 0 and ignores that the right one's element is mapped to that very node, so it updates the left. Anything keyed on a Yjs element of an atom can follow the wrong one, such as a comment anchor, a figure or a chart. The Equation panel tells its draft's equation by content instead ([DOCS.md](DOCS.md#an-equation-is-edited-as-latex-in-its-panel-and-a-draft-stays-in-the-tab-until-it-is-written)). Repro: two editors on two synced Y.Docs as in `equation-properties-panel.test.tsx`, the peer's `tr.delete(2, 3)`, then the surviving element's `_item.id` is the first one's. An upstream candidate: prefer the side whose element is mapped to the node. Whether to file it is the owner's call.

- **A peer's edit inside a footnote, text box or chart is lost when another tab splits its paragraph** (M): Found by two-client probes on 2026-11-03. One tab presses Enter in a paragraph while another edits inside an inline node in it (a footnote's text, a chart's title). On y-tiptap 3.0.10 to 3.0.12 and tiptap main the edit is lost in every case: `syncPositionElement` rebuilds the reused paragraph element and its children. On 3.0.9 it survives only when the paragraph is the document's first or last block; with blocks on both sides `reconcileMappedChildren` rebuilds it. Notes on both sides of the split, two splits at once and Enter inside a list item lose it on every version, since one Yjs element can't serve two halves and Yjs has no move. A fix for tiptap is drafted and waits until after the 0.4.2 release.

- **A peer typing right before an equation still ends its draft** (S–M): Found by a scratch two-client run. When text runs up to the drafted equation, a peer typing or pressing Enter right before it ends the draft and the panel closes: y-tiptap puts the node selection back by a relative position on the character before the equation, and the peer's text now stands between the two ([DOCS.md](DOCS.md#an-equation-is-edited-as-latex-in-its-panel-and-a-draft-stays-in-the-tab-until-it-is-written)). A peer moving the equation mostly ends it too. Fix: keep the drafted equation's Yjs element and select it again after a change through the binding, a second mechanism beside the binding's own selection restore; or a fix upstream in y-tiptap's `getRelativeSelection` for a node selection. Owner picks.

- **The Equation panel stays open and empty when a peer's change takes the selection off its equation** (S): Seen in the browser on 2026-11-01, not traced. When a peer deletes the selected equation, or types right before it in text that runs up to it, the draft ends but the panel stays open with an empty preview and an empty LaTeX field; a click away from an equation in the same tab closes it. The panel's draft logic was changed on 2026-11-01, but not what decides whether the panel shows, so this is likely older ([DOCS.md](DOCS.md#the-properties-panels-follow-the-selection-on-desktop-only)). The panel should close as on a local click away.

- **The first drag of an equation after typing a draft once failed to move it** (S): Seen once in nine runs in the browser, not reproduced. Right after typing a draft in the Equation panel, the first drag of the equation wrote the draft but didn't move the equation; the press became a text selection across two paragraphs. Possibly a race between the blur's write re-rendering the equation's node view and the drag start ([DOCS.md](DOCS.md#an-equation-is-an-inline-node-that-stores-its-mathml)).

- **⌘Z right after a panel change undoes nothing** (S): A change in a Docs properties panel leaves the focus on the panel's control, so ⌘Z reaches no editor until the user clicks back in the page; Edit › Undo and the toolbar's Undo work. Every panel has it, the table of contents' included. Fix: one keydown on the sidebar that sends undo and redo (`undoChord`, `packages/ui/src/lib/undoChord.ts`) to `activeEditor` when the target is not a text field, so a field's own undo stays the browser's.

- **Plain text after Word's own Update Table is unverified** (XS): The docx writes Plain text as a right tab with no leader on each entry and in the `toc N` styles ([EXPORT.md](EXPORT.md#a-table-of-contents-is-words-toc-field-its-entries-derived-both-ways)), checked in LibreOffice only. Word may write its own dotted tab on each entry when it updates the table, which would read back as Dotted. Check on Word desktop: export a Plain text table of contents, Update Table, save and import; if the dots come back, find what Word keeps and write that.

- **A doc whose first block is a table of contents warns on load** (XS): Each load logs ProseMirror's "TextSelection endpoint not pointing into a node with inline content (doc)" in the console, seen in a browser pass on the table of contents panel branch. Unverified whether it predates that branch. A text selection set at the doc's start, where the first block is an atom with no inline content, would log it; find what sets it on load and use `Selection.near` or `atStart` there.

- **A link colored exactly like a link loses its underline in a docx round trip** (XS): `marksOf` (`apps/api/src/lib/import/doc/runs.ts`) reads a link run in the link color with an underline as the plain link look (`LINK_LOOKS`), so a user's own `#2563eb` color and underline on a link come back without the underline. Invisible while the text is a link. Apply `LINK_LOOKS` only to a run without our `Hyperlink` style.

- **A picture can't carry a link** (S): Yjs keeps marks only on text, so a figure can't hold a link, and the docx reader (`pushText` in `apps/api/src/lib/import/doc/runs.ts`, `readDrawing` and `readVml` in `drawings.ts`) drops a picture's hyperlink or `a:hlinkClick`. Needs a figure `href` attribute that the reader fills and the renderers and docx writer draw.

- **Indenting a paragraph moves the image in front of or behind its text** (S): A positioned image's offsets count from its paragraph's padding box ([DOCS.md](DOCS.md#a-figure-in-front-of-or-behind-the-text-sits-at-an-offset-from-its-paragraph)), so Tab, the indent buttons and a list's nest or lift move it; Word keeps it still. Accepted for v1. Compensate `offsetX` in `stepIndent` (about half a day); a list's nest and lift change the CSS indent, so they cost more.

- **A text box's rotation and vertical text** (S–M): The docx reader counts a rotated or vertical-text box as `text-simplified` and draws it upright and horizontal. Needs `rotation` and `textDirection` attributes, the CSS `transform` and `writing-mode`, and the writer's `a:xfrm rot` and `bodyPr vert`.

- **A VML text box is never kept on the paper or aligned** (S–M): `readVmlTextBox` (`apps/api/src/lib/import/doc/text-boxes.ts`) takes a box's `margin-left` as it is. A box in front of the text at `margin-left:700px; width:300px` ends at 1096 px on A4's 793.7 px paper, and a 780 px one is stored at the column's 601 px where a DrawingML box may take the paper's width. In front of or behind the text its alignment is ignored too, and it can sit off the paper: `mso-position-horizontal:right` gives `offsetX: 0`, `margin-left:5000pt` gives 2112 and `margin-left:-200pt` gives -267. Fix: place it through the DrawingML clamp in `anchorPlacement`, with the width the node stores.

- **A floating VML picture imports as a block** (S): `readVml` (`apps/api/src/lib/import/doc/drawings.ts`) writes only a `v:imagedata`'s size, so a picture whose shape is absolute, wrapped square at `margin-left:300pt` or in front of the text, stays in its line. Fix: place it from its shape's style as `readVmlTextBox` places a box, through the same clamp.

- **Every picture in a VML group gets the whole group's size** (S): `readVml` reads the style of the `v:group` for each `v:imagedata` below it, so two pictures that each take half of a 300 by 150 pt group both import at 400 by 200 px. Fix: size each from its own shape's style, scaled by the group's `coordsize`.

- **A picture in a table cell is capped at the text column, not the cell** (S): `readDrawing` and `readVml` cap a picture at `reader.columnPx`, so a 600 px picture in a 133 px cell is stored 600 px wide. Fix: cap it at the cell's width, which the table reader knows.

- **A VML box's named color reads as none** (XS): `vmlColor` (`apps/api/src/lib/import/doc/text-boxes.ts`) reads only a hex, after Word's theme slot such as ` [3213]`. Word writes `strokecolor="black [3213]"`, so that box loses its outline, and `fillcolor="white"` its fill. No reader of CSS color names exists in the repo. Fix: a table of the 16 HTML names, or of all CSS names, shared with whatever else reads a named color.

- **An IME composition across a text box's remount types twice** (S): A peer's re-anchor of the box being typed in remounts its editor mid-composition; in Chrome the pre-edit text stays and the IME's commit adds it again. Rare. Hold the remount's forward until `compositionend`.

- **A closed empty text box shrinks to its padding** (XS): A text box with no stored height and no text is 36 px tall while it is open, but closed, and after a reload, `StaticStory` in `TextBoxView` draws its empty paragraph with no line height, so the box is about 12 px tall. Its 6 px edge bands then cover it, so a click selects the box and typing replaces it; only Enter on the selected box opens it. Draw an empty paragraph of a closed story at the height of one line.

- **An open text box keeps the body's selection ring** (XS): A press on a selected box's text opens it while the body's node selection stays, so `FigureFrame` draws its `eigen-selection-ring` around the open box. Move the body's selection to a caret beside the box as it opens, or hide the ring while it is open.

- **Reach a text box in front of or behind the text by keyboard** (S): The caret rules skip a positioned box as they skip a positioned image ([DOCS.md](DOCS.md#the-caret-never-rests-before-a-positioned-figure)), so a keyboard-only user can't read, type in or select it. The key planned for positioned images (the P2 keyboard row) should reach boxes too; Enter on a selected box already opens it.

- **Two people re-anchoring one image at once can duplicate it** (S): A re-anchor (a drop on another paragraph, a front or behind switch, a join that carries it) is a delete and an insert ([DOCS.md](DOCS.md#a-positioned-figure-moves-by-a-pointer-gesture-kept-on-the-page-maps-paper)), so two peers doing it at once keep both inserts and lose a concurrent attribute edit; a text box duplicates the same way, both copies with one story `id`. Accepted as rare. Fix: an `id` on the figure and the chart too, deduped in an `appendTransaction`, about a day.

- **Word's origin for an anchored picture's vertical offset is unverified** (XS): The docx writer anchors a front or behind image at `positionV relativeFrom="line"` and the reader takes Word's `paragraph` offsets less the space before ([EXPORT.md](EXPORT.md#a-figure-in-front-of-or-behind-the-text-is-a-wrapnone-anchor-at-the-start-of-its-paragraph)), both checked in LibreOffice only. Compare an export in Word desktop and Word for the web after a paragraph with space before; a difference changes one term in `anchoredFigure` or `lineOffset`.

- **No Google Docs re-save pins the title and subtitle** (XS): `google-docs-all-features.docx` predates much of the all-features doc, so the re-save test in `apps/api/src/test/import/doc/round-trip.test.ts` filters out the title, subtitle, table of contents, note and equation paragraphs, page number, positioned figures and chart, and `googleLosses` flips Heading 6's italic (`toggleItalic`). Re-record it from Google Docs and drop the filter and the workaround.

- **Add link sometimes inserts the URL as text on a keyboard selection** (S): Headless, after a Shift+Arrow selection, Add link inserted the URL as new text in 5 of 11 runs: `LinkForm`'s submit (`apps/docs/src/components/docs/link-dialog.tsx`) inserts text when the selection is collapsed, so the selection was lost by then. Needs a headed repro before a fix.

- **A list pasted at the end of a paragraph merges its first item into it** (S): Pasting `<ol><li>one</li><li>two</li></ol>` at the end of a paragraph joins "one" onto it, autolinked across the join, and leaves a one-item list. ProseMirror fits the open slice into the paragraph; Tiptap's autolink reads the join as a domain. Compare with Google Docs before changing it.

- **The doc docx runs a table of many columns off the page** (XS): `gridWidths` (`export/doc/docx/tables.ts`) floors columns at `MIN_TABLE_COLUMN_PX` (25 px), so a table of more than 25 columns on A4 writes a grid wider than the page. The PDF fits at a 1 px floor ([EXPORT.md](EXPORT.md#a-table-wider-than-the-text-column-prints-fitted-to-it)); the docx could take the same.

- **The doc PDF prints a table of many columns cramped** (S): A table fitted at the 1 px floor ([EXPORT.md](EXPORT.md#a-table-wider-than-the-text-column-prints-fitted-to-it)) wraps words a few letters a line, and in a column narrower than the 0.8em cell padding the text draws over the border (POI's 63-column `bug65649.docx`). Print only tables whose columns fall under the 25 px floor with smaller text or cell padding; Word's 0.08" cell margins are narrower than ours.

- **A nested table in the doc PDF can run over its cell** (S): `withTablesFitted` (`apps/api/src/lib/export/doc/transform.ts`) fits a nested table to its cell's widths, but a cell without a width falls back to the page column, so in a fixed-layout parent whose later rows store no widths the inner table draws over its neighbours. Fall back to the first row's width at that column.

- **The doc PDF repeats no table header row** (S): A table the PDF splits over pages ([EXPORT.md](EXPORT.md#the-pdf-splits-a-table-between-its-rows)) shows its header row on the first page only, while the docx repeats it (`w:tblHeader`) and the help center says it repeats. WeasyPrint repeats a `<thead>`: add a `table` mapping in `renderDocHtml` that moves the leading header rows into one, checked against the editor's CSS.

- **Prosemirror-tables' `findWidth` is quadratic in rows once a table has a rowspan** (S): `findWidth`, under every `TableMap`, rescans every earlier row after a rowspan: 49,000 one-cell rows took 27 s in `asOpened`, and the editor pays it on every rebuild. The docx reader splits a merged table every `MAX_MERGED_ROWS` (2,000) rows (`import/doc/tables.ts`), but a table grown in the editor is unbounded. Filed upstream as [prosemirror-tables#347](https://github.com/ProseMirror/prosemirror-tables/issues/347); the split stays until a release fixes it.

- **`@tiptap/static-renderer` nests a text's marks inside out** (XS): It wraps the first mark innermost where ProseMirror draws it outermost, so Eigen renders over a schema whose marks rank in reverse (`inEditorMarkOrder` in `apps/api/src/lib/document/doc-schema.ts`). Filed upstream on [tiptap#7299](https://github.com/ueberdosis/tiptap/issues/7299#issuecomment-6123508591); the reversed schema goes once it is fixed there.

- **Enter on a selected text box on a phone does nothing** (XS): The text box's `Enter` shortcut (`addKeyboardShortcuts` in `apps/docs/src/components/docs/extensions/text-box.tsx`) calls `onOpen` and returns true, but a phone opens no story, so the key only reselects the box. Fix: return false where the host opens no story.

- **A link's right-click rows miss three places** (S): A right-click on a link opens its Open, Copy, Edit and Remove rows only in body text (`linkAtPointer`, `apps/docs/src/components/docs/link-menu-sections.tsx`). In a table cell the table menu wins, on a comment's highlight the comment's menu wins, and in a header, footer or open note the browser's menu shows. Spread `linkMenuSections` into the table and comment menus, and wire the bands' and the story's editors.

## After 1.0

Large builds that wait for a trigger or for the editor to draw pages.

- **A page count in Word count** (M): Tools › Word count has no **Pages** row: the editor draws no pages, so only the PDF knows a count ([DOCS.md](DOCS.md#word-count-reads-the-editors-text-and-its-key-belongs-to-the-page)). Free once the editor draws pages. Before that: estimate from the blocks' laid-out heights (drifts where print moves a table or image whole), or the PDF's count (a route and a full render per open). Add the row to the dialog and the help center.

- **Suggesting mode (track changes)** (XL): No suggestions. The docx reader shows tracked changes accepted (insertions kept, deletions dropped). Version history restores a whole version but shows no changes. 12 of 154 corpus files hold tracked changes. Insertions and deletions as marks with author and time, accept and reject one or all, shown in the comment margin. The reader keeps `w:ins`/`w:del` (later `w:rPrChange`/`w:pPrChange`) and the writer writes them back. Shares rendering with a later compare-versions view. Needs a help-center article.

- **A text box in a header or a footer** (M): A band's schema has no `textBox` and holds no float, so a Word box in a header or footer imports as paragraphs after its anchor (49 of the corpus's 241 `wps` boxes) ([DOCS.md](DOCS.md#a-text-box-is-a-story-in-the-figures-frame)). Needs a box that draws in a band's editor and on every page of the PDF.

- **A text box in a group or a canvas** (M): A `wpg` group or `wpc` canvas imports its boxes' text as paragraphs after its anchor, or as its picture's caption (59 corpus boxes). Its pictures and charts come in at its anchor, each sized at its group's scale (`groupScale` in `import/doc/drawings.ts`), but none at its own offset. Read the group's `a:chOff` too, as `readXfrm` in `import/slides/inherit.ts` does for pptx, and place each box, picture and chart at its own offset, a box sized at the same scale.
