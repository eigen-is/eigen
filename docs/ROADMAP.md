# Roadmap

Prioritized backlog of the work still to do on **the road to a trustworthy 1.0**. Eigen runs in production but is honest about being pre-1.0, so the data-integrity work comes first. The P3 deferrals and everything else that waits until after 1.0 (or until a trigger appears) live in [ROADMAP-POST-1.md](ROADMAP-POST-1.md). Status is what exists today, not what the proposal hoped for; the detailed designs live in the `docs/proposals/PROPOSAL_*.md` files referenced per row.

The page holds only open work. When work ships, its row or the done part of it goes in the same commit: no done rows, no strikethrough, no status history. The same goes for [ROADMAP-POST-1.md](ROADMAP-POST-1.md). A bug found and not fixed gets a row in the same commit as the work that found it, naming the file and function, the failure and the callers.

Eigen does not implement backward compatibility for persisted formats before 1.0: a format-breaking change is done outright now (existing data is dropped, or converted with a one-off), and a migration system becomes mandatory only from 1.0. Stickies are the exception: eigen.is users rely on them, so stickies data stays backward compatible now. Self-host tooling has no backward compatibility either: scripts, env-file shapes, Compose layouts, archive, snapshot and backup formats, and runtime state across releases: an old script is deleted, never shimmed, and the running instances get a short manual note. Moving per-app object shapes onto one field convention (`x,y,w,h`) is reason enough to reshape non-stickies data. No pre-1.0 item left on this page breaks a persisted format; the remaining format breaks live in [ROADMAP-POST-1.md](ROADMAP-POST-1.md).

A grant application (NLnet Restack, call opens 2026-09-03, deadline 2026-11-03) funds the data-integrity push; the funding and launch tactics themselves are tracked separately in `docs/superpowers/strategy/` (local-only) and are not duplicated here.

The current focus, ahead of announcing the open-source repository, is the self-hoster's path: install, update, whole-server backup and a mail-off install. What is left of it is the Light restore row in P0.

**Legend**: Effort: S / M / L / XL (rough T-shirt size). Frozen-format: pre-1.0 the column flags a change to a persisted format (Yjs roots, DB schema, drive MIME values) that drops or converts existing data when done.

## Focused audits (future-proofing reviews)

Audit a layer right before a feature builds on it: findings are cheapest to fix then.

The recipe, per area:

1. Clean up the area with the [source-file skill](../.claude/skills/source-file/SKILL.md), every step of it, held to the [CODE-STANDARDS.md](CODE-STANDARDS.md) bar: renames, top-down order, moves to the right module, splits, honest types, visibility and imports, not only headers and comments. The report is the skill's per-file table. Code that exists for the area but lives in other modules moves into the area. Risk findings are reported, not fixed.
2. A cold review of the result.
3. One fix round, each fix with a red test first.
4. A scoped re-review of the fix diff.

Start with the risk-seam files: ACL checks, locks, persisted formats, cross-home calls, parsers of untrusted bytes.

Still to do:

- Tier 2 units: auth, storage, config, scheduler, setup, user.
- Routes (`chat.ts`, `space.ts`, `editor.ts`, `team.ts`, `settings.ts`, and the rest), each with its domain class, its `packages/lib` hooks and its `types/<domain>.ts`.
- Chat with its lib hooks.
- Calendar with CalDAV (`routes/calendar.ts`, `lib/ical`, `lib/caldav`, share and invite propagation, recurrence, iMIP); audit the two DAV servers side by side.
- Notification center, versioning, share, search, waitlist.
- `packages/lib` absences (owner-scoped query keys carry `ownerId`, mutations use `onMutationError`, SSE handlers invalidate what their emitter changes) and the `types/drive.ts` split into per-concern modules (it holds a private twin of `getExtension` that cannot import the shared one from `constants/preview` without a cycle).
