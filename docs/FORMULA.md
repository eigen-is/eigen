# Formula engine

> **TLDR:** The formula engine computes a workbook's formulas with no grid, no browser and no clock of its own. It holds the cells, parses each distinct formula once, recomputes what a write reaches and rewrites references when rows, columns or cells move. It is `@workspace/formula` (`packages/formula/`), a leaf beside `@workspace/math`: it imports no workspace package, and numfmt is its one dependency. The idea it rests on: a formula is stored as text relative to its own cell, so a formula filled down ten thousand rows is one text, parsed once. Today the product uses it for number display, Excel's function names and the row and column map (`mapIndex`, `mapSpan`, `GONE`); step 1b of [PROPOSAL_FORMULA_ENGINE.md](proposals/PROPOSAL_FORMULA_ENGINE.md) switches Sheets to it.

A host holds one `Engine` (`src/recalc/engine.ts`) per workbook. It loads the sheets from a description of their cells, then writes values and formulas, makes structural edits and calls `recalc`, which computes what changed and says which cells did. A host is the program around the engine: today the package's tests and the sheet package's workbook (`packages/sheet/src/engine/book/`), which nothing in the product runs yet, in step 1b the editor and the server through that workbook. A sheet is named by its id and a cell by its row and column from 0. A call the engine refuses, such as a cell off the grid, throws before anything changed. A read refuses only a sheet that is not there, named by its id or by its place (`sheetAt`); of a row or column that is no cell, `valueOf` and `formulaOf` answer null, `isPending` false and `nextCell` -1, and `cells` reports nothing for a block whose top or left is none. A load is refused the same way: a cell whose row or column is no whole number on the grid, or whose number is NaN or infinite, throws from `new Engine` or `addSheet` before the workbook holds any of the sheet (`admit` in `src/store/workbook.ts`, the one check for a write and a load).

The host's cells are the truth. The engine holds nothing a second load would not rebuild, so it is a computed copy of the workbook, never a second store. Inside it a cell is a slot in a column's typed arrays: its value, and for a formula the id of its shape. A shape is one distinct stored formula text with its parsed tree. The stored text writes a reference as an offset from its cell and a sheet by its id. A text is held once in the workbook's string table, and a cell holds its id.

These terms come back in every section. A pass is one `recalc` call. A seed is a cell written since the last pass, the start of what the pass computes. A row is one function as the registry declares it, and a word is the declaration of one of its parameters. The host hands the engine the time and a seed for random draws with every batch of edits.

The sections run from the package's place, through the three spellings of a formula, the store, values, evaluation, functions, recalc, edits, number display and the xlsx dialect, to the rules the build wrote down, the differences from Excel and the tests. A few things surprise people: [the day line is Google's](#the-day-line-is-googles-not-excels), so a date in January or February 1900 is one day earlier than in Excel; [empty text is 0 in arithmetic](#empty-text-is-0-in-arithmetic); [a formula whose result is blank leaves its cell blank](#a-blank-result-leaves-its-cell-blank-as-in-google-sheets); [a cell on a loop holds `#REF!`](#a-loop-is-found-by-computing-it-and-every-cell-on-it-holds-ref); [a clock formula moves with every edit, and only then](#the-clock-moves-with-every-batch-of-edits); and [a table reference is gone after import](#a-table-reference-is-one-leaf-and-the-importer-resolves-it-to-a-range).

## It is a leaf, reached through four entries

The engine runs unchanged in the browser, in Bun and in Node. Arithmetic, `^` and what is built on them answer the same on every machine; `LN`, `LOG`, `LOG10`, `EXP`, `ATAN2` and the trigonometric and hyperbolic functions and their inverses use the runtime's `Math`, and over the same 3,000 such calls Bun and Node differed in the last bit on 283 and in the 15 digits a cell shows on 23. So it imports no workspace package and no runtime API, and reads no clock and no locale. Biome enforces each part: the package imports nothing outside itself, numfmt only under `src/format/`, and `Date`, `Intl`, `performance` and `globalThis` are refused globals; `scripts/check-standards.ts` also fails module-level state, `Math.random` and a locale call there. Its tsconfig has `lib: ["ESNext"]` and no `types`, as `packages/math` does ([ARCHITECTURE.md § Dependency direction](ARCHITECTURE.md#dependency-direction)).

| Entry | What it holds | Who imports it today |
|---|---|---|
| `@workspace/formula` | `Engine`, the function registry `FUNCTIONS`, the error values and the host's types | the package's tests and scripts; `packages/sheet` only under `src/engine/book/`, where the workbook holds the engine and reads its error values |
| `@workspace/formula/text` | the parser and printers, `storedKey`, A1 labels and sheet names, `mapIndex` and `mapSpan`, the transforms, the xlsx dialect, `resolveTables`, `tokens` | `packages/sheet`, for the row and column map; lib's op validators and limits, for five constants |
| `@workspace/formula/format` | `numberDisplay`, `isDateFormat` and `numberFormatError` (numfmt's reason for a format it cannot show, for the format dialog's preview), the product's one call of numfmt's `format` (the sheet asks numfmt only whether a format parses) | `packages/sheet`, `packages/lib`'s charts, the API's xlsx import, chart export and demo seed |
| `@workspace/formula/names` | `isExcelFunction`, `EXCEL_FUTURE_FUNCTIONS` | the sheet engine's `#NAME?` rule, the API's xlsx writer |

The root entry is the whole engine, so a biome rule refuses it in `packages/sheet` outside `src/engine/book/`, and nothing a page imports reaches that folder until Sheets runs on the workbook: the page's bundle does not carry the engine before it uses it. lib imports only `/format`, and from `/text` only the constants its op validators check against (`MAX_STORED_LENGTH`, `GRID_ROWS`, `GRID_COLUMNS`, `ERROR_LITERALS`, `LAST_SERIAL`). A biome rule enforces both for package imports; a relative path into another package's `src` is outside what it checks. So lib, which every app and the server load, carries number display, and takes five constants from the engine's text entry: a bundled page keeps only those, a server loads that entry. `/format` holds no engine for the same reason.

## A formula has three spellings and one tree

One lexer and one Pratt parser (`src/text/`) read every spelling into one immutable tree, and one printer per spelling writes it back.

| Spelling | Reader, printer | What it is |
|---|---|---|
| Typed | `parseA1`, `printA1` | A1 as a person types it at a cell; a sheet name is looked up and becomes an id |
| Stored | `parseStored`, `printStored` | What a cell holds: offsets in R1C1 and sheets by id, so `=SUM(A1:A3)*2` at D5 is `=SUM(R[-4]C[-3]:R[-2]C[-3])*2` and `=Data!$B$2` is `=[id]!R2C2` |
| File | `parseXlsx`, `printXlsx` | An xlsx `<f>`: A1 without the `=`, with Excel's prefixes ([§ The xlsx dialect](#the-xlsx-dialect-is-one-grammar-with-a-rule-for-implicit-intersection)) |

The stored text is canonical: equal formulas print equal text, and that text is the key of the shape table. So a fill writes one shape into every cell. A tab rename rewrites no formula that reads the sheet, since a held sheet is named by its id; it rewrites only formulas typed with the name it takes, which no sheet had. A sheet a formula names while no sheet has that name is stored by its quoted name, and bound to the sheet's id wherever the two meet ([§ No held formula names a held sheet by its name](#no-held-formula-names-a-held-sheet-by-its-name)). Text that does not parse is a result, never a throw: `storedText` keeps it behind a second `=`, which no grammar reads as a formula, so it shows again exactly as typed and evaluates to `#ERROR!` (`src/text/typed.ts`). The parser keeps Excel's limits on nesting and arguments (`MAX_NESTING`, `MAX_ARGUMENTS`), and one bound on length for every spelling, `MAX_STORED_LENGTH`: 131,072 characters, 16 times Excel's 8,192. The bound that matters is the stored key's, since that is what a cell reads back, and a reference to another sheet can be twelve times as long stored as typed: `a!A1` far down the grid is the sheet's id and two long offsets. So `storedKey` prints the key and refuses one past the bound, and `storedText` keeps such a formula as the text that was typed, as it keeps text that does not parse. An importer refuses a file formula whose key `storedKey` refuses. The walks of the dialect can nest a tree deeper than the file's text did, so `parseXlsx` and `intersect` answer a failure, as the parser does, for a tree nested past `MAX_NESTING`.

## Equal stored text is one shape

The shape table (`src/text/shapes.ts`) gives each distinct stored text a small id, which a cell holds in its `shape` plane, 0 meaning no formula. A formula a host hands in, by a write or a load, is keyed by the text its tree prints, not by the text handed (`ShapeTable.intern`): `=sum(R[5]C,1.0)` and `=SUM(R[5]C,1)` are one shape, and `formulaOf` answers the second for both. That costs a load one print per distinct formula text. Spaces are part of a formula, so `=SUM( RC )` stays a shape of its own, and text the stored grammar does not read, such as `r[5]c`, is kept as handed and is `#ERROR!`. A text whose print would be too long to read back (`storedKey`), as `.5` prints `0.5`, is kept as handed too, with its tree, so it computes, unless it names a sheet by its name: then it does not parse ([§ No held formula names a held sheet by its name](#no-held-formula-names-a-held-sheet-by-its-name)). A shape keeps its text, its tree, its references and its facts: what the tree says about every cell that holds it, worked out once from the tree and the function list (`shapeFacts` in `src/eval/facts.ts`). The facts say whether the build can evaluate it at all (`Kept`, for a reference into another workbook or across sheets: the cell keeps the value it has, and with none, as a typed one has, it holds `#REF!`; an import or a paste writes such a formula with its value, `setFormula(sheet, row, column, text, given)`, which is ignored for any other formula, and `isGiven` tells a host which formulas to send a value beside), whether it reads cells its references do not name (`ReadsUnnamed`), whether it calls a function that reads the clock or draws (`Clock`, anywhere in the tree, in a branch never taken too), whether an edit can change its answer through a place or a size, whether a function that takes every value reads a range whose top row stays put down a block (`Anchored`, [§ A range that grows down a block](#a-range-that-grows-down-a-block-is-read-once-per-pass)), and how deep it nests.

A shape no cell holds is forgotten when the reverse index is rebuilt after a sheet that held formulas changed, or after the table gave out an id (`ShapeTable.added`, `ReverseIndex.rebuild`, [§ A pass](#a-pass-computes-what-the-writes-reach-and-can-stop)), and its id is given out again. The index counts the blocks that hold each shape, so it says which are held without a walk of the book. So a shape that no block ever held, as a formula written and written over before a pass, or a formula an edit rewrote before it was refused, is forgotten by the next rebuild, and a stream of refused edits leaves the shapes of one behind. An id means one shape only while a cell holds it, and the table stays as long as the most shapes it ever held.

## A cell is a slot in four typed column planes

A column (`src/store/column.ts`) is four parallel typed arrays over its rows: `kind` (the value's kind, with the recalc's flags in its high bits), `num` (a number), `ref` (a text's id, an error's code, or 1 for TRUE) and `shape`. Most arithmetic allocates nothing, and a loop over a column skips per-cell checks with the column's counts of errors, pending formulas and loops. A sheet keeps the counts of its pending and looped cells too, which its columns write as they change their own, so `settled()` is one step per sheet and a pass skips a sheet at zero. A column ends at its last cell, and a sheet has no column past the last one written; the empty ones before it are one shared frozen column, so a write into one that was never made throws. So a sheet costs its cells and a pointer per column before the last: about 128 KB for one cell in the last column. A load allocates each column at exactly its rows. A write or a row insert past them grows the arrays to the rows it needs and an eighth more, 64 rows at least and 65,536 at most, and never past the grid (`capacityFor`): one inserted row never doubles a column, and rows inserted one by one move it once in many. One exception follows from it: a column costs its last row, 17 bytes a row, so a single cell on the grid's last row reserves about 18 MB for its column. The system hands out those pages only when they are read or written, and a load touches only the cells it writes, so at load the cost is small: 200 cells on the last row, each in its own column, hold 54 MB resident on Bun and 75 MB on Node. The first rebuild of the reverse index reads the shape of every row, 4 bytes a row: after it the same cells hold about 850 MB. A row delete moves every slot of each column and so writes them all: after it they hold 3.4 GB on both runtimes, and one cell holds about 20 MB. A row insert above them is refused, since it would push them off the grid.

The string table (`src/store/strings.ts`) holds every distinct text once under an id, with the id of its upper-cased key beside it, so two texts that differ only by case compare as two integers. It forgets texts no cell holds in a sweep at the start of a pass (`Workbook.sweep`), when the table weighs more than `SWEEP_FLOOR` (2^22 characters) and twice what it weighed after its last sweep or load, or when a sheet was removed; a text counts its characters plus 16. A freed id goes to the next new text. A sweep was chosen over counting references per id: a count has no slow pass and less memory, but one miscount at any of the nine places that drop a cell shows a wrong value. The cost is an uneven pass on a sheet where one cell feeds a very large block of text formulas.

A column also keeps an index for exact lookups and equality criteria (`src/store/column-index.ts`): for each value, its rows in order. It is true for one version of the column, and the first ask at a version only notes it, so a column read once pays nothing.

## Values are plain JavaScript, errors are frozen objects

A number, a text and a boolean are the JavaScript types and a blank is `null` (`src/values/value.ts`). An error is one frozen object per kind, told apart by identity (`src/values/errors.ts`); an error only a file knows is carried as an object of its own. A reference stays a reference, unread, until something needs its value, and an array keeps its written size apart from what it stores, so a whole column costs its cells and not the grid.

Each coercion is one function for operators and arguments alike (`src/values/coerce.ts`): a text is a number when a person could have typed it into a cell as one (`parseNumber`), and a failed coercion is `#VALUE!`. The one order of values (`src/values/compare.ts`) puts a number below a text, a text below FALSE and FALSE below TRUE; a blank takes the other side's kind, numbers compare at 15 digits and texts by their keys. Excel's 15 significant digits apply where a number is compared, where a sum lands next to zero and where a rounding function cuts (`src/values/precision.ts`), so `0.1+0.2` equals `0.3`; arithmetic itself keeps every bit.

## One evaluator, and arrays are always on

The evaluator (`src/eval/evaluator.ts`) is one recursive switch over a shape's tree, given the cell the formula sits in, since the tree belongs to every cell of its shape. Reading a cell goes through the recalc, which computes a formula still to be computed first, so the order of a pass comes from these reads and nothing works it out ahead.

There is no array-formula mode. An operator with a range or an array on either side gives an array, element by element, in one loop over its operands ([§ An operator reads a range where it lies](#an-operator-reads-a-range-where-it-lies)). A function where one value is read and an array comes does so too: the call is lifted, run once per element (`src/eval/lift.ts`). An array stores one element for a run of equal ones, so the loop and the body run once per stored element. Two arrays are lined up by where they were written (`src/eval/bands.ts`). A cell holds the top-left value of an array result, since this step has no spill, and an array of references reaching the cell is `#CALC!`. One array stores at most 2^24 elements and one formula does at most 2^27 units of work (`MOST_STORED`, `MOST_WORK` in `src/recalc/recalc.ts`); past either the formula is `#CALC!`, alone. `@` in front of a range takes the cell on the formula's row or column, as Excel's implicit intersection does.

## A function is one row of words

A function is one line in its family's file under `src/functions/`: `fn('NAME', [parameters], body)` (`src/functions/registry.ts`). A parameter is a word that says how its argument is prepared, read, defaulted and repeated, and the call wrapper (`src/eval/call.ts`) does all of it before the body runs. So a body only computes: it gets one plain typed value or reader per parameter, does not coerce, read a cell or test for an error, and returns a value or an error for an input outside its domain. A biome rule refuses an import of `eval/`, `store/`, `recalc/` or `values/coerce` in a family file. A NaN or an infinity becomes `#NUM!`, and a text past 32,767 characters `#VALUE!`, without the body's help. `src/functions/library.ts` collects the families into `FUNCTIONS`, the one list a call is looked up in, and a name not there is `#NAME?`.

The order a call is worked in is also the rule for which error it answers: the count of arguments, every argument evaluated left to right but the lazy ones, every argument read by its word left to right, the insides of the ranges a family takes, in argument order and row by row, then the body, then the lazy argument the body picked.

| Words | What the body gets |
|---|---|
| `NUMBER`, `INTEGER` (cut toward zero), `NEARLY` (a hair under a whole number is that number), `SERIAL` (a date), `TEXT`, `BOOLEAN` | One value read as that kind; an array lifts the call |
| `PLAIN`, `ANY`, `CORNER` | One value as it is: no error, any value, or the first cell of a range |
| `LAZY`, `LAZY_VALUE` | A token; the wrapper evaluates the argument only if the body answers with it |
| `NUMBERS`, `COUNTED`, `FILLED`, `TRUTHS`, `NUMBERS_A`, `FACTORS`, `MODES`, `WHOLES` | Every value of the arguments, as that family counts a typed value, a cell and an array element (`src/eval/families.ts`) |
| `TEXTS`, `PAIRS`, `PRODUCTS` | Every value as text; two ranges side by side; ranges multiplied place by place |
| `WHERE`, `MATCHED`, `BLANKS` | The cells a criterion accepts, the numbers beside them, the cells that show nothing |
| `TABLE`, `ANYTHING` | A range or an array whole, to search, pick from or measure |
| `REFERENCE`, `HERE` | A place, never read; `HERE` left out is the formula's own cell |
| `NOW`, `RANDOM`, `ROOM`, `ENGINE` | No argument: the time of the last batch of edits, a draw, room for an array, a question about the workbook |

Modifiers change a word: `optional`, `skippable` and `defaulted` say what a left-out or empty argument is; `rest` and `each` repeat a parameter, `each` trying groups in turn as `IFS` does; `strict` and `addin` refuse a boolean, `addin` with the other two answers of Excel's add-in functions; `areas`, `refusing`, `referring`, `cells`, `apiece`, `expecting` and `placed` say what a union, a reference or an array of references does. `chosen` makes a row that picks another by its first argument, as `SUBTOTAL` does, and the marks `PART` and `ANYWHERE` let a row answer a part of its table or a reference it worked out. The signature records the words become are in `src/eval/signature.ts`.

To pick a word, type the function in Excel first: what Excel answers for a text, a boolean, an empty argument, a fraction and a range at that place decides it, and nothing else does. The law tests prove the wrapper does what a row says, never that the row says what Excel does, so a row also gets tests with Excel's recorded answers. A word the vocabulary lacks is added to the registry, never written inside a body.

## A pass computes what the writes reach, and can stop

The reverse index (`src/recalc/reverse-index.ts`) answers which formulas read a cell. It is built from rectangles of cells that hold one shape, with about one entry per reference of the shape, listed by the blocks of columns the reference reads and sorted by row. It is derived per sheet and never patched, so it cannot drift from the cells it describes. A sheet's blocks are found again from its columns when the sheet is forgotten, as a formula written or written over forgets its sheet and an edit forgets the sheets whose cells it moves, adds or removes (`ReverseIndex.forget`), or reshaped, when an edit only rewrote its formulas where they stand: then only the columns of the blocks it had are read (`reshape`). Each block is filed under what it reads: the id of every sheet a reference names, whether a sheet has that id or not, and a key of its own for a shape that asks the workbook itself, works a reference out, reads the clock, or names a sheet by a name or a span of sheets. Per sheet id that is read there is one `Listing` (`src/recalc/listing.ts`), the structure that finds the entries reading a span of rows, and a rebuild lists again only the sheets that the changed sheets read or did read. Nothing in the index holds the place of a sheet, so a sheet that comes, goes, moves or is renamed lists nothing again by itself, and a sheet that comes back under its id finds its readers listed. A pass marks: it flags every formula that reads a seed or a flagged formula, by the references it names and by the references it worked out when it last ran, and every formula that asks the workbook itself ([§ A reference worked out at run time](#a-reference-worked-out-at-run-time-is-recorded-and-followed-like-a-named-one)). Then it walks the flagged cells in sheet, column and row order and computes each, reading what it needs first.

`recalc(cap)` stops once it has stored `cap` formulas, before it runs the next (the top of `Recalc.compute`), and the next pass goes on from there: a host can keep a frame free on a large recompute. No finished formula is thrown away: the formulas that are running when the cap is met, each waiting for a cell it reads, finish and are stored, so a pass can store more than its cap by the formulas nested at that moment, which `BUDGET` bounds at about a hundred. A pass never stops before its first store, so a formula that alone costs more than the cap cannot hold every pass up. The nesting of the cells in progress has one budget (`BUDGET` in `src/recalc/recalc.ts`, half the smallest stack the engine runs on): past it the calls in progress are dropped by a throw and computed again from the list of cells in progress, so a chain of a hundred thousand formulas never overflows the stack. A host lets a stopped recalc run on before it writes more, or raises the cap: writes between every stopped recalc keep one from ever finishing when the cap is no larger than what a recalc after a write computes again. The result lists the cells on loops, whether the pass stopped, and the runs of cells whose value changed.

## A range that grows down a block is read once per pass

A running total, `=SUM($A$1:A1)` filled down, would read its rows again in every formula, so its block would cost the square of its rows: 20,000 of them took about 295 ms on Bun. Within one pass a cell that is computed keeps its value, so what one call found in a range holds for every later call of the pass that reads the same rows. A call whose walked argument is one reference, in a formula whose shape has such a range with an absolute top or bottom row or a whole column (`Fact.Anchored`), takes a carry for its range (`Carries.of` in `src/eval/carry.ts`): per sheet, top, left, right, the kinds the family counts and whether an error answers, and the skips, the row the computed and error-checked rows end above with their first error, and per answer (`count`, `sum`, `min`, `max`) the row it ends above, its value, the cells counted and the sum before the last addition. A range that reaches further down computes, checks and walks only the rows below (`look`, `Numbers.resume`, `Walk.below`), through the walk and the adder every call uses. A sum is a fold from 0 in written order, so going on from the carried sum and its sum before the last addition gives the same bits and the same snap next to zero as adding the range from its top: no value moves, Excel's recorded ones included. A range whose top moves with its row, as `A1:A3` filled down, never meets its carry again, so a shape without an anchored range takes the plain path and pays nothing for the carry. A range that is not an extension of its carry's starts it over at the cost of a plain call: one whose top moves down, as `A1:$A$1000` filled down, or one read bottom up. Rows a sheet hides or filters are fixed within a pass and part of the key through the skips. The carries are 16 slots on the evaluator, picked by a hash of that whole key, the skips included, so `SUM($B$2:B2)-SUM($C$2:C2)` keeps two, and so do two ranges 16 columns apart and SUM and SUBTOTAL(109) over one range. The recalc's era moves at every pass and at every loop that closes, and a carry of another era starts over: no carry outlives a pass, and none skips a cell a loop left in progress, which a reader must reach to join that loop. Nothing is carried on when a formula computed while the rows below were read took the slot for another range (`Carry.mark`), or carried the same range past the call's last row, which only a loop through the range can do. The body checks the same again before it goes on from the carry (`Numbers.resume`): a later argument that computes formulas, as texts do, could move it in between. Covered are the bodies that ask `sum`, `count`, `min` or `max` of one range: SUM, COUNT, COUNTA, AVERAGE, MAX, MIN and their A forms, OR, and those codes of SUBTOTAL and AGGREGATE. A body that takes `list()` or `holds()`, such as PRODUCT, MEDIAN and AND, still walks the whole range, and so does a criterion, as in `COUNTIF($A$1:A2,A2)`. Now T7 takes about 18 ms on Bun, an edit of A1 under it about 5 ms, and 200,000 rows about 190 ms.

## A load is computed whole or not at all

A formula whose result is blank and a formula never computed both come with no value, and a value walked after a pass that stopped, or after a write no pass followed, is stale, which nothing in the cell shows. So a load says once whether its values are computed, and the engine trusts all of them or none: `new Engine(sheets, now, seed, computed)`. With `computed` true every value is what a full pass computed, a formula with no value is its blank result, and the open computes nothing; only a formula that came with `#REF!` is computed again, with what reads it ([§ A loop](#a-loop-is-found-by-computing-it-and-every-cell-on-it-holds-ref)). The first write or edit after it also computes every formula that works a reference out, once, since no formula ran to record what it reads ([§ A reference worked out at run time](#a-reference-worked-out-at-run-time-is-recorded-and-followed-like-a-named-one)). With it false no formula's value is trusted and every formula is to be computed, as the formulas of an added sheet are (`Workbook.read`). A formula this build cannot evaluate is no part of either: whatever door it enters by, a write, a fill, a load computed or not, or an added sheet, it holds the value it came with from that moment, and `#REF!` with none, and no pass computes it (`Recalc.keep`). So no reader sees a difference a pass makes, and `isGiven`, which answers by the shape alone, is true of a cell that always holds a value: an inverse or a snapshot carries that `#REF!` beside the formula, and writing it back holds the same. A computed load that brings one with no value, which no walk of the engine makes, seeds its readers, so `settled()` is false until a pass; one that came with `#REF!` is no loop to look for and is not computed again. `Engine.settled()` says which a walk is: true when no write, edit, clock or change of the rows a sheet leaves out waits for a pass (`Recalc.seeds`, `stamped`, `rowed`) and no formula is flagged (`Sheet.pending`). It is false right after `setClock`, after a `setRowsOut` that changed a list ([§ The rows a sheet hides and filters](#the-rows-a-sheet-hides-and-filters-are-the-hosts-to-say)) and after every structural edit, even with no clock formula, since only the pass looks for them and an edit can move a draw to a cell that draws another number. A host writes the flag `settled` gives beside the walk, which the sheet workbook's `content()` does, and never sets it by hand: a `true` that is not so is never healed, since nothing reads those values again until a write reaches them. One workbook of the corpus stores 18,669 formulas that are blank by rule; read as never computed they cost 1.6 s at every open, and a computed snapshot of it now opens computing nothing. A build that computes differently makes every stored value stale in any design, this flag included.

## A loop is found by computing it, and every cell on it holds `#REF!`

A cell read while it is being computed is on a loop with every cell reading towards it. Each of them holds `#REF!`, as Google Sheets shows a circular reference, and the pass lists them. An `IFERROR` on the loop does not catch it, and one outside does. A loop is found by computing, never by a graph walk, since what a formula reads can hang on values: `=IF(B1,A1,2)` is a loop only while B1 is TRUE. A load carries no loops, so a formula that came with `#REF!`, which every cell on a loop holds, is computed by the first pass after a computed load (the `Recalc` constructor flags it): `loops` then lists what a load without values lists. It is a seed of that pass too, so every formula that reads it is computed with it: a marking takes the readers of a flagged formula for flagged, and with the flag alone a write or an edit before the first pass left a reader that holds another value, such as `=IFERROR(A1,7)`, with a value no fresh recalc gives. The `#REF!` is told by its code, as a cell stores it, so a copy a host made of the value counts. A loop whose cells came with other values, as in a file Excel wrote, where they hold 0, shows once one of its cells is computed. `src/test/recalc/recalc.test.ts` pins the cases.

## A reference worked out at run time is recorded and followed like a named one

Every cell a formula reads is known to a marking in one of three ways. What its references name is in the index. A reference worked out from values as the formula runs is recorded when it runs (`Recalc.record`); three places make one, and each sets `Fact.Resolves` on the shape: a row marked `ANYWHERE` (`OFFSET`, `INDIRECT`), a colon between two operands, whose box holds cells neither names, and a `MATCHED` range that takes its size from its criteria range. And a row that takes `ENGINE` and asks the workbook itself (`CELL`, `FORMULATEXT`, `ISFORMULA`, `SHEET`, `SHEETS`) carries `ReadsUnnamed` and is flagged by every marking, since its answer, such as whether a cell holds a formula, can change with no value changing. `INDIRECT` takes `ENGINE` only to find the sheet a text names, which an edit alone changes, so it is of the second kind. `src/test/functions/gates.test.ts` pins both lists, so a new `ENGINE` or `ANYWHERE` row fails it until someone looks.

A record is what one cell's formula resolved the last time it ran: one box for each sheet it resolved into, around every area of that sheet (`Records`, `src/recalc/records.ts`). It is memory only, never stored. A run builds its boxes as the formula resolves (`Recalc.record`), and when the formula ends they replace the record if they differ, so a formula that resolves the same areas changes nothing and one that resolves nothing holds no record. A record is bounded by the sheets a formula reaches, not by how many areas it resolves: a call lifted over a column, as `=SUMPRODUCT(N(OFFSET($A$1,ROW($A$1:$A$100000)-1,0)))`, resolves 100,000 areas and holds one box. The index holds the records in listings of their own, one per sheet that a box lies on and an entry per box, all built again when a record changed (`ReverseIndex.listRecords`), and a marking follows them for every span beside the listing of the named references. A record names its cell by number, its sheet's place times the columns of the grid plus its column, and its row (`Records.end`), so listing the records reads no column. That is safe because places change only in `Workbook.apply`, which an edit runs after it dropped every record.

**A box can flag more than the formula read.** A formula that resolved two areas far apart on one sheet is also flagged by a write between them and computed once more, to the same value. A list of the areas would flag exactly, at a size nothing bounds: 20 of the lifted formulas above held 237 MB as lists and hold 3.7 MB as boxes, and their first write took 728 ms where it now takes 353 ms. On the corpus workbook of 3,744 such formulas a write inside a table flags the same 1,404 formulas either way.

**The invariant: a formula that resolves is flagged, or its record covers everything it last resolved.** A formula that ran keeps it by recording. Three rules keep it where none ran:

- A computed load ran no formula, so the first marking after it flags every formula that resolves, once. The open itself still computes nothing ([§ A load is computed whole](#a-load-is-computed-whole-or-not-at-all)).
- Every structural and sheet edit drops all records and flags them all in its own marking (`Recalc.edit`): areas move with rows, columns and cells, and a rename or a new sheet changes what an `INDIRECT` text names. An edit that is refused has dropped the records too, and the next marking flags them.
- A cell whose formula went, or gave way to one that works no reference out or that this build cannot evaluate, loses its record when the index is rebuilt (`Records.prune`). A formula that still works one out, and resolved nothing when it last ran, dropped its record as it ended.

A pass that stops inside a formula leaves it flagged and its record as it was: the boxes of a run replace the record only when the formula ends. Excel and LibreOffice compute `OFFSET` and `INDIRECT` again at every recalculation, which costs one corpus workbook of 3,744 such formulas 60 ms on every write; recorded, a write none of them reads costs 0.1 ms. The price is the record, about 200 bytes a formula that resolved into one sheet and five numbers more for each further sheet, and the listing built again after a batch that changed one. `src/test/recalc/resolved.test.ts` pins each rule by name, `records.test.ts` the bound of a record, and `resolved-law.test.ts` holds the values against a fresh load under every kind of edit.

## The clock moves with every batch of edits

A row that takes `NOW` or `RANDOM` never reads the machine (`NOW`, `TODAY`, `RAND`, `RANDBETWEEN`, and `DATEVALUE` and `TIMEVALUE`, since a date without a year takes the current one). The host hands the engine a clock with each batch of edits it applies, `Engine.setClock(now, seed)`: the author's time as a serial and a whole number the author drew. The next pass then computes every clock formula again, whatever the batch wrote, as Excel does after any edit: a formula whose tree calls such a row anywhere (`Fact.Clock`), and what reads it. So every reader of one log of batches computes the same values itself, and nothing about a clock cell is sent: its value depends on what it reads, the last batch's clock and the cell's place alone.

`setClock` only stores the clock and notes that a stamp is due. The pass then flags the blocks the reverse index files under the clock (`ReverseIndex.reading`), so in a workbook whose formulas all name what they read a stamp costs the clock formulas and their readers, not the workbook. A formula that resolves a reference follows the clock like any reader: it is computed again when an area it resolved holds a clock formula or a reader of one, and when its own tree calls a clock row, as `=OFFSET(A1,RANDBETWEEN(0,2),0)` does. So 10,000 `=OFFSET(A1,0,0)` beside one `=NOW()` cost one formula on a batch that writes nothing. The stamp runs for every `setClock`, with the same clock too, and every structural edit makes one due (`Recalc.edit`), since a row insert moves a clock cell under one clock. A pass that stopped goes on with the same clock, and a batch that arrives meanwhile stamps every clock formula again, computed or not. A load takes the clock its values were computed with (`new Engine(sheets, now, seed, computed)`) and stamps nothing: a clock formula of a computed load keeps the value it came with, and one of a load that is not computed is computed with that clock. A formula this build cannot evaluate (`Kept`) is never stamped.

A draw is made of the seed and the cell. The n-th draw of a formula is a function of the seed, its sheet's id (`Sheet.salt`), its row, its column and n (`Recalc.draw`), and no stream runs from cell to cell. So a draw is the same in whatever order the cells compute, whether or not a pass stopped at its cap, and however often a throw for depth starts a formula again. `RAND()-RAND()` is two draws, and an array of eight `RANDBETWEEN` draws eight. A tab that moves or is renamed keeps its draws, and a cell that an insert moves to another row draws others at the next pass. `src/test/recalc/clock.test.ts` holds the law: readers that pass after every batch, once at the end, capped, with a wrong clock in between, through a fold, through a load and from nothing end with equal values.

A host calls `setClock` once per batch it applies and not for one it refuses, stores the last clock with a snapshot and loads with it, and writes beside a walk whether the engine is `settled` ([§ A load is computed whole](#a-load-is-computed-whole-or-not-at-all)). Two costs follow from the rule. Every batch computes every clock formula and its readers again, so a filled column of 10,000 `RAND()` costs one compute of that column per batch on every reader. And a reader whose cap is below its clock formulas and their readers does not settle while batches keep coming.

## The rows a sheet hides and filters are the host's to say

`SUBTOTAL` and `AGGREGATE` leave out rows the sheet does not show, and only the host knows which those are. It says them per sheet, whole, as two lists: `Engine.setRowsOut(sheet, hidden, filtered)`, the rows hidden by hand and the rows a filter left out, each as sorted pairs of a first and a last row that share no row (pairs may touch; anything else throws a `RangeError` with the lists as they were). `SUBTOTAL` 1 to 11 leave out the filtered rows, 101 to 111 the hidden ones too, and `AGGREGATE` leaves out both for its odd options (1, 3, 5, 7: "hidden rows" in Excel's words) and no row for the even ones, as Excel recorded it (`SUBTOTALS` and the `AGGREGATE` row in `src/functions/math.ts`). A cell on a row that is left out is passed over whatever it holds, an error included, as a cell that holds a nested `SUBTOTAL` is. The rows count for a reference only, on the sheet it reads, and a hidden column counts for nothing. The walk passes a run of rows over in one step (`Walk.cells`), so a row that shows costs nothing for the lists and a formula that leaves no row out never looks at them.

**The lists are part of what a value depends on.** So a change of them is followed like a write: the next pass flags every formula whose tree calls `SUBTOTAL` or `AGGREGATE` (`Fact.Chosen`) and names the sheet in a reference, on any sheet, and its readers (the blocks filed under the sheet's id, `ReverseIndex.reading`, and `Recalc.rowed`). One that works its range out as it runs (`SUBTOTAL(109,OFFSET(…))`, `INDIRECT`) is flagged by a change on any sheet: its record says where it last resolved, but an edit drops every record, and such formulas are few. A `SUM` is never flagged. The lists a sheet already holds change nothing and cost a check and a comparison (43 µs for 10,000 pairs), so a host may say them after every batch. After a change `settled()` is false until a pass ran, with no such formula in the workbook too, as after `setClock`.

**A load brings them with its cells.** A `SheetSource` carries `hidden` and `filtered` beside `cells`, for a load and for `addSheet`: the rows the values of a computed load were computed with. So a computed load of a sheet with hidden rows is settled and computes nothing, and the same rows said again after it change nothing. Said after the load instead, they would be a change: on a workbook of 10,000 `SUBTOTAL(109,…)` over 100 rows each that is a pass of 9 ms on top of a load of 1 ms at every open, and a snapshot that says it is computed would not be.

**The lists are row numbers, and the engine moves none.** A row edit does not shift them and a deleted row does not shrink them: the host holds the truth (a new line inside a hidden stretch is not hidden, a filter's last line is open) and says the lists again before the next recalc. What the engine does know is that cells moved across rows, so an edit of rows on a sheet that leaves rows out, and a move of a block from or to one, counts as a change of the rows of those sheets (`Recalc.edit`): a range a move carries to rows that show is read again though no list changed, and so is a sheet whose batch inserted a row above a hidden one, showed it and hid the row above, which leaves the lists as they were. Without that rule an equal list could not be skipped.

`src/test/recalc/rows-out.test.ts` pins each rule by name and `src/test/functions/rows-out.test.ts` every code and option; `recalc/law.test.ts` changes the lists at random between writes, edits, capped passes and computed loads and holds the values against a fresh load. The sheet workbook reads the lists in one function (`rowsOut` beside `Workbook`): a load puts them on its sources, and `applyOps` says them once at the end of every batch, landed or taken back, that holds an op other than an input or a format of cells (`Workbook.setRowsOut`), which covers an added sheet too. While a sheet's filter leaves a row out, the `filtered` list it says is the sheet's hidden and filtered rows together, since Excel then leaves every hidden row of the sheet out of `SUBTOTAL` 1 to 11, inside the filter's range or not (checked in Excel for the web on 16 Nov 2026). Criteria that are set but leave no row out count as no filter here, which was not checked live. Building the lists is what costs there, 270 µs for a sheet of 10,000 hidden runs, so a typed cell does not pay it.

## A structural edit is one transform of stored text

An insert or delete of rows or columns (`Engine.editLines`), a move of a block (`moveCells`) and a new sheet (`addSheet`) each rewrite stored text by one rule (`src/edit/`). Every reference keeps naming the cells it named: an absolute index goes through the edit's map, and an offset becomes the distance between the mapped target and the mapped host. `mapIndex` and `mapSpan` (`src/edit/map.ts`) are that map, the one rule for everything that holds a row or column index; the sheet's merges, rules, charts and filter already call it today. A formula depends on its host only through the host's line, so `hostClasses` cuts a filled column into stretches with one outcome each and transforms it once per stretch. The edit plan (`src/recalc/edit-plan.ts`) works the classes out before a cell moves: the blocks whose text changes get their new shape, the blocks whose old text undo cannot derive back are reported with it in `EditResult.rewrites`, and the blocks whose value can change seed the next pass. Lost is one rule, where the transform cuts a reference (`shift` in `src/edit/transform.ts`): a reference whose cells are all gone becomes `#REF!`, and a range that loses an end keeps fewer cells than it named, by a delete that takes its end or by an insert that stops it at the grid's last line. So `=SUM(R1C1:R1048576C1)` under five inserted rows is reported with `lost` set to its own text, though the text did not change: the delete that undoes the insert would end it at row 1,048,571, and the host writes `lost` back after it. A removed sheet rewrites nothing: a reference to it reads `#REF!` and reads the sheet again when its id comes back. A rename rewrites only the formulas typed with the name it takes, as an added sheet does ([§ No held formula names a held sheet by its name](#no-held-formula-names-a-held-sheet-by-its-name)).

Edit cost. An edit visits the blocks on the sheets it names and the blocks that name them, which the index hands the plan (`ReverseIndex.reading`): only those can be rewritten. A sheet that comes, goes, moves or is renamed adds the blocks that name a sheet by a name or read a span of sheets. The rebuild after it reads the columns of the sheets the edit named or rewrote, and lists again every sheet their formulas read, whole. So an edit on a sheet that holds no formula and that no formula names costs the same on a book of a million one-cell blocks as on an empty one, and a sheet move or a rename that binds no name visits only the blocks that name a sheet by a name or read a span of sheets, and lists nothing again. Two costs stay. A listing cannot lose the entries of one sheet, so an edit on a sheet whose formulas read a hub lists every reader of the hub again: a listing per pair of sheets would spare that, and charge every typed value a lookup per sheet that reads the hub. And `ShapeTable.keep` asks about every shape of the book, so the rebuild after a changed formula sheet or a new shape costs a step per shape.

## An edit that would lose a cell or a formula is refused

Two edits would lose what no inverse edit brings back, and the engine performs neither. Each throws an `EditRefusal` (`src/recalc/edit-plan.ts`), an `Error` whose `reason` says which, before anything is flagged or moved: the values, the formulas, the flags and the lengths of the columns are as they were, and the next edit meets the workbook as it was. `editLines`, `moveCells`, `addSheet` and `renameSheet` can throw it.

- **`grid-end`**: an insert of rows or columns that would push a cell holding a value or a formula past the grid's last line (`Sheet.pushesOff`, asked at the door in `Engine.editLines`). Excel refuses the same insert. A host can ask beforehand: `count` rows inserted at `index` push a cell when a column's `columnLength` is past the larger of `index` and `GRID_ROWS - count`, and `count` columns when `lastColumn` is at or past the larger of `index` and `GRID_COLUMNS - count`. Only content counts. A reference to the last line is no content: the insert goes through, and the reference is clamped or broken and reported ([§ A structural edit](#a-structural-edit-is-one-transform-of-stored-text)).
- **`too-long`**: an edit that would rewrite a formula to a stored text longer than `MAX_STORED_LENGTH`, which the next load would not read back. Every edit that rewrites can grow a key: an inserted row turns `R[9]C` into `R[10]C` in each term, a move turns an unwritten sheet into its id, and a new or renamed sheet turns a name a formula was typed with into an id that may be longer. A host has no cheap question to ask beforehand, so it makes the engine call the first write of its own edit.

The length needs no pass of its own. The plan runs whole before a cell moves and prints each rewritten text anyway, so `ShapeTable.internTree` answers 0 for a text `storedKey` refuses and the plan throws. The shapes the plan made before it threw are held by no cell; `Recalc.edit` forgets the sheets it names before it plans, so a rebuild comes before the next marking whether the plan throws or not, and that rebuild keeps only the shapes some block of the book holds (`ReverseIndex.rebuild`): refused edits leave no shape behind. Only a refused edit that names no sheet with a formula, as a rename does, leaves its shapes until the next rebuild that asks the table, and then only in ids that were free: once they are used up the table grows, and is asked. A sheet that `addSheet` refuses this way has already handed its texts, shapes and errors only a file knows to the tables. The shapes are forgotten the same way, at the next rebuild. The texts stay until a sweep finds the string table past its limit (`Workbook.sweep`), and such an error stays for good, as the errors only a file knows are never swept: a few objects, held by no cell.

A block to move lies on the grid where it is and where it goes: `moveCells` throws a `RangeError` at the door otherwise, as for a cell off the grid. So no edit drops a cell, and `EditResult` holds only `rewrites`. Rejected: a dry run that answers what an edit would drop, which transforms every formula twice, and a result that is either rewrites or a refusal, which every caller would have to tell apart.

## Number display is numfmt behind its own entry

`numberDisplay(value, format)` (`src/format/number-display.ts`) is a value as an Excel number format shows it, and the package's one use of numfmt: the sheet writes every cell's display string through it, a chart draws its value ticks through it, and the engine's `TEXT` answers through `valueAsText` beside it. A number shows as the 15-digit decimal Excel holds, a half rounded away from zero, so `1.005` under `0.00` is `1.01`. A text, a boolean and an error take the format's text section, as in Excel: `abc` under `0;-0;0;"T:"@` is `T:abc`, `;;;` hides them, and a text section with no `@` shows its literal instead. A format of one section with `@`, such as `@" kg"`, leaves a number alone, and one without, such as `"lit"`, touches only numbers. Empty text (`=""`) takes the text section too. Google differs, and we follow Excel: an error there never takes the text section, `;;;` included, and `@" kg"` shows 5 as `5 kg`. A malformed format falls back to General. The day line is passed as numfmt's `leap1900: false` ([§ The day line](#the-day-line-is-googles-not-excels)). numfmt 4.1.3 carries one patch for the weekday of a day before day 0, described with its removal in [SHEETS.md § Number display](SHEETS.md#number-display-strings-go-through-numberdisplay).

## The xlsx dialect is one grammar with a rule for implicit intersection

`src/text/xlsx.ts` reads a file's formula with the A1 parser and a walk that takes the file's spellings out, such as `_xlfn.` prefixes and `_xlfn.SINGLE(x)` for `@x`, and writes it back by the reverse walk and `printXlsx`. A prefix is stripped only for a name Excel's inventory holds (`src/functions/excel-names.ts`), so a function Microsoft adds later survives a round trip.

An Excel without dynamic arrays read one cell of a range wherever one value was wanted, and a plain `<f>` still means that. So `intersect` puts the `@` where such an Excel read one cell, and an importer calls it for a plain cell only. Each place in a tree is read as one of three contexts: a value, a reference, or an array. An operator passes its context to its operands, a lazy argument passes it through, and a call that picks an argument, as `IF` does, makes its test a value again. Excel's recorded rows decide two function facts. The registry carries the first: `placed()` marks the table of `MATCH`, `VLOOKUP` and `HLOOKUP`, which old Excel read as a reference, where `LOOKUP`'s table made an array. The dialect holds the second, for the two rows marked `PART`: `INDEX` is one cell when every index is a number other than 0 or a call of one value, `XLOOKUP` when it looks along a plain range and returns from one line.

`isLegacy` says how to write a cell back. True: a plain `<f>` gives the cell in Excel the value it has in Eigen. False: write it as an array formula with the dynamic-array mark, which is also the answer when the function list cannot tell, since Excel then shows the value Eigen showed, at worst in braces. Step 1b writes every `t="array"` with `cm` and the metadata part, or typed `INDEX`, `OFFSET` and `XLOOKUP` would open in Excel as old braces formulas. The one loss: an `@` frozen at import in front of a function the engine lacks that day stays when that function is built.

## A table reference is one leaf, and the importer resolves it to a range

`Sales[[#This Row],[Qty]]` parses as one leaf, `NodeKind.Table`, with its brackets as written. `resolveTables` (`src/text/tables.ts`) is what an importer calls with its file's tables: each reference becomes the plain range it names, with the marks Excel's own Convert to Range writes (column absolute and row relative for this row, all absolute otherwise). A this-row reference reads the table's row of the same number from any sheet, as Excel does. One whose table, column or rows the file lacks stays, evaluates to `#REF!` and is written back as read. Step 1b calls it after `parseXlsx` and before `intersect`. Tables are no live feature: after import a formula holds the range, and a table that grows does not grow it.

## Excel's limits and bugs are not copied

The owner's standing rule: no code whose only purpose is to copy an Excel limit or bug. The engine accepts more than Excel wherever the meaning is unambiguous, and refuses only where accepting would make one formula text mean two things, or cost code of its own. Every place it accepts more is a listed difference ([§ Known differences](#known-differences-from-excel)), since it can produce a file Excel refuses. Precedents: no 255-character limit on a criterion, a lookup key or the text of `CODE`, `UNICODE` and `REPT`, no 255-character limit on a number format, and no 8,192-character limit on a formula. Where Excel's answer is the meaning, as in a function's arithmetic, the engine follows Excel's recorded rows, and the tests pin them.

## The day line is Google's, not Excel's

A serial is the days since 30 December 1899 in the one real calendar, negative before it (`src/values/dates.ts`). So 1900 has no 29 February, as in Google Sheets; from 1 March 1900 on a serial is Excel's, and before it one day less. `DATE(1900,1,1)` is 2 where Excel says 1, `DAY(60)` is 28, and a negative number is a date, where Excel has none. Dates run from 1 January of the year 1 to 31 December 9999 (`FIRST_SERIAL`, `LAST_SERIAL`). Excel's 29 February 1900 is Lotus's bug, and copying it would be code for a bug in every date function, the display and the reading of typed dates. Number display holds the same line, which today's cells already show ([SHEETS.md § Number display](SHEETS.md#number-display-strings-go-through-numberdisplay)).

## Empty text is 0 in arithmetic

`=""+1` is 1 and `=B1*2` over a `=""` is 0, where Excel says `#VALUE!`; empty text is also FALSE as a condition and 0 in `VALUE` and `ABS`. It is the owner's pick from Google, since sheets are full of `=IF(x,"",…)` feeding arithmetic, and one coercion function holds it (`src/values/coerce.ts`).

## A blank result leaves its cell blank, as in Google Sheets

`=A1` over an empty A1 leaves its cell blank, and so do `=IF(TRUE,A1)`, `=IF(TRUE,,1)`, `=IFERROR(A1,1)`, `=CHOOSE(1,A1)`, `=INDEX(A1:A3,2)` and a lookup that lands on an empty cell. Excel stores 0 there. The cell is blank to every reader: `ISBLANK` is TRUE, `COUNT` and `COUNTA` pass it over, `COUNTBLANK` and `COUNTIF(…,"")` count it, `AVERAGE` and `MIN` skip it, `&"x"` gives `x`, `=""` is TRUE, `MATCH(0,…,0)` does not find it, and arithmetic still reads it as 0. The blank survives a chain of such formulas. The cell still holds its formula, so `ISFORMULA` and `FORMULATEXT` see it.

It is the owner's pick from Google. A mirror of an empty cell is then empty, and a mirrored column keeps its source's counts and averages, where Excel users write `=IF(A1="","",A1)` to get that. A blank is a value of its own everywhere in the engine, so the rule is only the cell write in `Evaluator.result` storing it as it is. Over the corpus the pick changes 161,299 cells in 26 of the 162 workbooks Excel wrote, nearly all in two models, and the owner's Google export goes from 33,109 cells that differ to 160. Google's recorded rows are pinned in `src/test/eval/blank-result.test.ts`.

The store holds such a cell as a formula with no value, as an uncomputed one sits: whether a cell is still to be computed is a flag beside its value (`isPending`), not the value. A host learns of a blank result from `RecalcResult.changed` when a value turns blank, but a formula written over a value is blank from the write on, so the pass that computes it to a blank names nothing. A cell cannot tell a blank result from a formula never computed, since both hold no value, so the load says it once for all of them: in a computed load such a formula is its blank result and is not computed, and in one that is not computed every formula is ([§ A load is computed whole](#a-load-is-computed-whole-or-not-at-all)).

One Excel blank stays: a blank element of a computed array is 0 ([§ A lifted call hands values](#a-lifted-call-hands-values-and-only-offset-and-indirect-keep-references)), where Google keeps it blank. So `=IF({1;1;1;1},C1:C4)` over a blank C4 holds 0 in its 4th element.

## A character is a UTF-16 code unit

`LEN`, `LEFT`, `MID`, `FIND` and every function that counts, cuts or finds by position count UTF-16 code units, so an emoji is 2 and `LEFT` can cut one in half, where Excel for the web counts it as 1. The choice lives in `src/values/characters.ts` alone. Desktop Excel, which wrote the cached values of imported files, is taken to count code units; switching to code points is a change in that one file.

## A 1×1 array is a single value

The store does not tell a one-element array from its element: `TYPE({"a"})` is 2 where Excel says 64. Telling them apart would be a member on every table for one function's answer.

## The approximate searches halve and assume sorted data

`MATCH` type 1, `LOOKUP` and an approximate `VLOOKUP` or `HLOOKUP` halve the list, moving a probe that lands on a value of another kind to the next value of the key's kind, and stop at the last of a run of equal values. `MATCH` type -1 halves too, for the key or else the last value above it. Excel documents that these need sorted data, and on sorted data they answer as Excel. On unsorted data Excel walks cell by cell in places, so two picks of the owner differ there: `MATCH(2,{1,2,2,2,2,2,2,2,2,2,2,2,3,2,2,4},1)` is 15 where Excel says 12, and `MATCH("a",{1,"a",2,"a",3,"a"},1)` is 6 where Excel says 4. The walk made a lookup on a column of long runs read every cell of the run, and a descending `MATCH` read the whole column. `XMATCH` and `XLOOKUP` in search modes 2 and -2 are a plain bisection in the one order of all values, so a next-smaller value can be one of another kind. A key matches only values of its own kind, text in any case, and a blank never matches (`src/eval/search.ts`). The 47 recorded rows that differ are the `PICKED` table of `src/test/functions/search-order.test.ts`.

## Text has the engine's own order

Text compares on its key, the upper-cased form, so case never matters and `"straße"` equals `"STRASSE"` (`src/values/text-order.ts`). Keys order by character: hyphens and apostrophes are passed over, then the space, the other marks, the digits and the letters, an accented Latin letter right after its base letter. Two texts equal without their hyphens and apostrophes are ordered by them, the one without first, so `"co-op"` sorts right after `"coop"`. Excel's 200 recorded rows set this order. It is the engine's own because the host's collation follows the language data of whichever browser or server runs it, and a sorted lookup must find the same row on every tab and on the server.

## Snapping to a whole number is per function

Excel reads a count or an index a hair under a whole number in one of four ways, and its rows show which function does which:

| Reading | Functions |
|---|---|
| Snaps to the whole number (`NEARLY`) | `FACT`, `LEFT`'s count, `INDEX`'s row and column, `ROUND`'s digits |
| Cuts it as it is | `MID`'s start, `REPT`'s count, `CHOOSE`'s index |
| Cuts it at 15 digits | `INT`, `TRUNC`, `ROUNDDOWN` |
| Takes the double as it is | `QUOTIENT`, `MOD`, `MROUND` |

So `LEFT("abcdef",2.9999999999)` is `abc` and `MID("abcdef",1,2.9999999999)` is `ab`. `NEARLY` does not cut, so a row that takes it tests the sign and cuts in its body: `LEFT("abc",-0.9)` is `#VALUE!`.

## Three kernels follow Excel's rows over the textbook

- `RSQ` squares the sample correlation, each variance with its own root, where `CORREL` and `PEARSON` stay on the population; their squares differ in the last digit, and only this order answers all six recorded sets (`src/functions/statistical.ts`).
- `DATE` reads each part as a 16-bit number: a day outside -32768 to 32767 counts as 32767 on either side, and a month from 32767 on or under -32767 is `#NUM!` (`dateOf` in `src/values/dates.ts`).
- `TIME` refuses a part above 32767 and wraps one below -32768 as a 16-bit number: -32769 minutes are 32767 (`timeOf`).

## A lifted call hands values, and only OFFSET and INDIRECT keep references

When a call is lifted over an array, each element's answer becomes a value: of an array the first element, of a reference the value of its first cell, and a cell that holds nothing stays that cell, so it is passed over as a blank cell of a range is. So `INDEX(A1:B3,{1,2},1)` is an array of values, as Excel records. A blank answer is stored as 0, as Excel stores it, so every reader of a computed array meets the same value: over C1:C3 = 5, 6, 7 and a blank C4, `TEXTJOIN("|",TRUE,IF({1;1;1;1},C1:C4))` is `5|6|7|0`, as in Excel, and the same over `INDEX(C1:C4,{1;2;3;4})`, whose C4 is still a cell, is `5|6|7`. Only a row marked `ANYWHERE`, which works a reference out (`OFFSET`, `INDIRECT`), keeps one reference per element, and that array of references is `#CALC!` when it reaches the cell.

## An operator reads a range where it lies

An operator never copies a range into an array of values. Each operand is read first (`Evaluator.term`): one cell is its value, a computed array stays as it is, and a range has its formulas computed and is banded as the array it would be (`band` in `src/eval/views.ts`), its cells left in their columns. One loop (`elementwise` in `src/eval/elementwise.ts`) then lays each operand out along the result as a column stores its cells: per element a kind, a number that is 1 for TRUE and 0 for what is no number, and the id of a text or the code of an error. Two elements that are numbers, booleans or blanks go straight to the arithmetic, and two texts of cells are equal when the ids of their keys are, so neither pair makes a value. Every other pair goes to the operator on two values (`operate` and `compare` in `src/eval/operators.ts`), the one the evaluator calls for two cells: the coercions, the order of kinds and the error order, the left operand first, live there only. A comparison takes a cell's text as its key from the string table, so no text of a cell is upper-cased; a text a formula made has no id and is upper-cased when the loop comes to it.

The result is an array like any other: plain numbers while every answer is one, which the next operator, `SUMPRODUCT`, `SUM` and `MATCH` read as they are, and else a list of values, as the booleans of a comparison are. A blank answer is 0, as in a lifted call.

Three things are kept as they were when an operator was lifted like a call, by choice. The cells of a range on the left are computed before the right operand is evaluated, and the references among the elements of two arrays, which `OFFSET` and `INDIRECT` make, are read element by element, the left one first: reading is what finds a loop. A range still counts its stored elements against its formula's work (`Recalc.room`), as the array it used to become, so no formula moved across `#CALC!` and no capped pass stops at another formula. And an element a sign makes is a value a cell can hold, where a sign on one value changes only what it must: over a cell a host wrote `5e-324` into, `-A1` is `-5e-324` and `INDEX(-A1:A2,1)` is 0, and `+` on a range turns a text past 32,767 characters into `#VALUE!`. `src/test/eval/operator-law.test.ts` holds the loop to its definition, the operator on two values per element, for random operands of every kind and shape, and `operator-in-place.test.ts` counts that 20,000 rows make no array of values and upper-case no text.

## `room` bounds bytes, not elements

A body that builds an array asks `ROOM` first, and the recalc refuses past `MOST_STORED` elements. A reference is an object of about 137 bytes where a number is 8, so an array of references is charged 17 slots an element (`REFERENCE_ROOM` in `src/eval/views.ts`). So `ISFORMULA` or `FORMULATEXT` over more than 986,895 held cells is `#CALC!`, as Excel answers `FORMULATEXT(A:A)`, where a single formula could otherwise take gigabytes and get the server killed.

## A sheet id must not hold a bracket

Stored text writes a sheet as its id in brackets, `[id]!`, and reads a bracket by the table reference rule, so an id that holds `[` or `]` does not parse back. A quote is fine: `[a'b]!R1C1` reads and prints back as it is. The editor's ids are UUIDs. A host hands the engine no other id: one from a file or a peer is checked or remapped where it enters.

## Two sheets never share a name

A load, `addSheet` and `renameSheet` refuse a name another sheet has, by a throw before anything changed (`Workbook.checkName`). Two names are compared as a formula compares them, by `sheetNameKey`: Excel's upper case, each character on its own. So `Data` beside `data` is refused and `Straße` beside `STRASSE` is not, and a sheet may take its own name in another case. With two sheets of one name, a name typed in a third case would read either. A load and `addSheet` refuse an id another sheet has the same way (`Workbook.checkId`), as a host names a sheet by its id.

## No held formula names a held sheet by its name

Stored text can name a sheet two ways, by its id (`[b]!R1C1`) or by a typed name (`'N'!R1C1`), and the second is only how a reference to a sheet that is not there is kept. So the engine holds one invariant: no name-typed reference in a formula it holds names a sheet it holds, as `sheetNameKey` compares names. Without it one text meant two things by history: `='N'!R1C1` beside a sheet N read `#REF!` until some rename happened to bind it, so a rename taken back did not restore the texts and two readers of one log could differ. The binding lives where stored text becomes a shape, `ShapeTable.intern` (`src/text/shapes.ts`), which every formula that enters passes: a load, `setFormula`, `fillFormula` and the formulas of the sheet `addSheet` brings, its own name included. `Workbook` hands it `named`, the lookup through the one map it keeps from a name's key to the sheet, true wherever a sheet is inserted, removed or renamed, which `checkName` and a name `INDIRECT` reads (`Book.refer`) go through too: so a typed name costs one map lookup, however many sheets there are. As no two sheets share a key, the key alone finds the sheet the exact name would. A load gives every sheet its place before it adopts a formula, so the order of the sheets does not matter. A reference to another workbook, a 3-D reference and text that does not parse are not touched. `intern` first makes the shape of the text as typed, as it always did, and binds that shape's tree only when it names a sheet (`Shape.namesSheet`): so a formula that names none pays nothing, and a typed text the table already knows is bound again each time it enters, as an edit may have bound every cell that held it while the table has not forgotten it yet. The typed shape no cell holds is forgotten at the next rebuild, as the shapes of a refused plan are.

The bound text can be longer than the typed one. A formula that fits `MAX_STORED_LENGTH` as typed and not once bound is stored with `#REF!` in place of each such reference (`breakSheets`), at every door alike: a load cannot refuse one cell, and a text kept name-typed beside its sheet would be bound, or refused, by a later rename back, which is the history the invariant removes. So no write and no load throws for length, and what it stores reads back as itself on every reader; only `addSheet` and `renameSheet` can, when the name they give binds formulas already held whose bound text would not fit, and then they change nothing ([§ refused](#an-edit-that-would-lose-a-cell-or-a-formula-is-refused)). A formula typed with a sheet's name whose own key is already too long, such as bare names the key quotes, is text that does not parse: kept as handed, `#ERROR!` on every reader, whatever sheets the workbook holds, so it never binds and no rename meets it.

**What a host must know.** A formula that enters with the name of a held sheet is stored bound, so what the host reads back (`formulaOf`, the walk) can differ from the text it wrote, and the host keeps what it reads back. `Rewrite.lost` is then only for a rename or an add that gives a sheet a name no sheet had: the formulas of the other sheets typed with that name are bound and reported, and undo takes the edit back first and writes `lost` after, when the name is free again. `addSheet` reports no formula of the sheet it adds.

## A load reads its source to the end before the workbook holds any of it

`Engine` and `addSheet` read a sheet through its `SheetSource`, whose `cells` callback is called twice, once to size the columns and once to fill them, so a host walks its own cells and builds no list (`Workbook.read` in `src/store/workbook.ts`). Both walks go through `admit`, and a cell the second walk reports outside the columns the first one sized is refused, so a source that reports other cells the second time cannot write where no cell is. While the source runs the sheet is a draft of its own: its texts, its formulas and its errors only a file knows are numbered in lists beside it, and the workbook's tables take them only once the source has returned (`Workbook.adopt`). A cell holds such a number as its complement, below 0, where no id or code is, and the draft lists per column the rows that may hold one. So `adopt` turns the numbers into ids by reading the listed cells only, and a cell the source reported twice, which is listed twice, is turned once. A load so costs its cells in time and in memory. A loop over every row of every column, which it replaced, read two planes of each row: 100 cells on the grid's last row then held 530 MB after the load where they now hold 37 MB (Bun; 566 and 64 MB on Node), and took 137 ms where they now take 5. A load of 1,000,000 numbers lists nothing and is no slower (0.96 of the time on Bun, 0.86 on Node); one of 1,000,000 cells of which two in five are texts and formulas takes 1.04 of the time on Bun and 0.98 on Node. The list is the price: one number per cell that is no plain number or boolean, dropped with the draft. A load that is refused leaves every table as it was. So a source that calls the engine, which it has no reason to do, meets the workbook as it was before the load: a recalc from inside it sweeps no text or shape of the half-read sheet. What `addSheet` refuses, such as an id in use, it checks after the source has run. Reading to the end was chosen over refusing a call from inside a load, which would need a flag that every method of `Engine` tests.

## The walk of a sheet is a source a load takes

`Engine.cells(sheet, sink, top, left, bottom, right)` reports the cells of a block that hold a value or a formula, a column at a time and down its rows, through the `CellSink` a load takes. So `cells: (cell) => engine.cells(id, cell)` is a `SheetSource`, and an engine built from it holds the same cells; the rows the sheet hides and filters are the host's, which puts them beside the walk. The walk allocates nothing per cell: a text comes from the string table, an error is the object the engine holds and a formula is its shape's text. A formula whose result is blank is reported with its text and no value. A formula still to be computed is reported with the value it last held, which a sink cannot tell from a fresh one, so a host that keeps values writes `settled()` beside the walk and the load takes it as `computed`. Over 1,000,000 cells, half of them formulas, the walk takes 2 to 3 ns a cell on Bun and 5 on Node, about a tenth of a full recalc of the same cheap formulas.

The sink must not write to the engine. The walk reads the columns as it goes and copies nothing, so after a write what it reports next is not defined. It is a sentence and no refusal: the walk only reads, so a sink that writes cannot harm the store, and a refusal would need a flag that every write tests.

`nextCell(sheet, column, row, last)` is the same walk as a cursor, the first content row from `row` to `last` or -1, for a host that feeds an iterator, which a callback cannot. It looks no further than `last`, so a screen's walk costs the screen's rows however far below the next cell lies. With `valueOf` and `formulaOf` per cell it costs about what the sink costs on Bun and six times that on Node, so whatever reads a whole sheet uses `cells`. `lastCell(sheet, column, row, first)` walks the other way, back from `row` to the column's last content row at or after `first`, or -1: a move asks it how far each column of its block reaches, and it looks no further back than the block's top.

The extents are `columnLength` (one past a column's last content cell, 0 for a column never written), `lastRow` and `lastColumn` (-1 on an empty sheet) and `slots()`, the lengths of every column of the workbook together. A column ends at its last content cell (`Column.trim`), after a load as after a write, so all four are facts of the content: a clear or a delete shortens them, the spare room of a column that grew never counts, and `slots()` is the number a decoder sums from a cell list, per column its last row plus one. It reads no column: each sheet keeps the count, measuring a column's length around every change of it, and `slots()` sums the sheets.

## Known differences from Excel

Each line is a decided choice; the function-by-function list is `packages/formula/FUNCTIONS.md`.

- The day line is Google's: a serial under 61 is a day earlier, and a negative serial is a date.
- Empty text is 0 and FALSE in arithmetic, conditions, `VALUE` and `ABS`, so `IF("",1,2)` is 2 and `NOT("")` TRUE, where Excel answers `#VALUE!`; `SUMPRODUCT` of one blank cell is 0.
- A formula whose result is blank leaves its cell blank, as Google does, where Excel shows 0: over an empty A1, `=A1` is blank, `ISBLANK` of it TRUE and `COUNTA` of it 0. A blank element of a computed array is still 0, as in Excel.
- No 255-character limit on criteria, lookup keys, `CODE`, `UNICODE`, `REPT` and number formats.
- A formula that does not parse is stored and shows `#ERROR!`, where Excel refuses the entry.
- Text lengths count UTF-16 code units.
- A 1×1 array is a single value, so `MATCH(2,2,0)` is 1, `VLOOKUP(5,5,1,FALSE)` 5 and `MATCH(2,{#DIV/0!},0)` `#DIV/0!`, where Excel answers `#N/A` for all three.
- An exact `MATCH` finds what `=` calls equal: over `=0.1+0.2` in D1, `MATCH(0.3,D1,0)` is 1, where Excel answers `#N/A` though `D1=0.3` is TRUE.
- `COUNTA` of the reference array a lifted `INDEX` or an `XLOOKUP` gives does not count a blank cell: `COUNTA(INDEX(C1:C4,{1;2;3;4}))` over a blank C4 is 3, Excel 4, though Excel's other readers of that array see the blank.
- `AGGREGATE` with an error cell as `k` answers that error: `AGGREGATE(14,6,D1:D8,B4)` over `#DIV/0!` in B4 is `#DIV/0!`, Excel `#VALUE!`.
- An intersection with a union is `#VALUE!`: `SUM((A1:A2,C1:C2) A1:C1)` is 3.5 in Excel, which intersects each area.
- `&` and `CONCATENATE` past 32,767 characters are `#VALUE!`, where Excel cuts the text silently.
- `HYPERLINK` takes a link of any length a text can have, where Excel answers `#VALUE!` past 255 characters.
- On a true tie in the 16th digit, `&""`, `FIXED` and `ROUND` give the exact answer: `73938790243119/4` to one decimal ends `.8`, Excel `.7`. `TEXT` there shows `.7`.
- Number display has two gaps of numfmt: `h:mm AM/pm` prints `12:28 A12/p12` for 0.52, Excel `12:28 PM`, and a negative duration is shown where Excel shows `#######` (`#VALUE!` from `TEXT`), its hours wrong past one day: -1.25 under `[h]:mm:ss` shows `-18:00:00`.
- A formula may be 131,072 characters long, where Excel stops at 8,192, so a long formula can export to a file Excel refuses. A formula is refused, and kept as the text that was typed, when its stored form would pass 131,072 characters.
- An edit that would make a formula's stored form pass 131,072 characters is refused whole, where Excel's limit of 8,192 applies to what is typed only. An insert that would push a filled cell off the grid is refused as in Excel.
- An approximate search on data not sorted as it assumes can land elsewhere (47 recorded rows).
- `LOOKUP` with a result range shorter than its lookup range is `#N/A`, where Excel reads past the range.
- A lifted lazy argument no element picks does not widen the result.
- A cell on a loop holds `#REF!`, where Excel shows 0 with a warning.
- A formula with a 3-D reference or a reference into another workbook is not computed: it keeps the value it was loaded or written with, and with none, as when it is typed, it is `#REF!`, where Excel computes `=SUM(Sheet1:Sheet3!A1)`.
- `ISFORMULA` and `FORMULATEXT` over more than 986,895 held cells are `#CALC!`.
- `AGGREGATE` with an even option keeps the rows a filter left out, as Excel documents the options; Excel recorded only the odd ones on a filtered sheet.
- A change of hidden or filtered rows computes every `SUBTOTAL` and `AGGREGATE` over the sheet again at once, where Excel was seen to leave a pasted `AGGREGATE(9,7,…)` stale after a hide.
- A table reference is resolved to a range at import; a this-row reference outside the data rows is `#REF!`, and forms Excel refuses but whose meaning is plain (`T[ Qty ]`) are accepted.
- Through an xlsx round trip, an unknown function name loses its letter case, a shared formula past the grid's edge is `#REF!` where Excel wraps it, a formula the dialect is unsure of is written as an array formula, and `TYPE` of a range after import is 64 where Excel shows 16.

## Tests mirror the source, and laws check what examples cannot

Tests live in `src/test/`, one folder per source folder (`edit`, `eval`, `format`, `functions`, `recalc`, `store`, `text`, `values`). Three kinds carry the suite:

- **Laws with generators.** Incremental recalc equals a fresh load of the same inputs, after any writes, clocks, changes of the rows a sheet hides or filters and stopped passes, and a walk loaded as computed when it is settled and as not computed when it is not, after a stopped pass or a write no pass followed, holds the same values and goes on equal (`recalc/law.test.ts`), and after any structural edits (`recalc/edit-law.test.ts`); formulas that work a reference out as they run equal a fresh load under writes, structural and sheet edits, clocks, capped passes and computed loads, and a write flags one exactly when it reaches an area it resolved (`recalc/resolved-law.test.ts`); a marking flags what the definition reaches, no less and no more (`recalc/marking-law.test.ts`); no held formula names a held sheet by name, a fresh load of what the engine holds is the same workbook and every write or sheet edit taken back leaves the workbook it met (`recalc/bind.test.ts`); every reader of one log of batches ends with the same values (`recalc/clock.test.ts`); the string table's sweep never frees a held text (`recalc/strings-law.test.ts`); the stored key reads back as the same tree (`text/xlsx-laws.test.ts`); the wrapper does what every row's words say (`functions/laws.test.ts`); every value of a block of growing ranges, under writes, rows left out and capped passes, is the one its formula has alone, and the block reads each row about once (`eval/carry.test.ts`).
- **Excel's recorded rows.** Function tests carry Excel's answers as recorded in Excel for the web, and a row that differs by a decided pick sits in a pick table with both answers, such as `PICKED` in `functions/search-order.test.ts` and the 255-character table in `functions/text.test.ts`.
- **Timing bounds.** A few tests hold a cost to a bound, such as `functions/products.test.ts`, so a quadratic shape fails the suite.

```sh
cd packages/formula
bun run test                       # the whole suite, each file isolated
bun run typecheck                  # source and tests
bun test ./src/test/functions/lookup.test.ts
EDIT_LAW_SEED=7 EDIT_LAW_COUNT=5000 bun test ./src/test/recalc/edit-law.test.ts   # a long law run
CLOCK_LAW_SEED=7 CLOCK_LAW_COUNT=20000 bun test ./src/test/recalc/clock.test.ts -t 'one log'
LAW_SEEDS=60 bun test ./src/test/recalc/law.test.ts                               # 60 seeds, with each one's counts
RESOLVED_LAW_FIRST=1 RESOLVED_LAW_SEEDS=4000 bun test ./src/test/recalc/resolved-law.test.ts
```
